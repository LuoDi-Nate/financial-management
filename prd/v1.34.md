## 0 · 这一版在解决什么

**背景与现状**:

1. 一个账户(券商、基金、理财……)里的持仓,所有页面都按**添加的先后**排(`stock_holding.id`),没有任何地方能改。账户本身有「显示顺序」(编辑页的数字),持仓没有。
2. 每月核对余额时,用户是对着平台 App 一行一行看的 —— 平台有自己的排法(多数按市值从大到小,也有按自选顺序的)。两边顺序不一样,就得在十几只持仓里来回找,10 分钟的预算有一部分花在「找」上。
3. 同一份持仓列表出现在好几个地方:持仓管理页、填报页「股票收入」选账户后联动出的持仓、截图导入的「旧持仓」那一侧、资产打标页。只改一处的话,用户在别处看到的还是旧顺序。

**服务谁**:每月核对持仓的家人。

**主推动力**:**让持仓的顺序和平台对得上,核对时从上往下挨个对**。

**顺带(#41)**:持仓名称填错了没地方改(账户名能在「编辑」里改,持仓不行),只能新加一只再归档旧的。名字也是截图导入「新旧比对」认同一只的依据之一 —— 改成平台 App 上的名字,下次导入就能对上。

---

## 1 · 调研

不适用 · 无外部依赖。交互参照常见 App 的「编辑顺序」模式:进入排序状态 → 上下移 / 置顶 → 保存;手机上不用拖拽(触屏拖拽在长列表里容易误操作,也难做无障碍)。

## 3 · FR

**preview**:[`preview/v1.34/holding-order.html`](../preview/v1.34/holding-order.html)。

### A · 怎么调

| # | 要求 |
|---|---|
| FR-1300 | 持仓管理页(账户 → 持仓管理)持仓列表上方一个「**调整顺序**」按钮(持仓少于 2 只时不出现)。 |
| FR-1301 | 点了进入排序状态:每只持仓收成一行(名称 · 代码 · 市值),行右边「↑」「↓」「置顶」;顶上三个一键排法:「**按市值从大到小**」「按名称」「按添加先后」(= 现在的样子)。下面「**保存顺序**」「取消」。 |
| FR-1302 | 保存后回到正常的持仓页,按新顺序显示;页面顶上一句「已保存顺序」。取消 = 什么都不改。 |
| FR-1303 | 手机上同样是一行一只,↑ ↓ 按钮够大、点得中;不做拖拽。 |

### B · 顺序在哪儿生效

| # | 要求 |
|---|---|
| FR-1310 | 同一个顺序用在所有列出「这个账户的持仓」的地方:持仓管理页、填报页「股票收入」选账户后联动出的持仓、截图导入比对页的「旧持仓」一侧、资产打标页按账户分的持仓。 |
| FR-1311 | 已归档的持仓不参与排序(照旧排在最后的「已归档」里)。 |
| FR-1312 | 之后新加的持仓(手动添加、截图导入新增、券商同步进来的)排在**最后**;用户再调一次即可。 |
| FR-1313 | 从没调过顺序的账户,顺序和今天**完全一样**(按添加先后)。 |

### C · 持仓改名(#41)

| # | 要求 |
|---|---|
| FR-1320 | 持仓管理页每张持仓卡片,名称旁一个小字「**改名**」;点开是一行输入框(默认是现在的名字)+「保存」。PC 上浮在标题下面,不挤动标题行;手机上整行展开。 |
| FR-1321 | 只改名字:份额、估值、代码、行业标一律不动。前后空格去掉、中间连续空格并成一个;不能为空,最多 64 个字。没变就什么都不做。 |
| FR-1322 | 改完回到持仓页,顶上一句「已改名:「旧」→「新」」;所有列出这只持仓的地方(填报页股票收入、截图导入、资产打标、资产透视)都用新名字。 |
| FR-1323 | 券商同步不会把用户改过的名字改回去(同步只在名字还是空的、或者还是裸代码时才填券商给的名字 —— 既有逻辑)。 |

### 关键文案

| 位置 | 文案 |
|---|---|
| 入口 | `调整顺序` |
| 一键排法 | `按市值从大到小` · `按名称` · `按添加先后` |
| 每行 | `↑` · `↓` · `置顶` |
| 底部 | `保存顺序` · `取消` |
| 保存后 | `已保存顺序 —— 填报页、截图导入也按这个顺序列` |
| 卡片上 | `改名` · `保存` |
| 改名后 | `已改名:「旧」→「新」` |

## 4 · 不做什么

- **不做「每次自动按市值排」**:市值每天变,顺序跟着跳,和「对着平台一行行看」反而对不上(平台的自选顺序也不跟市值走)。要按市值,点一次「按市值从大到小」再保存。
- **不做拖拽**(触屏误操作、无障碍差);不做跨账户排序(账户本身已有「显示顺序」)。
- **不改任何金额、口径**:只是展示顺序。

## 6 · 存量影响

| 维度 | 这一版的影响 |
|---|---|
| **schema** | 持仓表加一列「顺序」(可空,V73)。旧行为空 = 按添加先后,和今天一样。改名不加列。 |
| **口径** | 不涉及口径变更:只改展示顺序,不碰任何金额、估值、指标。 |
| **UI** | 没调过顺序的账户,所有页面与今天逐像素一致;持仓页多一个「调整顺序」按钮。 |

**核心功能影响排查**:不适用 · 不动跨页面共享的计算机制,只加一个展示用的排序键;写操作只有「保存顺序」一个(只写这个账户自己的持仓的顺序列,不涉及账期)。

## 9 · 失败模式(pre-mortem)

1. **只改了一处列表**:持仓页按新顺序,填报页 / 截图导入还是旧顺序 —— 用户以为没存上。
   **怎么发现**:持仓列表的取数收口到一个排序规则;e2e 保存顺序后依次打开四处,断言顺序一致。
2. **新加的持仓插到中间**,把用户排好的顺序打乱。
   **怎么发现**:单测 + e2e:保存顺序后再加一只,断言它在最后、其余不动。
3. **排序把已归档的持仓也排进来**(或保存时漏掉一只,顺序出现空洞)。
   **怎么发现**:保存只接受这个账户全部在用持仓的完整排列(少一只、多一只、别的账户的都拒绝)。
4. **改名顺手把别的列也写了**(走通用的整行 update,把并发改过的份额 / 估值覆盖回旧值)。
   **怎么发现**:改名走只写名字这一列的专用语句;e2e 断言改名前后份额 / 估值 / 代码 / 行业标逐字相同。

## 10 · 验收 → 护栏映射

| # | 验收标准 | 机器可校验? | 落在哪 |
|---|---|---|---|
| 1 | 持仓页「调整顺序」→ ↑↓ / 置顶 / 按市值 → 保存 → 页面按新顺序,库里顺序列对应 | 是 | e2e(页面 + 库) |
| 2 | 填报页股票收入、截图导入比对、资产打标三处与持仓页顺序一致 | 是 | e2e |
| 3 | 新加一只排在最后,其余不动 | 是 | 单测 + e2e |
| 4 | 从没调过的账户顺序与改版前一致 | 是 | 单测 + qa-run 护栏(持仓列表取数统一排序) |
| 5 | 手机上一行一只、按钮点得中、不横向溢出 | 部分 | e2e 量尺寸 + 双端截图 |
| 6 | 卡片「改名」→ 页面、库、填报页股票收入都是新名字;其它列一个不动 | 是 | e2e + 单测 |
| 7 | 改名为空 / 超长 / 别的账户的 / 已归档的 → 拒绝,一行不写 | 是 | 单测 |

## 13 · 实施记录(2026-10-13)

| 处 | 怎么定的 | 为什么 |
|---|---|---|
| 排序状态放在哪 | 单独一页 `/accounts/{id}/holdings/order`(持仓页操作栏「调整顺序」进去),保存 / 取消回到持仓页 | 持仓卡片里信息很多(份额、单价、改份额、归档……),在原页面上切「排序状态」要把卡片全收起来;单独一页一行一只最清楚,手机上就是这一列 |
| 顺序只有一份 | `StockHoldingMapper.ACCOUNT_ORDER`:`(sort_order IS NULL), sort_order, id` —— 持仓页、填报页股票收入、截图导入比对、资产打标都经 `findActiveByAccount` / `findAllByAccount` 取 | 一处改、处处一致(PRD §9 失败模式 1) |
| 资产打标页 | 「账户内现金」那几行照旧单列在上面(系统归类,不可标);其余持仓按保存的顺序 | 打标页本来就把现金行分开显示 |
| 一键排法 | 「按市值从大到小」用估值服务 `perHoldingLines`(和账户余额同一个算式);同市值 / 同名时按添加先后 | 页面上的市值和持仓页一致 |
| 改名 | 专用语句只写 `display_name`(不走整行 update);改完清资产透视缓存 | 失败模式 4;透视的持仓级行用名字 |
