## 0 · 这一版在解决什么

**背景与现状**(2026-10-10 在 beta 上用 390×844 手机视口逐页走查,60 种页面,每页整页截图 + 机器度量,PC 1440 同样各截一遍):

1. **页内目录只有 3 个页面有**(仪表盘 / 报表 / 资产体检)。另外至少 **20 个页面超过 2 屏**却没有目录,手机上只能一路划:
   使用手册 38.5 屏、审计日志 17.4 屏、账户详情 15.7 屏、资产打标 15 屏、AI 接入 13.2 屏、填报 9.9 屏、我的待办 8.4 屏、账户簿 7.1 屏、
   券商图文向导 7 屏、提醒 6.2 屏、周期 5.9 屏、持仓管理 5.8 屏……(完整清单见附录 A)
2. **管理的 18 个子页,手机打开第一屏全是菜单**:左侧那列 19 项设置菜单在手机上竖排压在页面最上面,整整一屏(840px),
   页面自己的标题在第 843px —— 也就是**打开任何一个设置页,第一眼看不到这页是什么**。
3. **表格在手机上硬挤进 390px**,有 12 张表出问题:
   - 周期管理:「02-01 → 02-28」折成 4 行、「CLOSED · 已结束」标签折成 3 行、关闭时间折 3 行;**「重新打开」按钮被挤到卡片右边框外看不见**;每行 100px 高,24 期占 3 屏。
   - 账户模板 / 产品类目:名称列只剩约 20px,「招商银行」「银行理财(R2 稳健)」**一字一行竖着排**,一行高 4~10 行字;类型标签(INSURANCE / PROPERTY)被截断。
   - 审计日志:类型标签和「由谁」叠字,详情列每行只放得下 2~4 个字,一条券商配置记录 20 多行高。
   - 汇率历史:来源「copied-from-period-350」折 4 行,几十期占几屏,**「手填覆盖」表单在整张历史表下面**,要划过全部历史才能改汇率。
   - 备份记录的「本地路径」列、提醒日志的「详情」列、AI 接入「接入点 / 最近调用」两张表:列被截在卡片外或两列文字叠在一起。
4. **横向溢出 2 处**:使用手册的对照表撑出屏幕 147px;「手填市值」页的单股估值输入框撑出 125px。
5. **按钮文字竖排**:账户详情页底部四个按钮(持仓管理 / 看资产体检 / 编辑 / 导出本账户 CSV)挤一行,文字一字一行。
6. **点多的折线图标签叠成黑条**:账户详情「余额时序」185 个点、每点一个金额标签,手机和 PC 上都叠成一条看不清的黑带。
7. **长列表全量铺开**:账户详情的「流水时间线」185 个月全部展开(这页 15.7 屏里 10 屏是它)。
8. **点击区太小**:支出类目每行的「改名 / 加细类 / 停用 / 删除」、账户簿的类型筛选 chip 等,实际可点高度不到 28px(走查共计 1117 处 < 28px)。

**服务谁**:**拿手机用的家人**(非技术),以及在手机上改设置的维护者。

**主推动力**:**手机上找得到、看得清、点得中** —— 不改任何产品逻辑、不改任何数字。

**本版新引入的名词**:无。「页内目录」是 v0.5.6 就有的既有概念([`AGENTS.md`](../AGENTS.md) 页面地图),本版把它从 3 个页面推广到全站。

## 2 · 用户故事

维护者原话(2026-10-10):

> 我们启动一个小版本 做一下易用性改造,你用手机端 自己启动浏览器 看看现在大量配置界面 样式有多差劲,尤其是:
> 1.原来只有dashboard和报表页面有目录 我们给所有页面都加上,尤其是移动端 很难滚动
> 2.大量页面 有巨大样式问题 比如 移动端 管理-周期管理 进去以后 上面有一大屏幕 是目录??还是什么 完全没有兼容好手机端
> 还是以周期管理这个页面为例 往下翻 手机端的表格/换行/tag 都惨不忍睹
> 逐个页面你都通过浏览器 认真review一遍 梳理出所有页面的样式问题,不改变产品逻辑的情况下 只进行UI/易用性的改造

原话里的设计线索:「**上面有一大屏幕 是目录??**」—— 用户把那列设置菜单认成了目录,说明它在手机上既占地方、又说不清自己是什么;
「**表格 / 换行 / tag**」三个词正好对应本版的三类修法(表格改卡片、关键文本不在中间断行、标签整体不折)。

## 4 · 不做什么

- **不改任何计算、口径、数据、接口、权限、页面跳转关系**;页面上的业务说明文字一字不改(只新增目录条目、分组名、展开 / 收起按钮这几类导航文案)。
- **不重做视觉风格**:字体、配色、纸张质感、eyebrow 小字的设计语言都不动;不做暗色模式。
- **不改 PC 布局**:PC 上只多了侧栏分组名、侧栏里的本页目录、右下「本页目录」钮;表格在 PC 上照旧是表格。
- **仪表盘 / 报表 / 资产体检的既有目录不重做**(只确认与新目录行为一致)。
- **两张有意横滑的宽表不卡片化**:资产透视「交叉透视」、报表「本期 vs 上期 vs 去年同期」—— 它们的列本身就是信息,已有横滑提示和横屏钮。
- 不做 PWA / 原生 App,不改登录页和落地页。
- 不撞「刻意不做」清单(本版无业务能力变化)。

## 7 · 开关与默认值

**不设开关**。理由:

- 本版不改数据、不改口径,只改展示层;没有「替用户改掉他看惯的数字」的风险。
- 维护者明确要求全站改造;开关意味着每个页面两套排版并存,测试面翻倍,而关掉开关的人得到的是本版要修掉的那些问题。
- 兜底:回滚换回 v1.30.x 的 jar 即可(§11),无迁移。

## 9 · 失败模式(pre-mortem)

1. **卡片化把按钮藏丢了** —— CSS 一改,某张表的操作列在手机上被隐藏或点不到(最可能:周期「重新打开」、类目「删除」)。用户发现不了「少了一个能力」,只会觉得「手机上做不了」。
   **怎么发现**:手机 e2e 从管理首页点进周期管理,在卡片里填理由、点「重新打开」,断言页面提示 + 数据库这一期状态变成 OPEN(再还原)。
2. **自动目录和页面局部刷新打架** —— 打标、体检、填报有大量 HTMX 局部替换;替换后目录指向的锚点没了 / 重复了,点了不动。
   **怎么发现**:e2e 在局部刷新之后再点一次目录条目,断言滚到了目标;护栏检查同一页面锚点 id 唯一。
3. **浮钮栈拥挤** —— 目录钮加进右下角那一列后(横屏 / 超级 Agent / 目录 / 隐私眼),四个叠在一起挡住卡片右侧的按钮或金额。
   **怎么发现**:双端截图人工核对每个改动页的右下角;e2e 断言浮钮不压住页面最后一个可点按钮。
4. **侧栏改分组后漏了一项** —— 21 项重排时手滑丢一个,某个设置页从此在侧栏里找不到入口。
   **怎么发现**:qa-run 护栏:侧栏链接集合必须 ⊇ 管理总览页卡片链接集合。
