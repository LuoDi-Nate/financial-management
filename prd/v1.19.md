# v1.19 · 超级 Agent —— 把资产讲给你听的对话入口

> 状态:**待评审**(PRD + preview 阶段,尚未写代码)
> 目标版本:app.version = 1.19.0(已 bump,beta 徽记显示在研版本)
> 来源:维护者 2026-08-25 提出 ——「对接一个 managed agent,允许 AI 直接访问我们的数据,用户可以自然语言对话,让 AI 进行分析 / 总结 / 建议」
>
> **维护者已拍板的三件**:
> 1. 走**阿里云百炼 Managed Agents**,不自建编排 ——「能复用就复用」「直接选 B,没有 A 这个方案」。

>    也就是**自己写的 agent loop**,正是上面说「没有 A 这个方案」的那个 A;而且把它设成了**默认**。
>    我当时在这里写的是「补了一条兜底」,用「补 / 兜底」把违背拍板包装成了增强(FR-434b)。

>    架构演进与我几次判断失误的记录见 `tech-design/v1.19.md` §2。
> 2. 对话记录**存本地**(用户自己的服务器),云端 session id 只用来维持上下文
> 3. **只支持通义千问** —— Managed Agents 是阿里云独有,方舟 / DeepSeek 用户用不了,维护者已明确接受
>
> **维护者对定位的纠正(2026-08-25,直接引用)**:
> 「我们核心是帮助用户看清自己的**资产分布**和**托管形式**,帮助做**投资建议**,记录收入和成本本来就是第二优先级的事情。」
> 「核心是用户自己和 agent 对话,只不过为了提高用户的效率,我们可能**预设一些问题**,或者**要求 agent 给一些追问**而已。」

## 0 · 这一版在解决什么

### 现状:六个 AI 入口,全是「我们替你问」

到 v1.18.7 为止,产品里有六处 AI:资产体检综合诊断、调仓建议、月报叙事、透视洞察、归因复盘、目标解读。
它们有一个**共同的形状**:

```
我们挑好事实 → 填进固定 prompt → LLM 返回固定结构 → 渲染成固定卡片
```

好处是数字可控(有一条用生产事故换来的铁律:**LLM 禁止做任何四则运算,数字必须原样照抄**)。
代价是:**用户不能问自己的问题**。他心里那句「我房子占比是不是太高了」「这几个账户里到底哪个在真赚钱」,
产品接不住 —— 除非我们恰好做了那张卡片。

### 这一版换的是什么

**从「我们替你问」变成「你自己问」。** 我们不再逐轮挑数据,而是维护一个 **agent template**
(系统提示词 + 工具清单),由 agent 自己决定调哪个工具、调几次、什么顺序。

这不是「加个聊天框」。真正变化的是**谁在决定取哪些数** —— 这也是本版全部设计取舍的来源。

### 三个用户,一个入口

| 谁 | 怎么用 |
|---|---|
| **维护者本人(工程师)** | 会直接打字问、会追问口径「这个 52% 怎么算的」 |
| **配偶(非技术)** | 不知道「能问什么」→ **预置问题是她唯一可用的入口**,不是可选装饰 |
| **自建用户(陌生人)** | 拿到 Docker 镜像,自己的阿里云 key,自己的服务器 |

## 1 · FR

### 分组 A · 入口与提问

#### FR-423 · 入口:PC 是侧边抽屉,移动是全屏页 —— 外壳不同,流是同一个

> **修正**:我原先写的是「一套响应式,不区分 PC / 移动」。查完之后这条**是错的** ——
> 窄屏放不下侧栏,而 PC 上跳走全屏页会把用户从他正在看的数据上扯开。
> **对话流本身是同一个片段**,外壳必须分。这才是「低成本」的正确解读。

| | PC(≥1024px) | 移动 |
|---|---|---|
| **入口** | **右下角常驻悬浮按钮** —— 用户的心智模型就是「一般在角落里」 | 导航栏**顶级入口**「超级 Agent」 |
| **形态** | **可拉宽的侧边抽屉**(copilot 形态)· 左边数据、右边对话,**同屏对照** | **全屏页**,带「← 回到刚才那页」 |
| **跨页** | **跟着走**。切到报表 / 体检 / 透视,抽屉不关、对话不断 | 全屏页退出后回到来处 |

**为什么 PC 要侧栏而不是独立页**:这一版最重的承诺是「数字点得回原页」(FR-427)。
侧栏能做到**左边看着数、右边问着话**;独立页做不到,每次点引用块都要跳走再跳回。

**为什么必须跨页面保持**:业界研究里被点名的反例正是「用户点进详情页,聊天就消失了,
于是放弃使用」。我们更严重 —— 用户点引用块跳到归因页,对话要是没了,这个功能就废了。

**「就这一屏问」**:各页(仪表盘 / 报表 / 体检 / 透视)的入口把**当前账期、视图币种、账户筛选**带进对话:

> 上下文:2026-08 账期(进行中)· CNY · 全部账户

- 换页时**续同一个对话**,只插一条「上下文已切到 2026-07」的分隔提示 —— **不新开对话**
- 用户可以在对话里改上下文(「按 7 月看」),同样回显

#### FR-424 · 预置问题:按新优先级分三组

首屏给 **6–8 个可点问题**,分组顺序**严格按维护者定的优先级**:

| 组 | 优先级 | 示例问题 |
|---|---|---|
| **钱在哪儿 · 谁在管** | 一 | 「我的钱都放在哪些平台?」「哪些是我自己盯、哪些交给产品了?」「房产占比是不是太高?」「外币敞口有多少?」 |
| **哪些在真赚钱** | 二 | 「剔掉工资以后,哪个账户真在赚钱?」「谁拖后腿,为什么?」「负债利率跑赢资产收益了吗?」 |
| **撑不撑得住** | 三 | 「应急金够几个月?」「这个月涨的是工资还是投资?」 |

- 点一下即发问,**不是模板填空**
- 问过之后 chip 不消失(她可能想再点一次)
- **移动端一行一个,不横滑**(横滑会让下面几组永远看不见)

#### FR-424b · 每次回答之后,再给 2–3 条追问按钮

预置问题只解决**冷启动**;真正的效率来自**答完之后知道下一步能问什么**。
业界研究把这两个时点并列:**首次打开** + **回答之后仍有可深入内容时**。

规则:

- **2–3 条,不是一屏** —— 一次抛十条等于没抛(「循序渐进,不是一次问十个问题」)
- **上下文相关**:刚讲完「钱赚 +¥X」,就给「拆到账户」「和上个月比」「这算好还是差」
- **被忽略过的不再推**。同一条追问推过两次没被点,就不再出现 ——
  重复推已被拒绝的建议会显得**纠缠而且不长眼**
- 追问 chip 与 FR-425 的**澄清反问**是两件事:前者是「还能往下问什么」,后者是「我不问清楚就答不了」

#### FR-425 · agent 信息不足时,先追问再回答

写进 template 的系统提示词。**不是可选行为,是硬要求**。

例:用户问「该不该提前还房贷」,而我们不知道他手里的现金要不要留着 →
agent 应当先问「你这笔现金近一两年有别的用处吗?」,而**不是**直接给结论。

判据:凡是结论会因为一个未知条件**翻转**的问题,必须先问。

#### FR-426 · 不给「你可以随便问我」这种空话

空态里不写「有什么可以帮您?」。空态就是 FR-424 那组问题 + 一句说明这个 agent 能看到什么。

### 分组 B · 答案的可信度(本版最重的一组)

#### FR-427 · 答案里的每个数字,必须挂着账期,且能点回原页

这一整个 v1.18 系列都在修同一类病:**数字说不清自己是哪一期**
(v1.6.29 同屏两个 KPI 打架 / v1.18.3 上面本月下面上月 / v1.18.7 储蓄率不是本期)。
对话是**最容易复发**的地方 —— 一段自然语言里混进三个不同期的数字,用户根本看不出来。

所以:

```
你 8 月净资产涨了 ¥XX
├ 人赚 ¥XX     2026-08 · 进行中   → 去「本期怎么变的」
├ 钱赚 ¥XX     2026-08 · 进行中   → 去「归因复盘」
└ 本月未封板,收支可能没录齐,「钱赚」会偏高
```

- 数字以**可点引用块**呈现,不是纯文字里的裸数字
- 每个引用块带 **账期 + 是否进行中 + 跳转目标页**
- **口径提示自动带出**:进行中账期、储蓄率的账期、紧急储备的分母口径等,
  与页面上现在显示的**逐字一致**

#### FR-428 · 工具只给「已经算好的口径」,不给原始表

**agent 可以自由决定调什么,但它拿不到能让它自己做加减法的东西。**

| 提供 | 不提供 |
|---|---|
| `资产分布(维度, 账期)` · `账户表现(账期)` · `体检结论` · `归因(账期)` · `目标进度` · `财富水位` · `账户流水(账户, 账期)` | 任意 SQL · 原始 `period_snapshot` / `cash_flow` 行 |

两个理由,都是踩过的坑:

1. **禁数学**:LLM 一拿到原始数就会自己算占比和增长率,那条铁律当场作废
2. **口径唯一**:v1.18 整个 bug 家族就是「同一件事两份判据」。agent 自己从原始数据推 =
   **凭空造出第三份口径**,它说的数会和页面对不上,而用户没法判断谁对

每个工具的返回值都必须带 `账期 / 口径名 / 是否进行中`。

#### FR-429 · 只读。没有任何写操作

agent 不能改数据、不能建账户、不能录流水、不能下单。工具层**物理上不提供**写入口,
而不是靠 prompt 约束。

#### FR-430 · 拒绝的口径

维护者定:**不专门做拒绝设计**(「不用,我们核心是…」)。所以只保留最低限度 ——
系统提示词里继承现有六处 AI 已有的三条边界:**不预测涨跌、不荐具体产品、不做担保性话术**。
其余问不到的东西,agent 如实说「这个我看不到」即可,不做专门的引导话术。

### 分组 C · 会话与存储

#### FR-431 · 对话存本地,展示只读本地

| 存哪 | 存什么 | 用途 |
|---|---|---|
| **我们自己的库** | 全量对话(用户消息 / agent 回答 / 工具调用摘要 / 引用的账期)+ 云端 session id | 历史列表、翻看、搜索。**页面只从这里读** |
| **百炼服务端** | Session 事件历史 | 只用来维持多轮上下文 |

理由(维护者原话):「本来就是用户自建的,都在用户托管的服务器里」。
云端那份过期、换账号、或用户注销阿里云,**本地历史不受影响**。

> 隐私提示:对话正文会包含真实金额 —— 那本来就是用户自己库里的数据,没有新增暴露面。
> 但**不进 `audit_log`**(那张表会被导出),也不进任何日志。

#### FR-431b · 能随时另起一段,旧的不丢

维护者问的「用户可以放弃当前对话历史重新来」—— 要做,而且是**另起**不是**清空**:

- 输入框旁常驻**「新对话」**;点了就开一段新的,**旧的进历史,不删**
- 顶部显示**当前对话的标题**(取首条提问),点它可切换到别的对话
- 「放弃」= 开新的 + 不再引用旧上下文。真要删,去历史里删(FR-432)

**什么时候不自动新建**:换页、换账期、换币种**都不新建** —— 只在对话里插一条
「上下文已切到 …」的分隔提示。每页一个对话会让历史碎成一堆一轮的残片,
而且违背「跨页面保持可用」。

**云端那份怎么办**:新对话 = 新的 `previous_response_id` 链;旧链自然失效不用管。
本地那份是完整的,永远还在。

#### FR-431c · 语音输入:第一版不自建,但要**告诉用户系统键盘就能说**

查下来的现状:

- **iOS Safari 的 Web Speech(`webkitSpeechRecognition`)名义支持、实际不可靠** ——
  可能静默失败,`interimResults` 行为与文档不符(Apple 开发者论坛有实例)
- 而**手机系统键盘上本来就有听写麦克风** —— 点输入框、按麦克风、说话,**零代码、零成本、
  零新增隐私面**(音频走的是系统自己的通道,不经过我们)

所以第一版:

- **不自建 ASR**,不上 `webkitSpeechRecognition`
- 但**要把这件事说出来** —— 输入框 placeholder 写「也可以直接问……(手机上按键盘的麦克风说就行)」。
  业界研究里反复出现的一条是:**用户不会假设一个功能存在**,不告诉他就等于没有

**为什么值得认真对待**:研究里明确写着「只能打字」是部分用户**直接放弃使用**的原因,
而且这是无障碍问题。我们的目标用户里就有一个不打字的人。

**要真做**(第二刀再评估):走阿里云 DashScope 的语音识别,`MediaRecorder` 录音上传。
代价是**新增一条音频出网通道** —— 那是今天没有的暴露面,要单独评估,不能顺手加。

#### FR-431d · 流式时不要自动滚到底

反直觉但有依据:流式输出应当把滚动位置停在**新消息的顶部**,让人从头读起,
而不是一路追着最后一个字滚。追着滚会让用户**读不了正在生成的内容**,只能等它停。

我们的答案里还有引用块 —— 一路滚到底会让最重要的数字一闪而过。

#### FR-431e · 不做成「两套 AI」

现有六个 AI 入口(体检诊断 / 调仓建议 / 月报叙事 / 透视洞察 / 归因复盘 / 目标解读)
是**固定卡片**,「超级 Agent」是**自由问答**。它们必须像**一套东西的两种入口**,而不是两套:

- 每张 AI 卡片旁给一个**「就这个问下去」**,点进对话时**带上那张卡的结论作为上下文**
- 对话里 agent 引用体检结论时,引用块**点回那张卡**

**判据**:用户不需要理解我们的内部结构,才能找到该用哪一个。

#### FR-432 · 历史列表

- 按时间倒序,标题取首条用户消息前 20 字
- 可删除单条会话(**本地删 + 云端 session 一起清**)
- **不做**跨会话搜索(第一版;要不要做看实际使用)

### 分组 D · 开通与降级

#### FR-432b · 只读接口 + HTTP MCP(本版主交付物 · 「超级 Agent」依赖它)

维护者 2026-08-26:「我们搞个 OpenAPI?把你要开放的接口都开放出去…
**我们如何让用户(程序员们)快速部署,是否能简简单单注册一个 mcp 就搞定**」
+「**我没有看到安全相关的设计?你认真点,这可是用户资产数据**」。

**「超级 Agent」就跑在这上面** —— 百炼的智能体要**回调**这个接口才能读到你的数据。
同一个接口也让你把自己的 AI 客户端接上来。

**没启用 AI 时接口返回 `404`;启用之后,凭据不对也返回 `404`**(不是 `401` ——
`401` 等于告诉扫描者「这里有东西,只是你没凭据」,而这背后是一个家庭的全部资产)。

**接入步骤(6 步,其中 3 步人工)**:

| 步 | 在哪 | 做什么 |
|---|---|---|
| ① | 管理页 | 新增接入点(名字 · scope · 有效期)→ 复制**只显示一次**的密钥与配置 |
| **②** | **百炼控制台** | MCP 管理 → 创建自定义 MCP → 安装方式 http → 粘配置 |
| **③** | **百炼控制台** | 复制服务 ID |
| **④** | 管理页 | 粘回服务 ID → 完成接入 |
| ⑤⑥ | 自动 | 我们建 Agent、建会话、发事件、收 SSE |

> ②③ 必须人工,原因是百炼的 `mcp_servers` 只能引用**已注册**服务,而注册**无公开 API**。
> 这是依赖方的结构限制,部署文档里要写成图文步骤。

**安全要求(详见 `tech-design/v1.19.md` §15)**:

| | |
|---|---|
| 凭据位置 | **`Authorization` 头,不放 URL** —— MCP 规范硬性禁止放 query string |
| 凭据存储 | 库里**只存 hash**,明文只在生成那一刻显示一次 |
| 粒度 | **一个接入点一把**;泄露一把 ≠ 全线失守 |
| 有效期 | 默认 90 天,到期自动失效,提前 7 天提醒 |
| scope | `aggregate`(只给聚合与占比,**默认**)/ `detail`(含账户名与流水) |
| 真名 | **复用现有脱敏** —— 成员真名 → 代号,与六处 AI 同一份实现 |
| 限流 | 60 次/分 · 2000 次/天,超了 429 |
| 熔断 | 调用突增 / 大量路径探测 → **自动停用 + 通知** |
| 通知 | **首次被使用**、被吊销、被熔断 → 站内 +(可选)微信 |
| 审计 | 每次调用记接口/时间/IP/UA/结果,**不记返回体** |
| 只读 | **物理保证** —— 这批接口没有写方法(护栏静态扫) |

**启用时页面要原样说的话**(不许美化):

> 打开之后,**拿到这串口令的人就能读到你的全部资产数据**(只读,改不了,看不到家人真名)。
> 这串口令要贴进阿里云百炼 —— 也就是说,**你在信任阿里云替你保管它**。
> 别发到群里、别贴进公开仓库、别截图。怀疑泄露就点「重新生成」。

#### FR-432c · 密钥要能**快速更换**,而且换的时候不断服务

维护者 2026-08-27:「需要增加更新 token 的能力,比如用户觉得时长 / 泄漏等原因,
可以做到**快速更换**这个 token」。

**先说清楚痛点**:密钥存在**百炼那一侧**,而百炼的自定义 MCP
「部署后仅支持编辑名称和描述,改配置必须**先停止部署 → 修改 → 重新部署**」。
所以换密钥的真实代价是**用户要去百炼折腾一趟** —— 如果这么痛,用户就不会换,
安全设计等于白写。

**所以拆成四个场景,大多数根本不用碰百炼**:

| 场景 | 操作 | 要不要动百炼 | 中断 |
|---|---|---|---|
| **到期临近** | 一键**续期 90 天**(密钥不变) | **不用** | 无 |
| **例行换密钥** | **换绑向导**(新旧并存) | 要,一次 | **无** |
| **怀疑泄漏** | **立即断开** | 事后重新接入 | 有(应该有) |
| 不再使用 | 删除接入点 | 不用 | — |

**最有价值的是第一行**:多数人点「重新生成」只是因为看到「即将过期」。
把**续期**和**换密钥**拆开之后,那类需求**一键搞定、零中断、零风险**。

**换绑向导怎么做到零中断**:生成新密钥时**旧的保持有效**;
由「**新密钥首次被使用**」这个事实触发自动吊销旧密钥 —— 不是定时器猜的。
换绑期间管理页显示「还在用旧密钥 / 已切到新密钥」,7 天没完成会提醒。

**紧急断开**:一键让该接入点**全部**密钥(含换绑中的新密钥)立刻失效,
端点即刻 404 —— **不需要动百炼**,先止血,回头再从容重新接入。
事后审计可查**泄漏窗口内被读了什么**。

#### FR-433 · Agent 模板由我们维护,用户不用碰

系统提示词与工具清单是**我们的产品责任**,不是用户的配置项。

- **模板在仓库里,随版本走**(`resources/prompts/ask-system.md`)—— 发版即生效
- 接入时我们用用户自己的通义 key **自动创建 Agent**;版本变更时自动更新
- 用户**不需要**在百炼里编辑提示词、挑模型、配工具

> **更新时的坑要说清**:百炼的 `PUT /agents/{id}` 是**全量替换 + 乐观锁** ——
> 缺省字段视为清空,所以每次必须带全;而且**会话创建时锁定 version**,
> 已有对话不会被中途改掉模板。

**用户唯一要做的**是 FR-432b 那 6 步接入里的 ②③④(两次复制粘贴 + 一次进百炼控制台),
以及日后可能的密钥更换(FR-432c)。

#### FR-434 · 没配通义时,不是空白页

方舟 / DeepSeek 用户点进「超级 Agent」,页面要**说清为什么**并给下一步:

> 这个功能目前需要**通义千问**。
> 你当前配的是方舟 —— 去「数据源接入」加一把通义的 key 就能用,原有的 AI 体检 / 调仓建议不受影响。

带直达「数据源接入」的链接。

#### FR-434b · 内网 / 没有域名的用户:给一条**能走的路**,而不是一句说明

选了 Managed Agents 之后,百炼必须能**回调**用户的实例 —— 于是实例必须公网可达 + HTTPS。

原本这一条写的是「说清楚为什么用不了」。**做的时候改了主意**:自托管用户里
装在家里 NAS、软路由后面、公司内网的占相当比例,对他们来说这不是「配起来麻烦」,
是物理上不可能。一个多数人永远开不了的功能,说明写得再清楚也还是开不了。

所以「超级 Agent」有**两条路**,在「AI 接入」页选:

| | 本机直连(默认) | 百炼托管 Agent |
|---|---|---|
| 要什么 | 一个大模型密钥(「数据源接入」里已有的那个) | 公网域名 + HTTPS + 百炼业务空间 + 手工注册 MCP 服务 |
| 谁在跑 | 你的服务器主动去调模型,**查数在本机完成** | 智能体跑在阿里云,取数时回头访问你这台机器 |
| 强在哪 | 门槛低、不开任何对外端口 | 服务端记着上下文、可中断续接、能装 skill |

页面上两条都列出来,**每条后面直接写「现在能不能用、不能用是差什么」**——
不许只说「暂不可用」或「去配 key」。托管那条不满足时,本机直连仍然可用,
用户不会看到一个死掉的功能。

> 这是一个**明确的产品取舍**:选 Managed Agents 换来 runtime 能力(session 持久化 / 中断续接),
> 代价是百炼必须能回调我们 —— 一部分自建用户因此用不了。
> 记在这里,是为了将来有人问「为什么内网用不了」时,能查到这是**当时的选择**而不是漏掉的需求。

#### FR-436 · 花了多少钱,用户要看得见

这个功能烧的是**用户自己的**阿里云额度。所以不能只管好不好用,还得让他**知道花了多少**。

- 管理页「AI 接入」显示:**本月 token 用量 + 估算花费**(按当前模型单价)
- 可设**月度提醒阈值**,超了给站内提示(不自动断 —— 断了他会以为坏了)
- 单段对话**硬上限**(约 30 轮):触顶时提示「这段对话太长了,建议新开一段」,
  **说明原因是成本**,不含糊

**默认用 `qwen3.7-plus` 而不是 `max`** —— 本场景是「读已算好的数并讲清楚」,不是复杂推理;
`max` 贵 5–6 倍而收益不明显。用户可在数据源接入页自行改。

> 实测口径与敏感度分析见 `tech-design/v1.19.md` §六。典型用法 **¥0.15/月**,
> 重度 **¥1.05/月**(plus + 上下文缓存),与项目「成本几毛/月」的宣称一致。

#### FR-435 · 出错要说人话,并且可重试

- 工具执行期间 → 流式给「正在查你的资产分布…」这类**工具级进度**,不是转圈
- 超时 / 失败 → 说清哪一步失败 + 一键重试,**不吞掉已经产生的部分回答**
- 型号失效 / key 失效 → 复用 v1.18.5 已有的 `classifyLlmError` 文案能力

### FR-437 · 支出可以记在信用卡上(v1.19.3 补丁 · 线上反馈)

> 与「超级 Agent」无关,是同一版本线上收到的一个记账缺陷。按维护者定的口径当 bugfix 走小版本,并进本文件。

**用户诉求**:「支出页面为什么不能选中贷款类的账户?想给信用卡账户(负债)做支出维护,却无法选中。」

**这是设计如此,但设计有盲区。** 原实现在两处显式排除负债账户,理由写在 `EntryService.recordExpense` 的 javadoc 里:

> 在贷款账户上记一笔支出等于「又借了一笔」,不是花钱。

这话**对房贷 / 车贷完全成立**,但它默认了「借钱」和「花钱」互斥 —— 而**刷卡消费同时就是这两件事**。根因是 `AccountType` 里没有信用卡类型,信用卡只能录成 `LOAN`,于是被整类连坐。

| # | 要求 |
|---|---|
| FR-437a | 支出账户候选**包含负债账户**,信用卡可选。用户在支出页能给信用卡记一笔消费 |
| FR-437b | 记在信用卡上的支出让该卡**欠得更多**(负债余额绝对值变大),净资产相应下降 |
| FR-437c | 负债账户上**禁止**「还贷」「利息支出」两个类目 —— 那两笔要记在钱实际流出的现金账户上,否则与卡上消费**重复计入本月支出** |
| FR-437d | 前端在选中负债账户时**移除**这两个类目并说明原因;服务端独立硬拦,不依赖前端 |

**明确不做**:不新增 `CREDIT_CARD` 账户类型(维护者选的是最快路线)。代价是**房贷 / 车贷也会出现在支出下拉里**,靠 FR-437c 挡住其中最危险的误用(在房贷上记「还贷」),其余靠用户自觉。把信用卡独立成类型是更正确的解,留待后续版本 —— 届时要按 `feedback_enum_add_sweep` 扫全链(模板里的 `'LOAN'` 硬编码条件、写死的计数分母、面向用户裸露的 code)。

**验收**:走用户真实点击路径 —— 填报页支出区下拉里能看到信用卡 → 记一笔消费 → 该卡欠款增加、本月支出增加 → 切回现金账户时「还贷」类目恢复。

### FR-438 · 截图识别失败不许伪装成「所有持仓都卖了」(v1.19.4 补丁 · 线上事故)

> 与「超级 Agent」无关。同一版本线上收到的反馈:「上传更新完全失败,提示没有任何持仓变动」。

**根因不在识别本身**:视觉模型的免费额度耗尽,上游返回 403。真正的缺陷是这个失败**被吞成了成功** ——
识别一张都没成 → 库里每条持仓都因「本次没截到」被判成「卖出?」→ 而页面上没有任何字提到识别失败。
用户面对的是一张**结构完全正常**的比对表,并且点了确认。没丢数据只因为卖出项默认「保留」;
**勾一下归档就会一次清空**。

| # | 要求 |
|---|---|
| FR-438a | 一张都没识别出来时,进**独立的失败状态**,不生成任何比对项 |
| FR-438b | 失败页面**没有确认按钮**(不是 form),服务端也拒绝确认 —— 误确认要在物理上不可能,不能只靠用户读提示 |
| FR-438c | 部分图失败时**整体不判「卖出」**:「没识别出来」不等于「卖掉了」,而这一步分不出来 |
| FR-438d | 失败原因要**能照着做**:额度耗尽说「请重试」是错的建议;要分清额度 / 鉴权 / 限流 / 型号 / 超时 / 网络 |
| FR-438e | 失败原因必须**落到页面上**。事故中该字段实测为空 —— 异常在内层就被吃掉了,用户一个字的线索都没有 |

**为什么 c 比 a 更重要**:全失败还算显眼(表里一条正常项都没有);**部分失败才真正骗人** ——
表格其余部分完全正常,只混着几条假的卖出建议,用户没有任何线索能分辨哪几条是假的。

**验收**:配一把无效 key 真的跑一次失败流程,验状态、验库里没有比对项、验页面没有确认入口、验持仓一条没动。

### FR-442 · 百炼接入教程漏了「模型授权」这一步(v1.19.12 补丁)

> 用户原话:「现有的配置不重要,重要的是 你是否前面引导用户的完整流程是有差错的?
> 如果是 完整调整,我可以跟着你调整后的教程,重新配置」。

**结论:是,而且不是补一句能解决的。** 教程有四处实质缺陷,其中第一处最致命 ——
用户把每一步都做对,最后仍然失败,而失败信息指向的是他没做错的地方:

| # | 缺陷 | 后果 |
|---|---|---|
| FR-442a | **整条教程没有「模型」这一环** | 走到最后报「模型不存在」,而前面没有任何一步提过模型要授权 |
| FR-442b | 业务空间 ID 写成「形如 `llm-…`」 | `ws-…` 同样有效;用户照格式判断,会去改一个本来就对的值 |
| FR-442c | 没区分**默认业务空间**与**子业务空间** | 而这正是失败的根因:子空间默认一个标准模型都调不了 |
| FR-442d | 没说 MCP 服务要注册在**同一个业务空间** | 跨空间注册,Agent 引用不到 |

修法(用户视角):

| # | 要求 |
|---|---|
| FR-442e | 向导从 5 步扩到 **6 步**,新增第 3 步「确认这个业务空间能调模型」 |
| FR-442f | 第 3 步要明说:**「聊天能用」不代表「这里能用」** —— 北京地域的对话接口不带业务空间,走的是全局通道 |
| FR-442g | 模型**必须可配**。原来写死 `qwen-plus`,而子空间开通的未必是它 —— 用户按提示开通了,页面上却无处可改 |
| FR-442h | 失败提示按上游原话**分流**:认得出的说准,认不出的**承认在猜**,不给笃定的错方向 |

**FR-442h 的由来**:上一版这句提示是「若提示指向配置,再核对业务空间 ID / MCP 服务 ID / 公网地址」——
用户那三样全是对的,这句话把排查带偏了一整轮。**一句笃定的错方向,比不给提示更糟。**

### FR-443 · Agent 建出来了,但它是个没有系统提示词的空壳(v1.19.13 补丁)

> 用户报:「创建失败 · 百炼返回:upstream 405 · 请求方法不支持」。

查下来发现**三件事同时错了**,而它们叠在一起把用户彻底带偏:

| # | 事实 | 用户看到的 |

**而这些纪律正是这一版全部可信度设计的落点**(见分组 B)。

| # | 要求 |
|---|---|
| FR-443a | 创建 / 更新之后必须**回读确认**模板真的存住了(系统提示词与 MCP 引用都验),存不住就报错 |

| FR-443c | 只有**上游**的错才配一句我们的猜测;我们自己抛的错已经把话说完了,再补一句只会添乱 |

凡是靠**字段名约定**写入第三方的地方,都可能被静默丢弃 —— 这类失败不报错、不降级、
HTTP 200,只有回读能抓到。

### FR-444 · 模板通了,但一提问就 400(v1.19.14 补丁)

> 用户报:「百炼返回了错误(400)。稍后再试试。」

Agent 模板这时已经完全正常(v1.19.13 之后回读确认过)。断的是**问答链路**本身 ——
我们对百炼会话接口的形状<b>从头到尾理解错了</b>,而这一路的报错**每一条都明确说了缺什么**,
只是全被那句「百炼返回了错误(400)」盖住,只进了日志。

| 百炼原话 | 我们错在哪 |
|---|---|
| `Missing required field: 'agent'` | 建会话的字段名是 `agent`,不是 `agent_id` |
| `Field 'input' must be an array` | `input` 是**事件数组**,不是单个对象 |
| `type must be one of: …, message, …` | 每个事件要带 `type` |
| `'content' must be a non-empty array` | `content` 是**内容块数组**,不是字符串 |

还有一条**没有报错**、因而最难发现的:`POST /events` 只负责<b>把事件追加进会话</b>,
它的响应就是刚写进去那条的回显,**Content-Type 永远是 `application/json`** ——
就算按官方文档加上 `Accept: text/event-stream` 也一样(实测)。
答案要从另一个端点 `GET /sessions/{id}/events/stream` 读。
**把追加请求当成答案流读,结果是一个字都读不到,而且不报错。**

| # | 要求 |
|---|---|
| FR-444a | 问答分三步:建会话 → 追加 message 事件 → 从 `/events/stream` 读答案 |
| FR-444b | 读流必须带 `after_id`。这个流**默认重放会话全部历史**,而会话是跨轮复用的(它正是选托管路线的理由)—— 不带就会把前面每一轮的答案再吐一遍 |
| FR-444c | 终止信号读 `content[].data.session_status`(`idle`/`terminated`);**事件自身也有一个 `status`**,拿它当会话状态会在第一条事件就截断 |
| FR-444d | 问答报错要带上**百炼原话** —— 这是同一个病的第三次复发 |

**FR-444d 的由来**:v1.19.4 是「识别失败,请重试」盖住额度耗尽,v1.19.11 是「upstream 400」
盖住字段类型错,这次是「百炼返回了错误(400)」盖住 `Missing required field: 'agent'`。
**每一次,那句被盖住的话都直接指出了 bug 在哪。**

### FR-445 · 「百炼到底连上我的账房了吗」要能一键问出来(v1.19.15)

> 联调到最后发现:会话建得起来、答案也流得回来,但智能体说
> 「capabilities 工具在当前会话里不可用 —— 我这边实际能调用的只有文件交付类工具」。

这是整条引导流程里**最后一个看不见的失败**:百炼运行时连不上 MCP 服务时<b>不报错</b>,
只是让模型在没有工具的情况下作答。用户看到的是一段像**模型犯傻**的话,
而真因在百炼控制台里那个服务的部署状态。

| # | 要求 |
|---|---|
| FR-445a | 管理页给一个「测一下百炼连没连上这个账房」按钮,真发一问,十几秒出结论 |
| FR-445b | 判据**看我们自己的入站审计**,不问模型 —— 模型的自述不是证据,它会把「我没看到」说成「不可用」 |
| FR-445c | 不通时要说清**已经排除了什么**(凭据 / 地址 / Agent / MCP 引用),并直接指向「MCP 服务的部署状态」 |
| FR-445d | 结论是纯文本 flash,不许有 markdown 记号 |

**FR-445b 的判据细节**:按 `user_agent`(`Bailian-MCP`)而不是 IP —— 百炼的出口 IP 实测跨了两个网段。

## 2 · 不做什么

| 不做 | 为什么 |
|---|---|
| **主动弹出 / 每日播报 / 推送提醒** | 硬约束是「每月 10 分钟」,定位是**问一次就走**。<br>**注意与 FR-423 区分**:右下角**常驻入口**是要做的(那是用户的心智模型,不做等于藏起来);不做的是**它主动跳出来跟你说话** |
| **让用户自定义 prompt / 建自己的 agent** | template 是我们的产品责任。用户改了 prompt 出错,我们无从复现,而且禁数学那条会被绕过 |
| **消费品类分析**(「这个月外卖花了多少」) | 颗粒度停在账户级月度快照,消费品类细化在**刻意不做**清单里 |
| **预测涨跌 / 荐具体产品** | 现有六处 AI 的边界,不因为换成对话就放开 |
| **多 agent / 工作流编排** | 一个 agent 够用。多 agent 是把复杂度前移到我们身上,用户感知不到 |
| **跨会话搜索** | 第一版不做,看实际使用频次再说 |
| **自建语音识别** | 手机系统键盘的听写已经能用,零成本零隐私面;自建要新开一条音频出网通道(见 FR-431c) |
| **对话里做写操作**(改余额 / 建账户) | 只读是**工具层物理不提供**(FR-429)。「说一句就记账」听着诱人,但那是另一个产品 |
| ~~**PC / 移动分开设计**~~ | **这条撤销了**。对话流是同一个片段,但**外壳必须分**:PC 侧边抽屉(同屏对照数据)/ 移动全屏页(窄屏放不下侧栏)。见 FR-423 |

## 3 · 调研结论(原为待决项,已自行查清并决定)

> 以下是查证之后的决定,每条都写了依据。

### 3.1 · 「托管形式」= 派生视图,不是新维度(已定)

查了代码:资产透视现有 **8 个维度** —— 风险 / 大类 / 行业 / 平台 / 主理人 / 用途 / 地域 / 币种,
**没有**「托管形式」这一维。所以它不是现成的,得定义。

定义成**派生视图**(由已有字段推导,不新增录入负担):

| 托管形式 | 判据(全部来自已有字段) |
|---|---|
| **自己盯** | 账户类型 STOCK / CRYPTO / METAL,且持仓是你自己建的标的 |
| **交给产品** | WEALTH / 基金类持仓 —— 有**穿透结果**的走穿透后成分(v1.5 起) |
| **不动** | PROPERTY / INSURANCE —— 存量登记,估值靠手填 |
| **随时可取** | CASH + 被标 LIQUID 的货基类 |

另外三个切法**直接复用现有维度**,零新增:

- **钱托管在哪个机构** → 现有 `平台` 维度(支付宝 / 券商 / 银行 / 交易所)
- **谁在管** → 现有 `主理人` 维度(`account.primary_owner_member_id`)
- **数字怎么来的** → `valuation_mode` + v1.18 的**流水来源标签**(手填 / 股价接口 / 富途同步 / 截图导入 …)

**为什么这么定**:维护者说核心是「资产分布和托管形式」。「分布」现有 8 个维度已经覆盖;
「托管形式」问的是**「这笔钱由谁替你做决定、数字由谁产生」** —— 这是一个新的**讲法**,
不是新的**数据**。做成派生视图,agent 不需要任何新录入就能回答。

### 3.2 · 技术选型归 TDD

接口选型(开放什么 / 用哪个 runtime)、凭据与安全、接入时序,全部在
[`tech-design/v1.19.md`](../tech-design/v1.19.md)。已定:

- **开放语义层**(`LensQuery` + `PivotEngine`)—— 自由度大而口径零新增
- **Managed Agents** 作为 runtime —— 要的是 session 持久化与中断续接

## 4 · 验收标准

| # | 标准 |
|---|---|
| 1 | 非技术用户**不打字**,只点预置问题,能完成一轮有价值的问答 |
| 2 | 答案里出现的**每一个金额 / 百分比**,都能点回产生它的页面,且账期标注与该页**逐字一致** |
| 3 | 问一个「结论会因未知条件翻转」的问题(如提前还贷),agent **先追问**而不是直接下结论 |
| 4 | agent 无法通过任何工具拿到原始表 / 执行 SQL(**工具层物理不提供**,不靠 prompt) |
| 5 | agent 无法产生任何写操作 |
| 6 | 未配通义的用户看到**说明 + 下一步链接**,不是空白页 |
| 7 | 对话历史在**本地库**完整可查;人为清掉云端 session 后,历史仍在 |
| 8 | 对话正文不出现在 `audit_log` 与任何日志里 |
| 9 | PC + 移动双端截图核对排版 |
| 10 | agent 回答中的数字与页面对不上时,能通过引用块**一眼定位**到是哪个口径出了问题 |
