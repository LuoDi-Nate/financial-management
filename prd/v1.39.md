## 0 · 这一版在解决什么

今天的退休目标把家庭净资产当作可供退休的本金,按默认 4% 取用率给出本金需求,再用不可配置的 2%/5%/8% 画达成年份。用户看不到哪些钱能花、每月投入来自哪些月份、未来购买力和今天购买力如何换算。新收入只落账户流水时,月供预测仍可能停在旧 PMC 月份。

**服务谁**:维护者与非技术家人。主推动力是“能核对自己的退休生活是否有资金支撑”,不是增加一堆理财参数。

**本版名词**:今天购买力、退休生活本金、单独预留、大额剩余支出、计划月投入。都是计划口径,不改 [AGENTS.md](../AGENTS.md) §3 的家庭净资产、收益、分析范围等定义。

**自动支出建议的边界**:

- 统一以家庭本位币消费口径为起点,已定稿包括 CLOSED 与自然结束且填报完成的期;逐笔/PMC 总额按项目既有优先规则。没有明细的月只能给总额参考,不能假装知道育儿/租金/医疗占比。
- 已明确填完的 0 支出期要进分母;未填期不当 0,净退款期原样列出但需确认如何反映在长期预算。完整数据不足 3 期时不默认启用自动模式,允许手填。12 期窗口有缺失要列“实际 N/12 期”。
- 年度旅游、年度保费等反复发生的开销不应因单月波动被自动丢弃。用户按类目或一次性标记选择剔除,列剔除金额与理由;总额模式分不出来时不做假拆分。
- 提供“常规预算已含育儿/医疗”的归属确认:已计入 X 的相同支出不能再进 B。若选择整项大额预留,当前对应消费须先从 X 扣除;无法识别的由用户修订 X,否则标“待核对”,不能给正式达标判断。
- 用户选“跟随账上建议”后,只有定稿窗口变化或账期重开后再定稿时更新 X,显示前后差与期数。普通余额刷新不能改预算。用户选固定计划时,新账期仅更新旁边建议。
- 无法拆分还款/消费的非零历史总额只列来源,不用作自动生活预算;明确零值仍参与。周账期不冒充月账期,本版周账期家庭手填月度生活预算与未来月投入。

### 3.3 可手算的结果定义

以下是产品验收合同,不是技术选型。今天购买力的基准为每次测算日期,用户手填计划金额保存其币值日期;跨年重算按计划 π 折到新的今天,不把名义预算永远误标今天价。更改 π 前后金额基准须明确展示。

```text
r = (1 + R) / (1 + π) - 1              # 名义模式
r = 直接输入值                         # 实际模式,不再次扣通胀
P = A - D - B                          # 可供退休生活生息的净本金
W = max(X - J, 0)                      # 每月需由投资负担的生活费
T = 12 × W / r                        # r > 0,今天购买力的生活本金门槛
G = max(T - P, 0)                     # 生活本金缺口
X支持 = J + max(P, 0) × r / 12         # P≥0、r>0 时可解释的预算反算
覆盖率 = P / T                         # T>0;允许显示负值/>100%,进度条另夹到0–100
```

首屏同时列 `A - D` 净资金与 `T + B` 总需求,两者的差必须等于 `T - P`。D/B 不再同时加入门槛又从 P 再扣一次。

门槛采用年化生活费、年末支付的基准合同,月是预算单位,不是已模拟逐月提款。积累期才按下节月度递推;两阶段明确标注,不把这个年化基准称为经过逐月支出压力测试的退休方案。

负值与零的定义:

- P<0:显示“单独预留还缺 X”,暂停未来达成日,不能把负本金按正投资收益复利。
- r≤0 且 W>0:门槛不是一个有限正数,显示“这组假设不能长期维持本金购买力”,保留输入,不返回0、∞图形或沿用旧结果。
- W=0:生活费由确认的 J 覆盖,不除以 r;保留 D/B 缺口,不显示0除0的百分比或“保证退休”。r<0 时仍提示剩余投资本金会损失购买力。
- 金额来源缺失:结果标待补齐,不能用缺失=0让进度升高。汇率缺失时列币种与账户并停止正式汇总。
- 配置输入必须区分空、0、负值。X/B/J不得为负;回报可负;C可为负,表示持续净流出。负 C 不裁成0以画出乐观结果。

**合成验收例**:X=10,000,J=0,r直接=2.5%,B=1,200,000,A=6,000,000,D=0 → T=4,800,000,P=4,800,000,覆盖100%。反算 X支持=10,000。同样支出改名义R=4.5%、π=2% → T=4,896,000,倍数489.6,差异原因可见。

### 3.4 未来路径与达成时间

所有曲线与目标线在同一张“今天购买力”坐标里。预留 B 视为已经从可投资资金中隔离,不享受投资回报;按计划保持其购买力,不模拟到期支出或预留投资收益。未来计划变化需更新 B,不能用预测误报已支付。

积累期每个情景的有效月回报 `q=((1+R情景)/(1+π))^(1/12)-1`;从 P 开始每月先复利、再月末投入。C名义固定时,第 m 月实值投入=C/(1+π)^(m/12);随通胀增长时,实值投入恒为C。不再混用年复利和 r/12 月复利。直接实际回报模式只规定退休门槛 r,积累期三情景仍明确用名义率换实值。

搜索未来最多50年第一次达到 T 的月份,逐月检查,不依赖曲线必然单调。目标年月另画标记并给届时缺口,不能把希望退休的年月误写成预测达成年月。三情景没有达到则写“50年内未达到”;已达到写“当前”,可退休当月无需再填更大年龄。输入缺失/P<0 时不推日期。达到线是确定性门槛,不是退休后资金不耗尽的概率。

### 3.5 来源与关键文案

“怎么算的”紧邻结果,不藏在三级菜单。展开有:本次代入式 → 每个变量的来源 → 节目简算 → 本项目扩展 → 原视频按钮。原视频外链只带 BV/时间,不带家庭数值、账户名或查询数据,不自动嵌入播放器/第三方统计。

关键文案:

- “按今天购买力估算;收益和通胀是你选的长期假设。”
- “480来自 12÷2.5%。本计划使用的倍数会随实际回报变化。”
- “已计入每月生活费的同一笔开销,不用再单独预留。”
- “自住房可以保障居住,但本计划没有把它当作每月生活费本金。”
- “这不是资金永不耗尽的保证;先亏后涨时,实际结果可能不同。”
- “未核对的预留不按零处理。”

| FR-1444 | 打开 AI 接入设置页不再等待百炼回读。模板状态显示最近检查时间、未检查/失败/过期,可显式刷新;创建或更新模板后使缓存失效,不同配置不复用旧读数 |
| FR-1445 | 管理页的超时秒数保存后下一次文本或本地 Agent 调用生效,无需重启;说明是单次请求等待上限,与工具循环总耗时不同 |

验证使用本地 HTTP 桩或 mock,不消耗真实模型额度。商户分类仍只传商户名与分类清单,不传金额和时间;本地 Agent 继续只读工具,不扩大权限。

## 4 · 不做什么

不做证券级持仓、交易建议/下单、逐笔手工记账、自动转账/锁款、推荐金融产品或医保精算。不引入外部账户接入,不例外扩大 AGENTS §1 的产品边界。

本版不做允许本金用完的寿命模型、蒙特卡洛/成功概率、夫妻分阶段退休、退休后才开始领的养老金桥接、逐月贷款摊还或房产出售时点模拟。后几项需要时序现金流模型,不能用“养老金×12/r”提前抵掉今天全部生活本金。允许录备注,但不影响结果。

## 6 · 存量影响与口径声明

| 维度 | 影响 |
|---|---|
| schema | 需要保存新方案参数/版本、资金范围、确认状态和预算基准日;如何存储及旧jar兼容留TDD。只增不破坏既有字段 |
| 口径 | 退休新方案从全资产/4%提款/未来价分母,变为选定资金扣负债预留/真实回报/同一购买力;只对用户确认的新方案生效 |
| UI | 旧退休目标继续原数值并标旧算法,有明显“查看新算法”入口;教育/应急/自定义原路径不变 |
| 真实数据 | 不读prod;调研、preview、自动化例均合成 |

零差异基线来自 tag `v1.37.1`,不是浮动master。新算法未启用时,老目标及其AI展示数值保持该版;预览差异不写入目标。采用新算法后不修改账户/流水/历史封板指标,但实时目标条的计划值会变,须注明“当前计划”,不冒充历史目标快照。

### 跨页联动矩阵

此版不新增余额或账期写入口。计划保存、采用新算法、退出新算法是显式用户操作,不落业务流水;自动建议更新是定稿窗口变化,余额仍锚最新余额期。

| 页面 / 消费方 | 当前余额/估值改变 | 收支窗口定稿/改正 | 固定计划改变 | 算法切换 |
|---|---|---|---|---|
| 目标详情、新建/编辑预览 | 资金/缺口变 | 建议和C参考变;自动X按授权变 | 本次结果及路径变 | 先看差异,确认后变 |
| 目标列表、dashboard目标条、报表目标条 | 与详情同一结果 | 与详情同一结果 | 与详情同一结果 | 同一份计划版本 |
| 填报页 | 沿既有余额/固定收支逻辑 | 沿既有录入逻辑 | 不变 | 不变;全仓未找到旧文档提到的退休投入提示,本版不另造 |
| 目标AI月报/预警、体检AI目标上下文 | 新请求取新结果 | 同左 | 旧结果标参数已变 | 不展示旧报告为新模型结论 |
| 家庭净资产、收入、储蓄率、封板报表、教育/应急/自定义 | 沿现有事实变化 | 沿现有事实变化 | 不变 | 不变 |

规律:只改变退休计划的解释与结果,不改变账上事实。所有退休数值消费方必须用同一计划结果,不能保留另一个“根据全家资产算月供”的旁路。已读入口见调研§4,开发时守护检索所有调用点,不是只测详情页。

## 7 · 开关与默认值

每个退休目标有旧/新算法选择。**现存目标默认旧**,确认后保存新版本;新建默认新方案草稿。不是全家庭隐藏参数开关,设置就在该目标的“调整计划”。历史CPI和历史收益只作参考,不静默改长期假设。

草稿所有默认值可见,不视为已确认。旧目标的月支出、target_date、π可以带入但需校核;旧withdrawal_rate不能自动解释成实际收益。手填预留的空值不能默认等于“无需”。

## 8 · 隐私与数据红线

确定性计算不调用大模型。不新增收集生日、疾病等隐私。对外只有用户主动打开来源视频,配置页面加 no-referrer;金额不进外链、埋点或第三方脚本。预览零业务请求,无需登录。

既有目标AI仅接收系统产出的统一结果、口径版本和来源摘要,遵守现有账户代号/提示词记录机制。新模型下取消AI推荐参数;引用过期结果须写生成时间和计划已变,不触发自动付费重算。QA全程stub,不走真实关账异步调用。

## 9 · 失败模式

1. 把房产和保额当本金,或贷款扣两次:用合成资金桥表核对每项,校验 `净资金-总需求=P-T`。
2. 生活预算和教育/医疗预留重叠:来源归属确认、未核对阻止正式达标、逐笔/总额混合覆盖用例。
3. 最新收入只有账户流水,投入仍锚旧PMC:纯账户收入/旧新混合/缺失/0/退款/双OPEN测试,每次显示相同收支期集合。
4. “480”硬编码、精确式却仍显示2.5%、只改详情没改目标条:反算恒等式+三币种不变性+全入口浏览器流程,r≤0用例。
