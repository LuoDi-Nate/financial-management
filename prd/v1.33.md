## 0 · 这一版在解决什么

**背景与现状**:

1. **没有删除,只有归档,而归档不是删除。** 归档按时间生效:归档之前的月份照常算它,从本期起不再计入 —— 它的余额在本期「消失」,看起来像本期亏了这么多。
   对建错的、测试用的、从来不该存在的账户,用户要的是「当它从来没有过」,归档给不了(issue #39:「归档后会计入该笔资产的损失」)。
2. **报表上的「封板」数字一个都没存,每次打开都现算**(`SealedPeriodService`「为什么不落库」)。删一个账户 = 所有包含它的历史月份(含已关账的)数字都会变,而页面上的「口径 v2」不会变。所以删除必须让人**事先看清、明确知晓**。
3. **最危险的是它和别的账户之间的划转。** 直接删掉划转,对方账户那一期就会凭空多出 / 少掉这笔钱,算成对方的赚亏 —— 对方的收益率、本期归因、家庭「钱赚」全被带歪。
4. 账户的数据散在约 20 张表里,其中一半没有外键;删漏一处就是「删了还在算」。

**服务谁**:所有成员(建错账户的人)。

**主推动力**:**能把建错的账户删掉,删得干净、删前看得清、删后还能恢复**。

**本版新引入的名词**(定稿后同步到 `AGENTS.md`):

- **回收站**:被删除的账户和它的全部数据的存放处;能恢复,也能彻底清除。
- **本金移出**:补录本金的反方向 —— 钱离开家庭账本(不算亏)。只在删除账户时由系统写在对方账户上,用户的「补录本金」表单不变。

### C · 删除做了什么

| # | 要求 |
|---|---|
| FR-1220 | 点「删除(先备份)」:先做一次**立即备份**(v1.32 FR-1170);备份失败就**不删**,面板里写失败原因,并指路「不备份,直接删除」。<br>点「**不备份,直接删除**」(维护者 2026-10-13 加:删掉的还在回收站里,备份不该是硬门槛):跳过备份直接删,回到账户簿的提示写「这次没有备份」,审计日志写「未备份」。确认语要求与「先备份」完全相同。 |
| FR-1221 | 备份成功后,账户和它的全部数据**移进回收站**(不是就地打标记):余额、待填、收支流水、持仓及其估值 / 份额记录、补录本金、关账时冻结的属性和分组、分组成员、保单、券商关联、目标绑定、再平衡计划条目、账单导入规则、固定收支。之后所有页面**当它从来没有过**,包括已关账月份的报表。 |
| FR-1222 | **它和别的账户之间的每一笔划转**:对方那一头改记成「本金进出」—— 对方收到的,记成对方的「补录本金」;对方转出的,记成对方的「本金移出」。对方账户的余额、收益率、损益**一分不变**;家庭层面这笔钱算外部资本进出(和开账基线同一类)。对方在那一期第一次出现的,自然并进它的开账基线。对方是贷款账户(比如用被删账户还过贷款)同样处理 —— 这是系统写入,不受补录本金表单「负债账户不用补录」的限制。改记了哪几笔,原样记进回收站(恢复时要还原)。 |
| FR-1223 | 记在它身上的收入 / 支出一起移走;成员按月填的总数(不挂账户)不动。 |
| FR-1224 | 别的贷款把它设成默认还款来源的,清空;AI 月度复盘(涉及的已关账月份)和 AI 调仓建议的存稿清掉,下次打开重新生成;「看 AI 收到了什么」的历史原文保留;资产透视立即刷新。 |
| FR-1225 | 整个删除要么全做完、要么一点不动(不会删一半)。 |
| FR-1226 | 删完回到账户簿,顶部提示「已删除「测试账户」· 可在回收站恢复 · 删除前的备份在 …」。审计日志一条:谁、何时、删了哪个账户、移走了什么、改记了哪几笔划转。 |

## 4 · 不做什么

- **不做就地打标记的软删**:「软删」按维护者的意思是「留回转余地」,实现上是**整块挪进回收站、能整块放回** —— 而不是在原表里打个删除标记、再让上百条查询各自去过滤(漏一处就是「删了还在算」,这个项目吃过两次这类亏)。
- **不做批量删除**、不做删除成员(另一件事)。
- **不做只删某几期的数据**(那是改余额 / 删流水的事,已有)。
- **不做「恢复到删除前那一刻以外的状态」**(不做版本历史);恢复就是原样放回。
- **不做回收站下载、不做定时自动清除**。
- 不撞「刻意不做」清单。

## 6 · 存量影响

| 维度 | 这一版的影响 |
|---|---|
| **schema** | 新增回收站(存被移走的数据和改记明细);补录本金增加「本金移出」(负的那一种,只由系统在删除时写)。不改已有表的含义。 |
| **口径** | 见下 |
| **UI** | 不删任何账户 = 什么都不变,只多了按钮和回收站入口 |

### 口径变更声明

- **新增「本金移出」**:和「补录本金」同一项、方向相反,进开账基线(外部资本进出),不算人赚也不算钱赚。只在删除账户、对方账户转出过钱给它时出现。
- **删除会改写历史**:所有包含被删账户的月份(含已关账)在下次打开时按新数据重算 —— 这是本功能的目的(维护者 D2),通过弹窗告知 + 报表留痕(FR-1240)让人知道。
- **零差异基线**(纪律:来自已发布 tag):用 v1.32.x 的 jar 和新 jar 跑同一份数据、**不删任何账户**时,仪表盘 / 报表 / 体检全部指标逐分相同。
- **恢复的基线**:删除再恢复之后,所有指标与删除前逐分相同(e2e 断言)。

### 核心功能影响排查

触发条件满足(新的写入通道,而且改写历史)。逐项影响已在 [`docs/research/account-delete-impact.md`](../docs/research/account-delete-impact.md) 第四、五、六节列全(仪表盘 27 项 · 报表 46 项 · 其它页面),每项标明「随删重算 / 取决于哪条裁定」;按裁定(D1 软删 · D3 B · 其余 A)之后的规律是:

- **被删账户自己的**数字从所有月份消失 —— 净资产、配置、集中度、趋势按「从来没有过」重算。
- **对方账户的**数字(收益率、损益、回撤、本期归因贡献)**一分不变** —— 因为划转改记成了本金进出。
- **家庭层面**:人赚只少了被删账户身上的收支;那几笔划转从「家里倒手」变成「外部资本进出」,计入开账基线。

## 9 · 失败模式(pre-mortem)

1. **漏移某张表 → 删了还在算**:账户的数据在约 20 张表里,将来再加一张挂账户的表,删除代码没跟上,就会留下孤儿数据继续进指标。
   **怎么发现**:护栏从数据库结构里**自动找出所有挂着账户的列**,逐个检查删除 / 恢复都处理了它(不靠人列清单)。
2. **划转改记方向弄反**:对方收到的记成了「本金移出」,对方收益率被带歪。
   **怎么发现**:e2e 删除前后对比对方账户的收益率、本期损益、本期归因贡献 —— 必须逐分相同。
3. **弹窗说的和实际做的不一致**:预演算出 3 笔划转,实际改记了 4 笔。
   **怎么发现**:预演和真删走同一段计算;e2e 断言弹窗里的每一行都在库里找得到对应的改记。
4. **恢复不完整**:恢复后少了几笔流水或划转没还原。
   **怎么发现**:e2e 删除 → 恢复 → 库里相关行与删除前逐行相同,各页面指标与删除前逐分相同。
5. **删一半**:中途出错,账户删了、划转没改记。
   **怎么发现**:整个删除在一个事务里;单测模拟中途失败,断言库里没有任何变化。

## 11 · 回滚与关闭

- 回滚 jar:老 jar 能照常读「本金移出」(就是负数的补录本金,事实层原样相加),对方账户的数字不受影响;**回收站老 jar 不认** —— 回滚后删掉的账户仍是删除状态,要恢复得先升回新版。不需要回滚前置 SQL;TDD 里复核老 jar 的补录本金页面遇到负数时的显示。
- 不可逆动作只有「彻底清除」,它本身就要打字确认。
