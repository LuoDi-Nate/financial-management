## 0 · 这一版在解决什么

**先认错**:v1.36 的调研没拿到 HIG 正文。苹果文档站是前端渲染,我当时直接抓页面只拿到空壳,就误以为「官方对网页只有两句话」,结果只做了「宽度变了不走样」。这次改用文档站背后的数据接口,读了 HIG 和开发文档全文,外加 6 个 Tech Talk 的完整字幕。

**苹果的核心设计(对 App)**:

1. **六种姿态**:
   - 合上(外屏)
   - 帐篷(倒 V 立在桌上,看外屏)
   - 打开 · 横(内屏横向)
   - 半折(像书,中间弯)
   - 打开 · 竖(内屏竖向)
   - 笔记本(内屏竖着半折,下半平放在桌上)
2. **操作放右侧竖排**:外屏比普通 iPhone 更宽更矮。原本在顶部、底部的栏都挪到**右侧一列**,从上到下依次是:灵动岛、状态栏、工具栏、标签栏。这样纵向空间都留给内容,右手拇指也够得着。**内屏横着时也一样**。只有「打开 · 竖」保留横向顶栏。
3. **折痕不放按钮**:半折时文字图片会自动避开中间,按钮、弹层、菜单都挪到两侧;网格优先用偶数列。
4. **不给每种姿态单做一套布局**:只按两种宽度(外屏窄、内屏宽)来排;折叠时不大幅改版。

**对照我们 v1.36 的现状**(详见调研 §6):

| 官方要求 | 现在 |
|---|---|
| 外屏、内屏横:操作在右侧竖排 | 顶栏在上,浮钮在右下 —— **没做** |
| 帐篷:外屏横向、不用手拿着看 | 外屏横向会触发「手机横屏冻结旋转」,**页面被转成侧着的** |
| 半折:弹框、按钮离开折痕 | 弹框居中,**正好压在折痕上** |
| 网格偶数列 | 内屏横向(约 890–951 宽)时,不少地方是 3 列,**中间那列压折痕** |
| 内屏竖:保留横向顶栏 | 符合 |
| 折叠时不丢内容、不大幅改版 | v1.36 已做到 |

**对网页的现实**:苹果没有专门写给网页的规范;Safari 拿不到折痕和姿态;UA 仍报 iPhone。但 **Safari 自己在外屏上就把工具栏放在右侧竖排**,苹果自家浏览器就是这么做的。我们的「主屏 App」在家里人看来就是一个 App,所以把 HIG 对 App 的规则平移过来。

**服务谁**:用 iPhone Duo 的家里人,首先是维护者本人(真机已购,发货中)。

**主推动力**:外屏和内屏横向时,操作挪到右侧竖排。其余几条(帐篷、折痕、偶数列)是同一次「按官方规范对齐」里顺手要修的错。

**本版新引入的名词**:**侧边操作栏**,指 iPhone Duo 形状屏幕上贴在页面右边的那一列按钮。定稿后写进 AGENTS.md 的领域概念。

## 3 · FR

### 3.0 · 三件事的决定(维护者 2026-10-22)

> 「1. 可以 听你的 2. 这个业界都怎么判断的?或者苹果建议怎么判断的? 3. 好」

1. **侧边操作栏只在「主屏 App」里出现(已定)**。在 Safari 里打开时,Safari 自己右侧已有一列工具栏;我们只把顶栏压薄一档。
2. **怎么判断「该出侧边栏」**(维护者问了业界和苹果的做法,答复如下,**已按推荐做法实施**):
   - **苹果的做法**:不给形状规则,由系统按设备决定栏放哪(App 里用系统栏就自动竖排,想知道的话读 `verticalBarEdge` 这个状态)。对布局只说两条:按「宽度级别」排(外屏窄、内屏宽),**不要按设备类型、屏幕尺寸、方向写分支**;对网页只说「别识别型号,用标准网页接口」。**网页没有「栏现在是不是竖排」的接口。**
   - **业界的做法**(谷歌 Material 3,安卓和网页通用):按**窗口宽度**分档 —— 窄(<600)用底部栏,中(600–839)和宽(≥840)用侧边栏;横屏手机这种「矮」窗口(高 <480)退回底部栏。网页上通常就是 CSS 媒体查询 / 容器查询;折痕用 Chrome 的折叠屏接口(Safari 没有)。
   - **两者在 Duo 上打架**:按 Material 的宽度分档,外屏(约 466 宽)该用底部栏、内屏竖(约 626 宽)该用侧边栏 —— 和苹果正好相反。苹果的判断其实是「**这块屏是不是矮宽型**」,不是宽度。
   - **推荐做法**:既然侧边栏只在主屏 App 里出现(第 1 条),主屏 App 的窗口 ≈ 整块屏幕,没有浏览器栏把它压矮,**直接用标准 CSS 媒体查询按窗口形状判断**就够了,不读设备、不读 UA、也不用 JS 读屏幕尺寸。把苹果的「哪种姿态竖排」翻成形状:
     - 主屏 App · 触屏 · **竖着且矮宽**(宽高比不小于约 0.58,且宽度不到约 560)→ 侧边栏(外屏竖握、分屏半边);
     - 主屏 App · 触屏 · **横着且不矮**(高度不小于约 460,宽度不到 1024)→ 侧边栏(外屏横握 / 帐篷、内屏横);
     - 其余(内屏竖、所有普通 iPhone 竖横、iPad、电脑)→ 不变。
     普通 iPhone 竖着宽高比约 0.46,SE 约 0.56,都不到 0.58;横着高度最多约 440,不到 460。**阈值等真机实测后定稿**(外屏主屏 App 里系统状态栏在侧边,具体占多宽要量)。
3. ~~做完先 Chrome 模拟验收,真机到货走完清单再发~~ → **改为直接发**(维护者 2026-10-22「发布吧,只要不影响原有的页面能力」)。发版前用 e2e 核对原有页面能力不受影响;真机到货后走真机清单,有问题出补丁版。

## 4 · 不做什么

- **笔记本姿态的专属布局**(可点元素挪到下半):网页拿不到折痕,分不清「笔记本」和「内屏竖向平放」;苹果也说这是可选的,而且不能把功能绑在姿态上。
- **分屏时侧边栏跟着去左边**:苹果让左边那个 App 的控制靠左。网页不知道自己在左半还是右半,统一放右边,记作已知限制。
- **折痕感知布局**:Safari 默认没开相关接口,等它默认开了再说。
- 不按设备型号判断(苹果明确反对);只看屏幕形状和触屏能力。

## 9 · 失败模式(pre-mortem)

| 可能怎么失败 | 防法 |
|---|---|
| 判据误伤普通手机(SE、Pro Max)或 iPad,它们也冒出侧边栏 | 只在主屏 App 里、按窗口形状判断(§3.0 第 2 条);阈值真机实测后定稿;e2e 拿普通 iPhone(多种型号尺寸)、iPad、电脑的主屏 App 和浏览器两种形态,与 v1.36.1 逐像素对照 |
| 主屏 App 里侧边栏被系统状态栏或摄像头挡住,或者和它们之间空太多 | 按左右各自的安全区让位;**真机确认前不发**(§3.0 第 3 条) |
| 尺寸猜错(官方只给像素,两组数对不上) | 判据只看形状和范围,不写死数字;两组尺寸都进 e2e |
| 侧边栏和现有的「手机横屏冻结旋转」打架 | 冻结旋转只留给普通手机横屏(高度 ≤ 普通手机最大短边);Duo 外屏横握走侧边栏。e2e 走一遍普通手机竖 → 横 → 竖,对照 v1.36.1 |
| 弹框挪到右半边以后,在 Safari 里被它右侧的工具栏盖住 | Safari 里不出侧边栏(§3.0 第 1 条),弹框按可视区域右半边定位;真机清单专门看一项 |
