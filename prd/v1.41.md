# v1.41 · 硅基流动 AI 接入

> 状态:**需求待评审**。本分支只有需求、静态交互预览及版本元数据,尚未开发、部署或调用硅基流动。
> 目标版本:app.version = 1.41.0。版本号为私有工作稿,不构成对外排期承诺。
> 来源:[issue #42](https://github.com/LuoDi-Nate/financial-management/issues/42),提交者 @SDaoer;维护者于2026-11-12明确要求开始处理,取代原暂缓决定。

## 0 · 这一版在解决什么

目前「管理 → AI 接入」只能保存百炼、DeepSeek官方和火山方舟的密钥。已经持有硅基流动密钥的自建用户,无法让现有分析或截图识别使用该平台。它托管的DeepSeek也不能借用「DeepSeek官方」选项,因为凭据、服务地址和账单属于不同平台。

服务谁:有硅基流动账户的自建用户,以及使用这些用户配置好的AI能力的非技术家庭成员。

主推动力:增加一个与既有平台地位相同的AI接入选择,服务「摸清资产、辅助决策」,不增加月度录入动作。

新名词:**完整型号**是从平台复制的原始Model ID,包含组织前缀、大小写以及可能的`Pro/`前缀;例如官方文档中的`deepseek-ai/DeepSeek-V4-Flash`。不把平台托管的同名模型当作另一平台的账户。

现状已查证:

- `LlmCatalog.java`只登记三个平台,型号格式当前不接受`/`,长度上限64;直接复制硅基流动型号会被拒绝。
- `admin/_llm-settings.html`有三张独立凭据卡、主备/视觉选择和写死的三家计数。
- `AiModelController.java`将密钥保存与型号保存分开;连接自检使用已保存密钥和选定型号。
- 文字分析、`VisionLlmClient.java`的图片输入、`LocalToolLoopRuntime.java`的工具对话都需要覆盖;百炼托管Agent是另一种运行方式。

## 1 · 调研

2026-11-12只核对官方公开文档,未持有、读取或申请硅基流动密钥,未发送任何生成或计费请求。

| 核对项 | 官方材料给出的能力 | 本版用户承诺 |
|---|---|---|
| 服务与认证 | 中国站提供Bearer认证的对话服务 | 单列「硅基流动」及自己的密钥,固定使用中国站 |
| 完整型号 | 官方示例包含组织前缀、大小写和多段路径 | 复制、保存、回读、调用保持一致,错误时不换成别的型号 |
| 图片与工具 | 对话接口列出图片输入及工具参数,具体支持取决于模型 | 视觉模型用于截图,支持工具的文字模型用于本地Agent,不宣称所有型号都兼容 |
| 模型目录 | 模型列表接口返回ID等基本信息,不能据此保证图片或工具能力 | 沿用少量参考型号加手填,不把全量远端目录冒充已验证的能力目录 |

初始参考型号以官方当前示例为依据:文字`deepseek-ai/DeepSeek-V4-Flash`,图片`moonshotai/Kimi-K2.7-Code`。预览只演示选择与完整ID,没有证明账户权限、余额或真实输出质量。技术设计及实施前需再次核对当时官方目录;若示例失效,换成核验后的参考项,不静默覆盖用户手填值。

**preview**:[AI接入交互预览](../preview/v1.41/ai-access.html)。这是现有页面中受影响部分的静态样例,所有账户状态为合成数据,所有保存和连接反馈均为模拟。

评审路径:

1. 在第四张卡粘贴任意示例串并点「保存密钥」;无需先填写其它模型。
2. 主选选「硅基流动」,采用或粘贴完整型号;备选保留另一平台,点「保存模型选择」后查看当前生效摘要。
3. 开启截图识别,独立选择图片模型;关闭后即使图片型号未填也能保存文字配置。
4. 用预览页独立的「预览场景」切换连接反馈,检查错误、超时和测试保护。它只是评审工具,不会进入正式产品。
5. 电脑与320/390手机核对完整型号、字段错误、下拉面板和同行按钮是否可读、可点、无遮挡。

关键文案:

- 未配置:「先保存硅基流动密钥,再选择这家平台的模型」。
- 保存空密钥:「没有输入新密钥,原密钥未改动」。
- 测试说明:「使用已保存密钥和生效型号测试,未选用时使用参考文字型号,可能产生少量用量」。替换原有「不烧额度」的误导说法。
- 型号错误:「请复制平台上的完整型号,保留组织前缀和大小写」。
- 保护拦截:「测试环境 · 未调用」,不得显示「连接成功」。

## 4 · 不做什么

- 不接图片生成、音视频、向量检索、训练、第三方模型交易或自动充值。
- 不引入任意地址的通用兼容平台编辑器、转发代理、国际站切换或批量同步远端模型目录。
- 不增加新Agent权限或替换百炼托管Agent;不自动创建外部智能体。
- 不修改财务计算、提示词中的既有业务规则或持仓颗粒度,不让模型参与数学。
- 不把保存设置等同为自动调用模型;不在回归或截图中测试真实模型。

上述需求未触及项目「刻意不做」清单。

## 6 · 存量影响

| 维度 | 影响 |
|---|---|
| schema | 使用既有运行配置保存新平台凭据与选择,不计划新增业务表或迁移 |
| 口径 | 本版不涉及口径变更;所有金额、比率、预测日期仍由系统计算 |
| UI | 原AI设置页增加一家平台及四卡排布,原主备、视觉与高级设置继续保留;不会替现存家庭选用新平台 |
| 原配置 | 百炼轮询、DeepSeek官方、方舟及旧配置兼容继续保留;新平台没有独立免费轮询策略 |
| 核心功能影响 | 不新增账期/快照/流水写入口,不改变取数锚点。AI仅使用原业务入口已准备的材料;截图经既有人工确认后才入账 |

能力覆盖矩阵用于验收,不是第二套业务逻辑:

| 场景 | 本版要求 | 边界 |
|---|---|---|
| 文字分析与后台月报 | 硅基流动可作主选或备选,名称和来源可追溯 | 不为验证而关账或触发真实后台模型 |
| 持仓截图 | 独立视觉型号、同平台密钥 | 仍只转写,人工确认后按既有入口写入 |
| 超级Agent分类/本地工具循环 | 沿用主备,覆盖正常回答和工具回合 | 型号须具备工具能力,不扩大读写权限 |
| 百炼托管Agent | 原运行方式和凭据保留 | 不把硅基流动密钥用于百炼 |

## 8 · 隐私与数据红线

密钥沿用既有私密配置保存,浏览器只提交新输入,回读只显示脱敏值和已配状态,不写进审计正文、日志、PRD、预览、截图或issue。设置页保持家庭归属和CSRF约束。

选择硅基流动后,该用户主动使用的AI能力会将既有prompt或上传图片发往该平台。文字分析中的成员/账户代号映射、超级Agent现有工具返回范围及图片自身可能包含的信息均沿用现行合同,不能因增加平台暗中扩大出站数据。图片不承诺自动遮盖原图中的信息;工具结果不额外附加凭据或原始表。

每次结果继续关联实际发送时记录的提示词,不在来源面板事后重拼。系统只给模型已经算好的财务数字,模型只解释。

本版不新增面向外部的入站接口;既有只读接入的认证失败语义不变。

## 9 · 失败模式

| 最可能的失败 | 用户后果 | 如何发现 |
|---|---|---|
| 型号前缀被校验拒绝、截断或转小写 | 看似保存,实际调用另一型号 | 前后端边界与保存回读测试,捕获请求中的完整ID |
| 同名DeepSeek被送到官方平台或拿错Key | 所有请求失败或记错平台健康 | 文字/视觉/本地工具请求目标和认证隔离测试 |
| 参考型号退役或不支持图片/工具 | 文字能用,其它入口失败 | 能力明确标注、错误分类与各入口桩测试;实施前重核官方目录 |
| 连接测试/后台路径绕过保护 | 回归产生真实账单 | 同epoch的服务端计数证明实际发送0,覆盖每个出口 |

## 11 · 回滚与关闭

用户可将主备及视觉切回原平台,不删历史报告或财务记录。不计划有新schema迁移。

回滚旧程序前需先切回旧版本认识的平台并保存;不能依赖旧程序理解新增的平台选择。完整技术回滚流程在技术设计阶段单列核对。已经发给第三方的prompt或图片无法通过回滚撤回,因此启用必须由用户保存选择,测试不得真实出站。

本issue保持开放至能力发布并公开说明升级方法;需求或beta待审阶段不关闭。
