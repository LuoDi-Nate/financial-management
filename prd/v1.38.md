## 0 · 这一版在解决什么

### A · 贷款

**背景与现状**:

同一件事(贷款每期还一笔、余额往下走),系统里现在有**两套**做法:

| | 旧:贷款趋势建议(v0.17 起) | 新:固定还款(v1.32 起) |
|---|---|---|
| 在哪 | 填报页「固定收支」那一行里的一条「建议」 | 同一行里的一条「待确认」 |
| 出现条件 | 这笔贷款**本期还没被人确认**,且前两期余额不一样 | 设过一次,以后每期到日子就出现 |
| 按钮 | 「接受」「保持上月」「设成固定还款」 | 「确认」「这期没有」 |
| 记了什么 | 只改**贷款余额**;从哪个账户还的不记(只起草一张不进口径的草稿) | 贷款余额 + 付款账户的「还贷」(本金)+ 利息(按利率算时) |
| 设一次管多久 | 每期都要点 | 一直有效 |

问题有三个:

1. **旧建议是一次性的**。这期点过「接受」就消失,下期开账才再出现。所以维护者 10-21 在 prod 上看到「两个房贷没提醒」:10-06 已经点过「接受」,本期不会再出现。系统从来没有一处地方告诉人「这两个贷款还没设固定还款」。
2. **两套并存,说不清该用哪个**。旧的只记一半(钱从哪个账户出去的不记),新的记全;但旧的每期都自己冒出来,新的要人主动去设。结果是越老的用户越停在旧的那一半上。
3. **同一笔还款在两处各管一半**,改一处容易忘另一处。v1.32 已经把旧建议的算法并进了新功能(「自动 · 按上两月差值」与「接受」算出来的贷款余额逐分相同),旧入口留着只剩历史原因。

**服务谁**:有贷款或信用卡的家庭(维护者家就有两个房贷),以及所有已经部署、每期在点「接受」的自建用户。

**主推动力**:**每个贷款都有一个明确的归宿**,要么设了固定还款,要么明说「不设,我每月自己填」。没有归宿的,一直提醒。

**A 新引入的名词**:**不设固定还款(每月自己填)** —— 贷款账户上的一个选择,表示这笔贷款不用固定还款、每期自己填余额,不再提醒。定稿后写进 AGENTS.md 领域概念(「固定收支」条目下)。

### B · 测试环境不调大模型

**背景与现状**:

- v1.37 做了第一道拦截:e2e、发版截图、入口巡检时,**浏览器**把 AI 请求拦下、返回占位。
- 但浏览器拦不到**服务端自己发起**的调用。最典型的是关账:关账后服务端会异步生成目标 AI 月报和偏离预警。
  - beta 上有 1 个目标,每关一次账约 1–2 次真实调用;
  - 会关账的有 qa-run(1 次)和 e2e flow 20 / 21 / 47 / 50 / 52。
- 为了省钱,v1.37 发版时这 5 条 flow 没跑。**回归覆盖因此变窄了**。
- beta 每天 00:35 宽限到期自动关账,也会走 AI 月报(约每月一次)。

**全站会调大模型的出口**(2026-10-23 逐个查过,共 10 类):

| # | 入口 | 谁触发 |
|---|---|---|
| 1 | 资产体检 · AI 综合诊断 / 单账户诊断 / 资产洞察 | 打开体检页 |
| 2 | 报表 · AI 调仓建议 | 点「生成」 |
| 3 | 月度复盘 · AI 解读 | 点「生成」 |
| 4 | 资产透视 · AI 解读、AI 打标 | 点按钮;持仓截图导入后也会自动打标 |
| 5 | 目标 · AI 参数建议、「立即生成月报」 | 点按钮 |
| 6 | 目标 · 关账后自动月报 + 偏离预警 | **关账**(手动关账、管理页强制关账、每天 00:35 宽限到期自动关账) |
| 7 | 持仓截图识别 | 上传截图后识别 |
| 8 | 支出导入 · AI 猜商户分类 | 点「AI 猜一下」 |
| 9 | 超级 Agent 提问;管理页「测试 Agent 连接」 | 提问 / 点按钮 |
| 10 | 管理页 · 大模型「测试连接」 | 点按钮 |

**服务谁**:维护者(beta 上跑回归不再花 API 费用);间接服务所有自建用户(他们也能在自己的测试机上打开)。

**主推动力**:让 beta 上的完整回归(含关账)**一次大模型都不调**,而且能**核对**确实是 0 次。

**B 新引入的名词**:**测试环境开关**(全称「测试环境:不调大模型」)—— 管理页 AI 接入里的一个开关,打开后这台机器不往外调大模型。定稿后写进 AGENTS.md 领域概念。

## 3 · FR

### A · 3.1 · 一直提醒

| # | 要求 |
|---|---|
| FR-1400 | **提醒对象**:全家所有**没归档、欠款不为 0** 的贷款账户(房贷、车贷、消费贷、信用卡、亲友借款都算),只要既没有启用中的固定还款,也没有选「不设固定还款」,就要提醒。 |
| FR-1401 | **常驻**:填报页「固定收支」那一行的摘要上一直带着「**还有 N 个贷款没设固定还款 · 设一下**」。<br>· 不管本期确认没确认、点没点过什么,每一期都在,直到这 N 个都有了归宿;<br>· 这句提示**不计入**导航「填报」角标和仪表盘的「待确认」数(它不是这期要做的事,是一次性的设置)。 |
| FR-1402 | **展开后逐个列出**:每个贷款一行,写名称、负责人、上月末欠款,两个按钮:<br>· 「**设成固定还款**」:打开表单,按这个账户预填好(见 FR-1406),确认保存就行;<br>· 「**不设,每月自己填**」:先确认一句「以后这笔贷款每期自己填余额,不再提醒。随时可以在 管理 › 固定收支 改回来。」,确认后记下,这个贷款不再提醒。<br>列表上面一句说明:原来的「接受 / 保持上月」换成了固定还款 —— 设一次,以后每期跟着别的固定收支一起确认,还会顺带记上从哪个账户还的。 |
| FR-1403 | **其他看得到的地方**:<br>· 「管理 › 固定收支」页加一组「**贷款**」,把每个贷款分成三类列出:已设固定还款 / 没设(带两个按钮)/ 选了每月自己填(带「改回来」);<br>· 贷款账户详情页那一行(v1.32 FR-1133)多一种状态:「每期还款 · 不设(每月自己填余额)· 改」。 |

### A · 3.2 · 旧建议下线

| # | 要求 |
|---|---|
| FR-1404 | **「接受」「保持上月」这条建议整个去掉**。填报页、贷款行、仪表盘都不再出现「按上两月差值,本月预计还到 X」的建议,也不再有「本期还款 · 待确认 ↑」那句指路(设了固定还款的贷款,指路照旧指向它那条待确认)。 |
| FR-1405 | **没设固定还款的贷款,和其他账户一样填**:贷款行照常显示「待填」,自己填本期余额。旧建议替人算的那个数,改由固定还款「自动 · 按上两月差值」来算(同一个算法,结果逐分相同)。 |

### A · 3.3 · 设成固定还款(从提醒里点进来)

| # | 要求 |
|---|---|
| FR-1406 | **表单按账户预填**,做到大多数人只点「保存」:<br>· 种类:信用卡(负债类型是信用卡,或这张卡上记过消费)预填「**信用卡账单 · 全额还上期**」;其他贷款预填「**贷款月供**」;<br>· 金额方式:贷款上填过年利率的,预填「月供固定,按年利率拆本金 / 利息」并提示填月供;没填年利率的,预填「**自动 · 按上两月差值**」(和以前点「接受」算出来的贷款余额一样);<br>· 从哪个账户还:贷款的「默认还款来源」;没设的就空着让人选;<br>· 几号:**1 号**(每期一开账就出现,和以前的建议出现时机一样),可改。 |
| FR-1407 | **表单上写清和以前的区别**:「确认时除了更新贷款余额,还会从『{付款账户}』记一笔还贷(本金)。如果你每月还另外手记还贷,或者从银行账单导入了这笔,以后就不用再记了。」 |
| FR-1408 | **本期已经填过余额的贷款,新设的固定还款从下一期开始**:这期不会再出一条待确认,免得同一期贷款余额改两次、还贷记两笔。表单上写明「这笔贷款本期余额已经填过,从 {下一期} 开始」。 |

### A · 3.4 · 已部署用户的升级

| # | 要求 |
|---|---|
| FR-1409 | **升级不改任何已有数据**:<br>· 以前点「接受」写进去的贷款余额、起草的那张还款草稿,原样保留;<br>· 已经设好的固定还款不受影响;<br>· 所有历史数字(净资产、负债、收支、报表、目标)逐分不变。 |
| FR-1410 | **升级后第一次打开填报页,就能看到要做什么**:所有没设固定还款的贷款都会出现在 FR-1401 的提醒里。没有自动替人设固定还款 —— 设了以后确认时会多记一笔「还贷」,有人每月另外手记或者导入银行账单,自动设会让这笔记两遍,所以必须由人点。 |
| FR-1411 | **升级当期接得上**:<br>· 升级时本期贷款还没填的,设好固定还款(1 号)就立刻是「待确认」,确认结果和以前点「接受」的贷款余额逐分相同;<br>· 已经填过的,按 FR-1408 从下一期开始。<br>不会出现「这期既没有建议、也没有待确认」的空档,也不会同一期记两次。 |
| FR-1412 | **升级说明写进 Release 页的「升级注意」和使用手册**,一段话说清:「贷款趋势建议(接受 / 保持上月)换成了固定还款:升级后到填报页按提示给每个贷款设一下(约 1 分钟),或者选每月自己填。」 |
| FR-1413 | **跳版本升级也成立**:从 v1.32 以前直接升到这一版的(还没见过固定收支),看到的是同一套提醒,不需要先升到中间版本。 |

## 4 · 不做什么

**A**

- **不自动替人设固定还款**(哪怕是一直在点「接受」的贷款):设了以后确认时会多记一笔「还贷」,会和手记、导入的那笔重复。理由见 FR-1410。
- **不保留旧建议当「过渡期」**:维护者定「彻底代替」。两套并存正是这版要解决的问题;留着就又回到「越老的用户越停在旧的那一半」。
- **不改固定还款本身的算法和确认结果**:v1.32 的五种自动计算、确认写进去的东西,一样不变。
- **提醒只看贷款账户**:系统里所有负债(房贷、信用卡等)都是贷款账户;资产类账户不提醒。
- **不清理历史草稿**:以前「接受」时起草的那张还款草稿本来就不进任何口径,留着不碍事;删历史数据的风险比留着大。

**B**

- **不造假的 AI 内容**:不返回假文字、假 JSON。拦下就是「没调用」,按「没配大模型」的路径走 —— 假内容会被当成真结果解析,最危险的例子就是持仓截图识别把空结果当成「全部卖出」。
- **不拦超级 Agent 的配置类操作**:「更新百炼上的 Agent 模板」、模板是否过期的检查、MCP 口令这些不调模型、不花钱,照常可用。「测试 Agent 连接」会真跑一次模型,要拦。
- **不按入口单独开关**:只有一个总开关。按入口开关会让「到底哪些在花钱」重新变得说不清。
- **不顺手修和本版无关的 AI 老问题**:比如商户分类和本地 Agent 只认主选平台、不走备选。查出口时发现的,记进待办,另开。
- **不碰 prod**:默认关,升级不改变 prod 任何行为。

**撞「刻意不做」清单**:A、B 都**不撞**。

## 6 · 存量影响

| 维度 | 这一版的影响 |
|---|---|
| **schema** | A:贷款账户上加一个「不设固定还款」的标记(只加不改,旧行为空 = 还没决定 = 提醒)。旧版 jar 读不到这一列,回滚不受影响。<br>B:开关存在已有的运行配置表里(不加列);拦截计数要存库、重启不清零(新表或复用已有表,技术设计里定),只加不改。 |
| **口径** | **本版不涉及口径变更**。A:固定还款的算法、确认写进去的东西都是 v1.32 已有的;旧「接受」写进去的历史数据不动。B:不碰任何数字。 |
| **UI** | A **会变**(维护者定「彻底代替」):有贷款的家庭,填报页旧建议消失、换成提醒;管理页和贷款账户页多一种状态。没有贷款的家庭看不到变化。<br>B:开关默认关,关着时与上一版逐字一致;只在「管理 › AI 接入」多一张卡片。 |

### 核心功能影响排查

- **少了一个写入通道**:「接受」(写贷款余额)、「保持上月」(按上月末提交余额)两个入口下线。
- **没有新的写入通道**:设了固定还款以后,写入走的是 v1.32 已有的「固定收支确认」(`EntryService` 既有方法,L24)。「不设,每月自己填」只是一个**设置**,不写任何余额、流水、划转。
- **账期、快照、取数锚点都不动**。三个核心页面(填报 / 仪表盘 / 报表)上的数字,在用户做同样操作时与上一版相同:
  - 「自动 · 按上两月差值」确认写进的贷款余额 = 以前「接受」写进的(同一个 `predictLoanBalance`,v1.32 FR-1108 已有 e2e 守着);
  - 多出来的只有付款账户那笔「还贷」(本金),这是 v1.32 固定还款本来就有的行为。表单按 FR-1407 写明。
- **确定不受影响的**:
  - 已设固定还款的贷款(行为一字不变);
  - 资产类账户(从没出过这条建议);
  - 关账、宽限、自动关账(建议从来不参与关账);
  - 超级 Agent / 只读接口(查过,没有任何工具引用这条建议)。
- **B 不加写入通道**:开关打开时,关账后的 AI 月报 / 偏离预警**不生成**(和没配大模型时一样),其余关账动作照旧;已经生成的月报、复盘、调仓建议照常能看。

## 7 · 开关与默认值

| 开关 | 默认值 | 关掉时的行为 |
|---|---|---|
| B · 测试环境:不调大模型 | **关** | 与上一版逐字一致(prod 一直关着) |

**A 不设开关**。按模板,「改变既有视图的能力默认要关」;这一版是**例外**,理由如下:

- 维护者明确要求「彻底代替」;
- 留开关等于把「两套并存」变成配置项,正是这一版要消灭的东西;
- 对现有用户的影响靠迁移设计兜住:不动数据(FR-1409)、升级后有提醒(FR-1410)、当期接得上(FR-1411)、写进升级说明(FR-1412)。

## 9 · 失败模式(pre-mortem)

| 可能怎么坏 | 怎么发现 |
|---|---|
| **升级当期同一笔记两次**:本期已经点过「接受」,又设了固定还款并确认 → 贷款余额不会被覆盖(v1.32 规则),但付款账户多记一笔「还贷」 | FR-1408:本期已填的从下一期开始。e2e:先在本期填好贷款余额,再设固定还款,断言本期**没有**这条待确认,下一期才有 |
| **升级当期出空档**:旧建议没了、新的又没出现,这期贷款余额没人提醒 | e2e:本期贷款未填 → 从提醒设好固定还款 → 立刻是待确认,确认后贷款余额 = 用已发布 v1.37.0 点「接受」的结果(逐分相同) |
| **提醒漏人或多人**:归档的、欠款为 0 的还在提醒;或者设了固定还款但被停用的不提醒 | 单测覆盖四种状态(已设 / 停用 / 不设 / 未决定)× 归档 / 结清;e2e 断言提醒数 = 库里按判据数出来的数 |
| **B · 漏了一个出口**:以后新加的 AI 功能自己写了 HTTP 调用,没经过开关,开着时照样花钱 | 「发出去 M 次」不是 0 → 脚本判失败;qa-run 护栏扫源码:凡是往大模型平台发请求的地方,都必须先过开关 |
| **B · 拦下被当成空结果**:某个入口把「没调用」当成「AI 说没有」继续往下走,改了数据 | e2e:开关开着时上传持仓截图,断言页面显示「测试环境 · 未调用」**且库里持仓一行没变** |
| **B · 拦下被算成故障**:健康读数变红、熔断累计,关掉开关后还要等熔断恢复才能用 | 单测 + e2e:开着时连续触发多次,健康读数不出现「失败」;关掉后第一次调用就能发出去 |
| **B · 忘了关 / 误开在 prod** | 全站提示条(FR-1391)+ 打开时确认(FR-1390)。prod 本身不跑这些脚本,也不会有人去点 |
| **旧入口没删干净**:某个模板、接口、测试还留着「接受」那条路,被人从旧书签点进来写了余额 | qa-run 护栏:旧接口路径返回 404、模板里不再有旧按钮;源码里不再有旧的写入方法调用 |

## 11 · 回滚与关闭

- A 不设开关(见 §7)。发现不对,回滚 jar 即可:`deploy/rollback.sh`。
- B 关掉开关即恢复真实调用;计数表只加不改,回滚不受影响。
- 迁移只加一列,旧 jar 读不到它,不影响回滚;回滚后旧建议恢复,新加的「不设」标记被忽略。
- 没有不可逆动作:不删数据、不对外发送。
