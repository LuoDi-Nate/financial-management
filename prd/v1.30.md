## 0 · 这一版在解决什么

**背景与现状**:

- A 股、港股、美股、场内 ETF / LOF、加密货币、贵金属,今天都能「填代码 + 数量」自动估值;**场外基金不行** ——
  在支付宝、银行、天天基金买的开放式基金,只能「手填市值」每月改一次,或者用 v1.4 的截图导入。
- 讽刺的是,v1.5 的基金穿透**已经能把这些手填基金解析出基金代码**(beta 演示数据里「支付宝-余额宝」账户 13 条持仓,12 条是手填市值,其中 6 条已经带着穿透解析出的基金代码)——
  代码有了,只差没拿净值去算市值。
- issue #25 的提问者用过的 Capivot 能做到:选中一只基金(界面显示「广发多因子混合 (002943) - 基金」),只填份额,净值自动带出,持有总额自动算,
  之后一键刷新 [竞品报告 §4 F2]。

**服务谁**:家里在支付宝 / 银行 / 基金 App 买开放式基金的成员(多半是非技术家人)—— 这正是「每月 10 分钟」里最费时的那几行。

**主推动力**:**场外基金录一次份额,以后净值自动更新**。其余(把已有手填基金转过来、货币基金的单独处理)都是为了让这件事在存量数据上也成立。

**本版新引入的名词**:

- **场外基金持仓**:按「份额 × 单位净值」自动估值的持仓,净值来自基金公司每天公布的单位净值。
- **净值日期**:这一份净值是哪天的。场外基金净值当晚才公布,QDII 还要再晚一个交易日,所以页面上**总是写日期**。

## 1 · 调研

完整报告:[`docs/research/capivot/README.md`](../docs/research/capivot/README.md)(竞品 Capivot 的模型、用户故事、全部动线截图、与本产品的对比,所有论据带来源)。
与本 PRD 直接相关的结论:

1. **Capivot 怎么做**:「标准资产库」—— 选中一只证券,只填份额,价格 / 币种 / 总额自动带出,保存前就能看见 [报告 §4 F2]。它的库覆盖「A 股 B 股,沪深市债券,场内场外基金,港股,美股,数字货币」[报告 S1]。
2. **它被抱怨什么**(App Store 原话,带日期):
   - 「有一些基金是一直定投的,每次都要手动添加更新金额」(2026-09-02);
   - 「现在理财的 app 很少直接显示份额」(2021-05-31);
   - 「数据经常时间无法更新和添加」(2026-09-30,2★)、「汇率数据失真,也不支持切换数据源」(2024-12-12)[报告 §5.2]。
   → 照搬「按份额估值」时,**份额不好找、份额会变、数据会旧**这三件事必须一起解决。
3. **数据可得性(2026-10-05 实测)**[报告 §6.5 · `evidence/fund-data-check.md`]:
   - 天天基金代码表 28,010 只,带名称和类型;每只基金有每日单位净值序列;
   - **QDII 晚 1 个交易日**(实测 270042 净值日期 09-29,同日混合基金 002943 是 09-30);
   - **货币基金没有净值序列**,只有万份收益 / 七日年化 —— 净值恒为 1;
   - 这两个文件 v1.5 起就在用(`EastMoneyFundClient.java`),**不新增数据源**。
4. **银行理财**:2026-09-01 上线的「理财行业统一信息披露平台」能按登记编码查净值,但查询接口请求体加密,没有可用的公开接口 [报告 §6.5]。

## 2 · 用户故事

> 「考虑到国内用户的投资习惯,看看是否可以借鉴 capivot 的模式,同时支持覆盖国内大家更常见投资的各类型基金(似乎没找到查询入口)、理财产品等常见金融产品,
> **通过编号可以一键导入投资标的,后续可一键刷新所有资产的价格**,汇率自动换算(外币转人民币)。」—— @chca2(issue #25)

原话里的线索:

- **「通过编号」**:他要的是「输代码就认出来」,不是再截一次图。
- **「一键刷新所有资产的价格」**:我们已有「刷新持仓估值」按钮,只要基金也被它带上。
- **「汇率自动换算」**:已有(issue #25 首条回复已说明),本版不动。
- **「理财产品」**:银行理财做不了自动净值(§1 第 4 条),本版明确不做,继续走手填 / 截图导入。

Capivot 用户的另外两条原话(§1 第 2 条)直接对应 FR-961(按市值反推份额)和 FR-967(份额改起来顺手)。

## 3 · FR

| # | 要求 |
|---|---|
| FR-959 | 在能挂持仓的账户(证券 / 理财 / 现金类)里新增「**添加基金 · 按净值自动估值**」:输入 6 位基金代码**或**基金名称,下拉列出匹配的基金(名称 · 代码 · 类型),选中后显示**最新单位净值与净值日期** |
| FR-960 | 选中基金后只需填「**持有份额**」;保存前实时显示「份额 × 单位净值 = 市值」 |
| FR-961 | 不知道份额的,可以改填「**当前市值**」:系统按最新净值反推份额,并标明「按 X 月 X 日净值估算的份额」;之后照常按净值更新 |
| FR-962 | 基金持仓跟着已有的「**刷新持仓估值**」按钮和「行情自动拉取」定时任务一起更新净值;持仓页每行显示**净值日期**,QDII 晚一天的净值照实写日期 |
| FR-963 | 拉不到新净值时(基金终止、代码失效、数据源出错),**不静默沿用旧值**:持仓行标「净值停在 X 月 X 日」,刷新结果里点名是哪几只 |
| FR-964 | **货币基金**(类型为货币型的)不拉净值:按「金额」记(份额 = 金额,净值固定 1),页面写明「货币基金的收益每天变成份额,月底核对一次金额」 |
| FR-965 | 已有的「手填市值」基金持仓,只要已经识别出基金代码(截图导入 / 穿透得到的),持仓行上出现「**改为按净值自动估值**」:确认框里写清「按 X 月 X 日净值 Y,把当前市值 Z 折成 N 份」,确认后转成场外基金持仓;**可以改回手填** |
| FR-966 | 场外基金持仓**按代码直接穿透**(不再靠名称去猜代码),并照常进入资产透视、体检与 AI 分析 |
| FR-967 | 份额变了(定投、赎回、分红再投)时,持仓页这一行能**直接改份额**,一处改完,市值立即按最新净值重算 |

**关键文案**:

| 位置 | 文案 |
|---|---|
| 入口按钮 | `+ 添加基金 · 按净值自动估值` |
| 搜索框占位 | `输入基金代码或名称,例如 002943 / 广发多因子` |
| 选中后 | `广发多因子混合 · 002943 · 混合型-灵活 · 最新净值 4.7800(9 月 30 日)` |

## 4 · 不做什么

- **银行理财自动净值**:没有可用的公开接口(§1 第 4 条)。继续手填 / 截图导入;信披平台若日后开放机读接口再评估。
- **定投 / 分红自动加份额**:撞「刻意不做」清单的**逐笔流水账**与**定投提醒**。替代做法:份额变了在持仓行直接改(FR-967),月度核对时顺手完成。
- **盘中实时估值**(天天基金的「估算净值」):估算值不是基金公司公布的净值,当天收盘后还会变 —— 月度账本只认公布的单位净值。
- **基金交易记录 / 持有收益 / 成本**:不做。收益看账户级(人赚 / 钱赚、XIRR),与现有口径一致。
- **沪深债券、B 股**:Capivot 覆盖、我们没验证(竞品报告 §6.2)。另开 issue 查,不混进本版。
- **货币基金按万份收益自动累计**:见 §13 ①。

| FR | 对录入负担的影响 | 判定 |

| FR-967 | 只在份额变了的月份改一个数;今天是每个月都要改市值 | 通过(负担下降) |

## 6 · 存量影响

| 维度 | 影响 |
|---|---|
| **schema** | 持仓要能表达「场外基金」这一类(具体加市场类别还是加列,TDD 定);**只加不改**,旧行不动 |
| **口径** | 不改任何指标定义。被转成自动估值的基金,账户余额从「月底手填」变成「按净值每天更新」—— 这是用户自己点了转换才发生的 |
| **UI** | 没有基金持仓的家庭:**一个像素都不变**(除了添加入口多一个按钮)。已有手填基金:多一个「改为按净值自动估值」,不点就不变 |

### 口径变更声明

本版不涉及口径变更。零差异基线:没有转换任何基金的家庭,对照已发布的 v1.29.0 逐页零差异。

### 核心功能影响排查

- **写入通道**:没有新增通道 —— 基金净值走已有的「估值刷新」(按钮 + 定时任务),归属判据与股票持仓相同(余额 = 永远最新,写进当期)。
  「改为按净值自动估值」是用户主动操作,同样写当期。
- **受影响的**:转换了的账户,当期存量类指标(账户余额 / 净资产 / 资产分布)随净值变;收益类从转换那期起由净值变化驱动。
- **确定不受影响的**:已关账月份(封板);没有基金持仓的账户;股票 / 加密 / 贵金属持仓的拉价;收支。
- 完整矩阵(写操作 × 三页面指标)在 TDD 里列。

## 9 · 失败模式(pre-mortem)

1. **代码填错还不知道**:场外基金代码是 6 位纯数字,和 A 股代码长得一样 → 必须**先显示名称和净值再让填份额**(FR-959);名称不对用户一眼能看出来。
2. **净值静默变旧**:数据源改格式、基金终止,页面却一直显示旧市值(Capivot 被骂最多的就是这个)→ FR-963 标日期、点名;e2e 造一只拉不到净值的基金验证。
3. **货币基金被当成按净值估值**:拿不到净值序列 → 市值算成 0 或报错 → 按基金类型分流(FR-964),单测覆盖货币型。
4. **转换时用了旧净值**:QDII 晚一天、节假日没有新净值 → 确认框写明用的是哪天的净值(FR-965)。

## 11 · 回滚与关闭

- 回滚 jar:原则是**余额不丢** —— 老代码读到场外基金持仓时,账户余额停在最后一次估值写回的数上,不会被清零;确切行为在 TDD 里写清并用单测钉住。
- 迁移只加不改,回滚 jar 后新列 / 新取值闲置。
- 不可逆动作:无(只读外部数据)。

## 13 · 待维护者裁决

| # | 问题 | 倾向 | 理由 |
|---|---|---|---|
| ① | 货币基金要不要按每天的万份收益自动累计金额? | **不做**,月底核对一次 | 中途有申购赎回就会算错,而且是静默错;月底核对本来就在 10 分钟里 |
| ② | 「按当前市值反推份额」是默认,还是「填份额」是默认? | **默认填份额**,旁边一个「不知道份额?按市值填」 | 份额才是不会随净值变的那个数;市值反推只是第一次的便利 |
| ③ | 入口放哪? | **持仓页单独一个按钮「添加基金」**,不塞进「添加持仓 · 自动估值」的市场单选里 | 股票那页要先选市场再填代码;基金是「搜名字」的动线,硬塞进去两边都别扭(见 preview ①) |
| ④ | 定时拉净值的时点 | **每天晚上一次 + 次日上午补一次**(具体时点 TDD 按实测定) | 实测 QDII 净值比国内基金晚一个交易日(§1 第 3 条);国内基金当晚何时公布,TDD 前再连续几天实测,不凭印象定 |
| ⑤ | 沪深债券 / B 股要不要一起查? | **另开 issue** | 与「基金」不是一件事;先验证现有 A 股通道能不能拉到 |
