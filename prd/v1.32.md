## 0 · 这一版在解决什么

**背景与现状**:

1. **每期金额几乎一样的那几笔,每期都要重新敲一遍。** 工资、物业、月保、房贷、会员费……在填报页里和「这个月在超市花了多少」走的是同一条路:选类目、选账户、填金额。
   「最近常用」只记住了类目,金额和账户每次重填。
2. **漏了没人知道。** 现有提醒(截止前 N 天的短信、站内 banner、导航「填报 ·N」徽标)只看「**账户**填没填」,不看「**该有的那几笔**有没有记」。
   物业费忘了记,账户余额照样能校准,只是那笔钱会变成「说不清的差额」。
3. **系统里其实已经有一条同类的能力,但只有贷款有、只管一半**:填报页贷款行的提示条
   「按上两月趋势,本月预计还到 X(较上月 −Y)[接受] [保持上月]」(`entry/_row.html:121`、`EntryService.acceptLoanPrediction`、`PeriodOpener.predictLoanBalance`)。
   - 它只更新**贷款余额**;这期从哪个账户还、还了多少(含利息)要另外记一笔「还贷」。
   - 接受时顺手起草的那笔「还款划转」是草稿,不进任何口径 —— 等于没有。
   - 它是 v0.17.x 从「开账时静默外推写进去」改成「列出来让人点」的,原因是用户不知道系统替他改了数(这条教训决定了本版的交互形式,见 FR-1111 与 §4)。
4. **保单登记里有「每期保费 · 年缴 / 月缴 · 生效日 · 已缴期数」**(V44 `account_insurance_policy`),但只是展示,没有任何地方拿它提醒或记账。
5. **账单导入**:支付宝 / 微信可以导(逐笔模式下填报页的「批量导入」);信用卡 / 银行账单不导 —— 各家格式不一样、手上没有真实样本(导入页已写明)。
   导完之后,银行卡那边通常只剩房贷、代扣、线下刷卡这几笔要手记 —— **恰好就是固定收支最能接住的那几笔**。

**服务谁**:每月填报的家人(非技术为主)。

**主推动力**:**每期固定的那几笔,设一次,以后到日子列出来,一键确认**。贷款趋势提示、保单保费都是「每期会发生、金额可预期」的同一类事,统一收进来。

**本版新引入的名词**(定稿后同步到 `AGENTS.md` 领域概念节):

- **固定收支**:每期(或每年固定几个月)都会发生、金额基本固定的一笔。分四种:**固定收入 / 固定支出 / 还款 / 交保费**。
- **本期待确认**:本期该有、还没确认的固定收支;以及没设固定还款的贷款的**趋势建议**(原贷款行提示条)。

## 2 · 用户故事

issue #38 原文(@Jsonya,2026-10-10):

> 比如每月固定的月保、物业等费用,每年的保险费用,都是固定的支出,如果每次手动填有点麻烦,或许可以设置成固定支出、固定周期这样?如果有账单的自动导入那更好了,通常就是微信,信用卡,支付宝

维护者 2026-10-12:

> issue38 要做,但是你要考虑下我们原来已经有的能力来统一进行整合和规划:我们曾经有个功能 如果是负债类型的账户 每个月初开账的时候 会自动根据前两个月的差值 进行一个试算和推荐,这个其实也是一个类似固定支出(其实就不只是支出了 收入 负债减少)你来统一进行下思考和规划,明确用途 交互形式 配置入口和提醒时机

原话里的设计线索:「**其实就不只是支出了,收入、负债减少**」—— 所以本版不叫「固定支出」而叫「固定收支」,覆盖收入、支出、还款(负债减少)、交保费四种;
「**试算和推荐**」—— 贷款那条是「推荐 + 人确认」,本版所有固定收支都用这个形式。

## 3 · FR

**preview**:[`preview/v1.32/fixed-flows.html`](../preview/v1.32/fixed-flows.html)。

### A · 固定收支是什么

| # | 要求 |
|---|---|
| FR-1100 | 一条固定收支有:**名称**(物业费、月保、工资……)、**种类**(收入 / 支出 / 还款 / 交保费)、**金额**、**账户**(钱从哪出或到哪)、**类目**、**周期**(每月 / 每年的某几个月)、**几号**、**负责人**(默认是账户主理人),以及可选的「**到哪期为止**」(贷款、分期保费到期后自动停)。 |
| FR-1101 | **固定收入**:现金收入(工资、奖金、房租……),确认 = 在入账账户记一笔收入,和手动「记一笔收入」完全一样。股票收入不在此列(股数每次不同)。 |
| FR-1102 | **固定支出**:确认 = 在付款账户记一笔支出,和逐笔录入完全一样;消费分类和「不是消费」的三项(还贷 / 利息 / 转给亲属)都能选,**负债账户上不能记「还贷」**的规则照旧(v1.19.3)。 |
| FR-1103 | **还款**:选一个贷款账户 + 从哪个账户还(默认取贷款的「默认还款来源」)+ 每期实际扣款额(含利息)。确认 = **付款账户记一笔「还贷」** + **贷款余额按上两月趋势更新**(和今天点「接受」写进去的一样)。两样都是今天已有的写法,本版只是把它们合成一次点击。 |
| FR-1104 | **交保费**(储蓄型保险):选一个保险账户 + 从哪个账户付。确认 = 一笔划转(付款账户 → 保险账户),保费进保单的现金价值那边,不算支出。消费型保险(没有保险账户的)用「固定支出」记。 |
| FR-1105 | 保险账户的保单登记里填了「每期保费 + 缴费频率 + 生效日」的,账户页一键「设成固定交保费」:金额、年缴的月份(= 生效月)、总期数 / 已缴期数都带出来,剩余期数缴完自动停。 |

### B · 本期待确认(交互形式)

| # | 要求 |
|---|---|
| FR-1110 | 填报页「第一步 · 本月收支」最上面一张卡「**本期固定收支**」:列出这一期该有的每一笔 —— 名称、种类、金额、账户、负责人、几号。**到了日子的标「待确认」**,没到的标「X 号」(也能提前确认)。没有任何固定收支、也没有贷款建议时,这张卡不出现。 |
| FR-1111 | 每笔两个按钮:**「确认」**(按卡上金额记;金额可以当场改)/ **「这期没有」**(这期不记)。卡片头一个 **「全部确认」**,只确认已到日子的。**系统从不自己记**,不确认就不会有这笔。 |
| FR-1112 | 当场改了金额 → 小字问「以后都按 ¥新金额?」(默认不改)。比上一次确认的金额多 / 少时,行里标出差额(物业费涨了看得见)。 |
| FR-1113 | 确认后这一行显示 ✓ 和「记成了什么」(哪个账户的哪一笔),能「**撤销**」(删掉那一笔、余额跟着回去,这一行回到待确认)。 |
| FR-1114 | 确认写进去的,**和手动记一笔完全一样**:同样的余额联动、同样进报表和各项指标;流水上标来源「固定收支」,能看出是哪一条带出来的。 |
| FR-1115 | 账期选择器选的是哪一期,卡片就是哪一期的(两期同时开着时各管各的)。关账时没确认的**不记、也不挪到下一期**;下一期卡片顶部提一句「上期有 N 笔没确认」,点开能看是哪几笔。 |

### C · 贷款还款提示并进来

| # | 要求 |
|---|---|
| FR-1120 | **没设固定还款的贷款**:原来贷款行里的「按上两月趋势,本月预计还到 X(较上月 −Y)[接受] [保持上月]」挪进「本期固定收支」卡,作为一行「**建议 · 按上两月趋势**」,按钮不变,多一个「**设成固定还款**」。 |
| FR-1121 | **设了固定还款的贷款**:不再出趋势建议,由那条还款代替(一个贷款只出一行,不会两条都出)。 |
| FR-1122 | 贷款行里原来那条提示条去掉,换成一行小字「本期还款 · 待确认 ↑」,点了跳到卡片上那一行。接受建议写进去的东西和今天一样。 |

### D · 配置入口

| # | 要求 |
|---|---|
| FR-1130 | **在记账的时候顺手设**:记一笔收入 / 支出时,表单上多一个勾「**每月都有,设成固定**」;勾上提交 = 记这一笔 + 用这一笔的名称、金额、账户、类目建一条固定收支(几号 = 今天)。 |
| FR-1131 | **集中管理页「固定收支」**:列出全家所有固定收支(按种类分组),可新增 / 修改 / 停用;停用不影响已经记过的。入口:填报页卡片右上「管理」、管理总览「家庭基础」组、管理侧栏(v1.31 的清单里加一项)。 |
| FR-1132 | **账户页**:贷款账户的详情 / 编辑页显示「每期还款 ¥X · 从 Y 还 · 改」,没有就给「设固定还款」;保险账户同理(FR-1105)。 |
| FR-1133 | 账户归档 → 用到它的固定收支自动停用,归档时提示一句「它的 N 条固定收支一起停了」。 |

### E · 提醒时机

| # | 要求 |
|---|---|
| FR-1140 | **到了日子当天起**,这一笔变成「待确认」,并进到三个现有的地方:导航「填报」徽标的数字、「我的待办」(负责人那里)、仪表盘「本期还有 N 个账户未填」那条后面加「· M 笔固定收支待确认」。 |
| FR-1141 | **截止前的短信不改内容**(阿里云审过的模板只有 4 个变量,改字要重新报备);站内 banner 加一句「还有 M 笔固定收支没确认」。 |
| FR-1142 | 不另加提醒渠道,不按笔推送。 |

### F · 和账单导入

| # | 要求 |
|---|---|
| FR-1150 | **先确认、后导入**:导入支付宝 / 微信账单时,和本期已确认的固定支出**同账户、同金额**的那一行,默认不勾、标「已作为固定支出记过」(还能手动勾回来)。 |
| FR-1151 | **先导入、后确认**:卡片上这一笔显示「导入的账单里有一笔 ¥X 可能就是它」,点「就是它」= 标为已确认、不再另记一笔。 |

### G · 支出录入方式是「每人一个总数」时

| # | 要求 |
|---|---|
| FR-1160 | 固定支出、以及还款里「还贷」那部分**不单独入账**(总数里本来就含它们,单独记会算两遍);卡片上这几行只做清单,总数输入框旁写「本期固定支出 ¥Z(物业 ¥A · 月保 ¥B · 房贷 ¥C)—— 填总数时别漏了」。固定收入、交保费、还款里「贷款余额」那部分照常确认。 |

### 关键文案

| 位置 | 文案 |
|---|---|
| 卡片标题 | `本期固定收支` + `{N} 笔待确认`(全部确认完:`本期都确认了`) |
| 行状态 | `待确认` / `{D} 号` / `✓ 已记 · {账户} {种类} ¥{金额}` / `这期没有` |
| 贷款建议行 | `建议 · 按上两月趋势,本月预计还到 {X}(较上月 {−Y})` |

| 总额模式 | `本期固定支出 ¥{Z}(…)—— 填总数时别漏了` |

## 4 · 不做什么

- **不做「到日子系统自己记」**。金额会变(物业涨价、工资调整)、同一笔可能还会从账单导入,静默写进去就是静默算错;贷款预填 v0.17.x 正是因为「用户不知道系统替他改了数」才改成让人点确认的。一键确认已经够省事。
- **不做账户间的固定划转**(比如每月定投到基金账户):撞「刻意不做」清单的「**定投提醒**」。交保费是唯一例外 —— 它是合同规定必须交的钱,不是投资决定。
- **不做金额每期都不一样的「估一个」**(水电燃气)。固定收支只管金额基本固定的;会变的照常手记。
- **不做从流水里自动认出「每月都在扣」的订阅**(v1.24 推迟的那条):那是事后识别,这是事先设好,两件事;那条的前置(流水加商户字段)还没做。
- **不做预算**(「刻意不做」清单的预算包络)。
- **不做信用卡 / 银行账单导入**:还是没有真实样本;固定收支正好接住导完支付宝 / 微信之后剩下的那几笔银行侧扣款。
- **不改任何口径**:确认写进去的和手动记的一模一样(FR-1114)。

## 6 · 存量影响

| 维度 | 这一版的影响 |
|---|---|
| **schema** | 新增两张表:固定收支本身、每期的确认记录(确认 / 这期没有 / 关联到哪一笔流水或划转)。**不改任何旧表、旧列**。 |
| **口径** | 本版不涉及口径变更:确认写进去的和手动记的一样,经同样的写入口。 |
| **UI** | 没设任何固定收支的家庭:**唯一看得到的变化是贷款行的趋势提示挪进了卡片**(有贷款、且这期还没校准时才出现,按钮和结果都不变)。 |

**核心功能影响排查**(触发条件:加了新的写入**触发方式**)

新的只是「谁按下按钮」,写进去的东西全部走既有入口:

| 确认的是 | 写了什么 | 走的既有入口 | 归属判据 |
|---|---|---|---|
| 固定收入 | 一笔收入流水 + 入账账户余额 | 填报页「记一笔收入」同一方法 | 显式选期(卡片所在的期) |
| 固定支出(逐笔模式) | 一笔支出流水 + 付款账户余额 | 逐笔录入同一方法 | 显式选期 |
| 还款 | 付款账户一笔「还贷」+ 贷款余额(趋势值) | 逐笔录入 + 现有「接受贷款趋势」 | 显式选期 |
| 交保费 | 一笔划转 + 两端余额 | 账户间划转同一方法 | 显式选期 |
| 撤销 | 删掉那一笔(余额回滚) | 现有删除流水 / 划转 | 那一笔原来的期 |

规律:**每一格都和「人在同一期手动记同一笔」逐字相同**,所以仪表盘 / 报表 / 体检上的每个指标对它的反应,和对手动记账的反应一样 —— 不需要另画指标矩阵。
**确定不受影响**:开账(不在开账时写任何东西,和 v0.17.x 以后一样)、关账与定格、估值刷新、券商同步、账单导入的写入路径(只多了去重标记,FR-1150)。

## 7 · 开关与默认值

**不设开关**。理由:

- 不设任何固定收支 = 什么都不会发生,天然就是「关」。
- 唯一影响存量用户的是贷款趋势提示的**位置**(行为不变)。维护者明确要求把它并进来统一;留两个位置各显示一次,反而会出现「同一件事两处都能点」。
- 兜底:回滚 jar;新表老 jar 不读(§11)。

## 9 · 失败模式(pre-mortem)

1. **同一笔记了两遍**:确认了物业费,又从支付宝账单导进来一遍;或者先导入了、又点了确认。不报错,本月支出凭空多一笔。
   **怎么发现**:FR-1150 / 1151 的 e2e —— 两种顺序各走一遍,断言库里这一期这一笔只有一条。
2. **写进了错的期**:两期同时开着(关账宽限)时,在上月的卡片上点确认,却写进了本月。
   **怎么发现**:e2e 在双开期下从上月卡片确认,断言流水的 `period_id` 是上月。
3. **撤销不干净**:删了流水、余额没回去,或这一行没回到待确认。
   **怎么发现**:e2e 撤销后断言余额回到确认前、确认记录消失。
4. **年缴 / 周期边界算错**:每年 3 月的保费在 2 月或 4 月冒出来;按周开账的家庭一笔都看不到。
   **怎么发现**:单测覆盖「每年某月 × 月度 / 周度账期 × 跨年」。
5. **一个贷款出两行**:设了固定还款,趋势建议还在。
   **怎么发现**:qa-run 护栏 + e2e 断言一个贷款在卡片里只有一行。
