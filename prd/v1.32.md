## 0 · 这一版在解决什么

**背景与现状**:

1. **每期金额几乎一样的那几笔,每期都要重新敲一遍。** 工资、物业、月保、房贷、会员费……在填报页里和「这个月在超市花了多少」走的是同一条路:选类目、选账户、填金额。
   「最近常用」只记住了类目,金额和账户每次重填。
2. **漏了没人知道。** 现有提醒(截止前 N 天的短信、站内 banner、导航「填报 ·N」徽标)只看「**账户**填没填」,不看「**该有的那几笔**有没有记」。
3. **系统里已经有一条同类的能力,但只有贷款有、只管一半**:填报页贷款行的提示条
   「按上两月趋势,本月预计还到 X(较上月 −Y)[接受] [保持上月]」(`entry/_row.html:121`、`EntryService.acceptLoanPrediction`、`PeriodOpener.predictLoanBalance`)。
   - 它只更新**贷款余额**;从哪个账户还、还了多少(含利息)要另外记一笔「还贷」。
   - 接受时顺手起草的那笔「还款划转」是草稿(`is_draft=1`),不进任何口径 —— 等于没有。
   - 它是 v0.17.x 从「开账时静默外推写进去」改成「列出来让人点」的,原因是用户不知道系统替他改了数(这条教训决定了本版的交互:**系统算、人确认**)。
   - 贷款账户上其实还登记了「负债类型」(房贷 / 消费贷 / 信用卡分期 / 亲友借款)和「年利率」,这条提示都没用上。
4. **保单登记里有「每期保费 · 年缴 / 月缴 · 生效日 · 已缴期数」**(V44 `account_insurance_policy`),只是展示。
5. **账单导入**:支付宝 / 微信可以导;信用卡 / 银行账单不导(没有真实样本)。导完之后银行卡那边通常只剩房贷、代扣、线下刷卡这几笔要手记 —— **恰好就是固定收支最能接住的那几笔**。
6. **备份只能等定时**:systemd 每周日 03:00、Docker 每天一次。改大东西之前想先备一份,只能去服务器上手动跑命令(#29 用户建议加按钮)。

**服务谁**:每月填报的家人(非技术为主);立即备份服务维护者。

**主推动力**:**每期固定的那几笔,设一次,以后到日子列出来,一键确认**。贷款试算、保单保费是同一类事(每期会发生、金额可以算出来),统一收进来。立即备份是顺带的小能力(本版改动面不大,维护者定一起做)。

**本版新引入的名词**(定稿后同步到 `AGENTS.md` 领域概念节):

- **固定收支**:每期(或每年固定几个月)都会发生、金额固定或可以按规则算出来的一笔。分四种:**固定收入 / 固定支出 / 还款 / 交保费**。
- **金额方式**:**固定金额**,或**自动计算**(从几种内置算法里选,见 FR-1106)。
- **本期待确认**:本期该有、到了日子、还没确认的固定收支。

### A · 固定收支是什么

| # | 要求 |
|---|---|
| FR-1100 | 一条固定收支有:**名称**、**种类**(收入 / 支出 / 还款 / 交保费)、**金额方式**(固定金额 / 自动计算,见 FR-1106)、**账户**(钱从哪出或到哪)、**类目**、**周期**(每月 / 每年的某几个月)、**几号**、**负责人**(默认账户主理人),以及可选的「**到哪期为止**」。 |
| FR-1101 | **固定收入**:现金收入(工资、奖金、房租……),确认 = 在入账账户记一笔收入,和手动「记一笔收入」完全一样。股票收入不在此列。 |
| FR-1102 | **固定支出**:确认 = 在付款账户记一笔支出,和逐笔录入完全一样;消费分类和「不是消费」的三项都能选,**负债账户上不能记「还贷」**照旧(v1.19.3)。 |
| FR-1103 | **还款 · 贷款月供**(房贷 / 车贷 / 消费贷 / 信用卡分期 / 亲友借款):选贷款账户 + 从哪个账户还(默认取贷款的「默认还款来源」)。确认 = 付款账户记「**还贷**」(本金那部分)+「**利息支出**」(利息那部分,有才记)+ **贷款余额减掉本金**。本金和利息怎么分见 FR-1106。两个类目都是今天就有的;今天手动记的人通常整笔记成「还贷」,本版只是把它拆准。 |
| FR-1104 | **还款 · 信用卡账单**(刷卡消费已经记在卡上的那种信用卡):确认 = 一笔**划转**(付款账户 → 信用卡),**不记支出** —— 消费在刷卡时已经算过一次了,再记「还贷」就是 v1.19.3 说的支出翻倍。按账户自动判断是哪一种(建户模板是「信用卡」、或这张卡上记过消费 → 信用卡账单),表单上可以改。 |
| FR-1105 | **交保费**(储蓄型保险):选保险账户 + 从哪个账户付。确认 = 一笔划转(付款账户 → 保险账户),不算支出。消费型保险(没有保险账户的)用「固定支出」记。保单登记填了「每期保费 + 缴费频率 + 生效日」的,保险账户页一键「设成固定交保费」,年缴月份 = 生效月,缴满总期数自动停。 |

### A2 · 金额:固定,或自动计算(兼容现在的贷款试算)

| # | 要求 |
|---|---|
| FR-1106 | 金额两种方式,表单上二选一:**固定金额**(填一个数;某期当场改了会问「以后都按新金额?」),或**自动计算**(选一种内置算法,只列出对这一种、这个账户适用的):<br>**① 按上月和上上月的差值**(还款 · 贷款月供 · 默认)—— 就是现在贷款提示那套:本期本金 = 上月末欠款 − 上上月末欠款(只有一期历史时 = 0,还到 0 为止不会变正,与 `predictLoanBalance` 同算法)。<br>**② 月供固定,按年利率拆本金 / 利息**(还款 · 贷款月供 · 贷款上填了年利率时可选)—— 每期扣款 = 固定月供;利息 = 上月末欠款 × 年利率 ÷ 12;本金 = 月供 − 利息。等额本息 / 等额本金都适用,比 ① 准。<br>**③ 全额还上期账单**(还款 · 信用卡账单)—— 金额 = 信用卡上月末欠款。<br>**④ 按保单每期保费**(交保费)—— 金额 = 保单登记的每期保费,改保单就跟着变。<br>**⑤ 近 3 期平均**(收入 / 支出)—— 每期有点变的那种(水电燃气、话费、加班费):金额 = 这一条最近 3 次确认的平均;不满 3 次按有几次算,一次都没有就先按固定金额走。 |
| FR-1107 | 自动算出来的数**只是填在卡片上**,和固定金额一样要人点「确认」,当场可改;卡片上写明它是怎么算的(如「按上月 −1,190,000 与上上月 −1,195,600 的差值」),点开看算式。 |
| FR-1108 | 选「贷款月供 · 按差值」时,确认写进去的贷款余额与今天点「接受」**逐分相同**;付款账户那边多记了「还贷」本金 —— 今天这一笔要人另记,本版把它带上。月供里的利息算不出来(方式 ① 不知道月供),所以不记利息;想记准就选方式 ②。 |

### B · 填报页上:默认只占一行(交互形式)

| # | 要求 |
|---|---|
| FR-1110 | 填报页「第一步 · 本月收支」标题下面**一行摘要**,默认收起:<br>`固定收支 · 3 笔待确认 · 共 ¥7,100  [全部确认] [展开 ▾]`<br>都确认了:`固定收支 · 本期 6 笔都确认了 ✓`;这期都还没到日子:`固定收支 · 下一笔 28 号 视频会员`。一条固定收支都没设、也没有贷款:这一行只剩一个小入口 `+ 设固定收支`(FR-1131)。 |
| FR-1111 | 展开后**只列到了日子的**(待确认 + 自动试算的建议);没到日子的收在「还有 2 笔没到日子 ▸」,已确认的收在「已确认 1 笔 ▸」。每笔一行:名称、种类、金额(自动的标「算」)、账户、[确认] [这期没有]。 |
| FR-1112 | 「全部确认」只确认已到日子的。**系统从不自己记**,不确认就不会有这笔。 |
| FR-1113 | 当场改了金额 → 小字问「以后都按 ¥新金额?」(默认不改,自动计算的不问)。比上一次确认的金额多 / 少时标出差额。 |
| FR-1114 | 确认后这一行收进「已确认」,写明记成了什么,能「**撤销**」(删掉那几笔、余额跟着回去)。 |
| FR-1115 | 确认写进去的,**和手动记一笔完全一样**:同样的余额联动、同样进报表和各项指标;流水上标来源「固定收支」。 |
| FR-1116 | 账期选择器选的是哪一期,摘要就是哪一期的(两期同时开着时各管各的)。关账时没确认的**不记、也不挪到下一期**;下一期摘要后面提一句「上期 N 笔没确认」。 |
| FR-1117 | **贷款行变短**:贷款行里原来那条提示条去掉(它的位置挪到了摘要里),贷款行只剩一行小字「本期还款 · 待确认 ↑」。填报页整体比今天短。 |
| FR-1118 | 手机上摘要同样一行;展开后每笔两行(名称 · 金额 / 账户 · 按钮),按钮整行点得中(v1.31 卡片排法)。 |

## 4 · 不做什么

- **不做「到日子系统自己记」**。金额会变、可能和导入重复,静默写进去就是静默算错;贷款预填 v0.17.x 正是因为这个改成让人点确认的。自动计算只是**替人把数算好**,写不写仍由人点。
- **不做账户间的固定划转**(比如每月定投到基金账户):撞「刻意不做」清单的「**定投提醒**」。交保费、还信用卡是例外 —— 一个是合同规定必须交,一个是还已经花掉的钱,都不是投资决定。
- **不做从流水里自动认出「每月都在扣」的订阅**(v1.24 推迟的那条):那是事后识别,这是事先设好。
- **不做预算**(预算包络)、**不做信用卡 / 银行账单导入**(还是没有真实样本)。
- **不做按贷款合同生成整张还款计划表**:方式 ② 每期按上月欠款算一次利息,已经够准;整张表要录合同参数,拉高录入负担。
- **立即备份不做「下载备份文件」和「一键恢复」**:备份里是全家所有数据,开下载链接是另一类风险;恢复是破坏性操作,不适合放一个按钮。
- **不改任何口径**:确认写进去的和手动记的一模一样(FR-1115)。

## 6 · 存量影响

| 维度 | 这一版的影响 |
|---|---|
| **schema** | 新增两张表:固定收支本身、每期的确认记录(确认 / 这期没有 / 关联到哪几笔流水或划转)。**不改任何旧表、旧列**。立即备份用 `backup_log` 已有的 `MANUAL` 类型,不加迁移。 |
| **口径** | 本版不涉及口径变更:确认写进去的和手动记的一样,经同样的写入口。贷款「按差值」与今天的「接受」同算法、同结果(FR-1108)。 |
| **UI** | 没设任何固定收支的家庭:填报页「本月收支」下面多一行(有贷款时是贷款试算建议,没有时是 `+ 设固定收支` 小入口);贷款行内的提示条挪进这一行(按钮和结果不变)。 |

**核心功能影响排查**(触发条件:加了新的写入**触发方式**)

新的只是「谁按下按钮」,写进去的东西全部走既有入口:

| 确认的是 | 写了什么 | 走的既有入口 | 归属判据 |
|---|---|---|---|
| 固定收入 | 一笔收入流水 + 入账账户余额 | 「记一笔收入」同一方法 | 显式选期(摘要所在的期) |
| 固定支出(逐笔模式) | 一笔支出流水 + 付款账户余额 | 逐笔录入同一方法 | 显式选期 |
| 还款 · 贷款月供 | 付款账户「还贷」本金(+「利息支出」)+ 贷款余额 | 逐笔录入 + 「接受贷款趋势」写余额的同一方法 | 显式选期 |
| 还款 · 信用卡账单 | 一笔划转 + 两端余额 | 账户间划转同一方法 | 显式选期 |
| 交保费 | 一笔划转 + 两端余额 | 账户间划转同一方法 | 显式选期 |
| 撤销 | 删掉那几笔(余额回滚) | 现有删除流水 / 划转 | 那几笔原来的期 |
| 立即备份 | `backup_log` 一行 + 备份文件 | 与定时备份同表、同目录 | 不涉及账期 |

规律:**每一格都和「人在同一期手动记同一笔」逐字相同**,所以各页面指标对它的反应和对手动记账一样 —— 不需要另画指标矩阵。
**确定不受影响**:开账(不在开账时写任何东西)、关账与定格、估值刷新、券商同步、账单导入的写入路径(只多了去重标记)。

## 9 · 失败模式(pre-mortem)

1. **同一笔记了两遍**:确认了物业费又从支付宝导进来;或信用卡还款记成了「还贷」支出(消费已经在卡上记过)。不报错,本月支出凭空多一笔。
   **怎么发现**:e2e 两种导入顺序各走一遍、断言这一期只有一条;信用卡账单确认后断言**没有**支出流水、只有一笔划转。
2. **本金 / 利息拆错**:方式 ② 用错了月份的欠款,或欠款的正负号弄反,利息变成负数、本金比月供还大。
   **怎么发现**:单测覆盖等额本息一整年 + 还清那一期 + 利率没填时不出现方式 ②。
3. **按差值的结果和今天的「接受」不一样**:并进来时换了算法或取错了「上月」。
   **怎么发现**:e2e 同一贷款分别用旧路径和新路径算,断言贷款余额逐分相同。
4. **写进了错的期**(两期同时开着)。
   **怎么发现**:e2e 在双开期下从上月的摘要确认,断言流水的期是上月。
5. **立即备份挂住或写满盘**:mysqldump 卡住、连点十次。
   **怎么发现**:同一时间只跑一个 + 1 分钟间隔 + 超时写失败记录;e2e 连点断言只多一条记录。
