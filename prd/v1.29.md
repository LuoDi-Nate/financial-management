## 0 · 这一版在解决什么

**背景与现状**:v1.26 起 IBKR(盈透)可以用 Flex 报表只读同步,带进来的是**现金和正股 / ETF**。期权、期货、债券一律跳过,只在同步结果里写「跳过期权/期货 N」(`BrokerSyncService.java:253-255`)。于是期权做得多的账户:

- **账房里的账户总额 ≠ 盈透里的净值**:买入的期权少算了;卖出(做空)的期权本该是负债,也没减掉 —— 两个方向都可能错。
- 用户只能自己手填一条「手填市值」去凑,而期权每天在变、每月到期,手填的数很快就过时。

**服务谁**:用盈透、做期权的自建用户(#24 的 @Jsonya)。

**主推动力**:**账户总额和盈透对得上**。其余(期权的展示、到期提示)都是为了让这个数看得懂。

**评审后扩的范围(维护者 2026-10-03)**:期货、债券「都是一类的」,一起做;富途、老虎如果默认没同步期权,算 bug,本版一并修。查下来三家各有各的洞(见 FR-953 / FR-954)。

**本版新引入的名词**:**期权持仓** —— 一张合约(同一标的、同一看涨 / 看跌、同一行权价、同一到期日)记成账户里的一条持仓,市值用盈透报表给的持仓市值(已含合约乘数;卖出为负)。

## 1 · 调研

**盈透 Flex 报表的期权行**(Open Positions 一节,`assetCategory="OPT"`)自带:标的代码、看涨 / 看跌、行权价、到期日、合约乘数(美股期权通常 100)、持仓张数(卖出为负)、每股标记价、**持仓市值**(= 张数 × 标记价 × 乘数,卖出为负)。也就是说**不需要我们自己去拉期权价格** —— 报表里的市值就是盈透自己的估值,和它 App 里的净值同源。

**实测状态(2026-10-02 · @Jsonya 在 #26 贴了真实报表的两行:一张买入、一张卖出的看涨,组成一个牛市价差)**:
- 买入:数量 `1`、方向 `Long`,**持仓市值 = 数量 × 标记价 × 乘数(100)**,正数;
- 卖出:数量 `-1`、方向 `Short`,**持仓市值为负数**,同样已乘乘数;
- 每行都带标的代码、看涨 / 看跌、行权价、到期日(`YYYYMMDD`)、乘数;期权代码形如「标的 + 空格 + 到期日 + C/P + 行权价」,**21 个字符**(超过现有 16 字符的列)。
- 他贴的是报表导出成表格后的列名(`AssetClass` / `Quantity` / `Put/Call` …),我们读的 XML 里对应 `assetCategory` / `position` / `putCall` …,含义一致。
- 结论:§9 ① 担心的「市值差 100 倍或符号反了」在真实数据上**不成立**,但仍保留交叉核对(防止个别券商品种乘数不是 100)。测试数据按这个形状重新合成,不直接用他贴的数。

**别的工具怎么做**:持仓聚合类工具(Sharesight、Kubera 等)对期权普遍是「按券商给的市值记一行」,不自己算 Greeks、不追逐笔交易 —— 与本项目「账户级月度快照」的颗粒度一致。

## 4 · 不做什么

- ~~期货、债券、权证:仍跳过~~ → 评审后改为一起做(FR-951 / FR-952;权证同期权)。
- ~~富途、老虎的期权:本版不动~~ → 评审后改为一并修(FR-953 / FR-954)。
- **富途的期货账户**:富途的期货在单独的期货账户里,本版只同步证券账户(港 / 美 / A 股市场)里的持仓。
- **差价合约、外汇头寸**等其余品种:仍跳过计数(「跳过其他品种 K」)。
- **期权的成本与盈亏**:不显示 —— 各家成本口径不一(每股 / 每张),给半对的盈亏不如不给。
- **Greeks、盈亏分析、期权策略识别**:不做。我们只关心「这个账户现在值多少」。
- **逐笔交易 / 行权指派事件**:不做 —— 撞「刻意不做 · 逐笔流水账」。行权、指派的结果下次同步自然体现在持仓上。
- **手动录入期权**:不做专门入口。没接盈透的用户仍可用「手填市值」记一条。

## 6 · 存量影响

| 维度 | 影响 |
|---|---|
| **schema** | 持仓表要能放下期权的代码(盈透的期权代码约 21 个字符,现在的 `ticker` 列只有 16)和看涨 / 看跌、行权价、到期日、乘数。**只加不改**:加列 / 加宽,旧行这些列为空。细节在 TDD |
| **口径** | 见下 |
| **UI** | 没接券商、或券商里没有期权 / 期货 / 债券的用户:**一个像素都不变**(老虎用户例外:股票第一次同步进来) |

### 口径变更声明

- **改的是**:接了券商且有期权 / 债券(老虎:还有股票)的账户,账户余额从「现金 + 股票」变成「现金 + 股票 + 期权等」。
- **旧数据**:已关账的月份**不变**(封板)。变化只发生在升级后第一次同步所在的那一期:余额会跳一下(多了期权市值,或卖出期权减掉一截)。
- **那一跳怎么记(维护者 2026-10-03 定,§13 ②)**:**新账户**第一次同步 = 开账(这个月不算收益);**已经在记的账户** = 计入当月收益(「钱赚」),当月收益率会偏高一次。#26 的提交者之前就有期权持仓没算进来,升级那个月会看到收益率偏高 —— 在 issue 里提前说明。
- **零差异基线**:没有期权的账户,对照已发布的 v1.28.x 逐页零差异。

### 核心功能影响排查

- **写入通道**:没有新增 —— 还是券商同步这一条(事件时点:同步那一刻落进余额期,与股票持仓同一判据)。
- **受影响的**:同一期的存量类指标(净资产 / 总资产 / 总负债 / 账户余额 / 资产分布 / 集中度)立即变;收益类只在第一次同步那个月出现上面说的一跳。
- **确定不受影响的**:没接券商的账户;券商里没有期权 / 期货 / 债券 / 空头的富途、盈透账户(零差异基线);已关账月份;收支、人赚、储蓄率(期权不碰收支)。
- **会变的券商账户**:盈透 / 富途里有期权、债券或空头的;**老虎账户**(股票第一次进来 —— 以前只有现金)。
- 完整矩阵(写操作 × 三页面指标)在 TDD 里列。

## 9 · 失败模式(pre-mortem)

1. **市值差 100 倍或符号反了**(静默算错):真实报表的「持仓市值」若不含乘数、或卖出时不是负数,账户余额会错得很离谱。→ 用「张数 × 标记价 × 乘数」与「持仓市值」**交叉核对**,对不上的行不同步、照实列出(FR-950);评审后先拿真实数据核对再写代码。
2. **代码太长塞不进去**:期权代码超过现有列宽 → 插入失败或被截断,两张合约撞成一条。→ 加宽列 + 单测覆盖真实长度的代码。
3. **到期日当天的残行**:到期当天报表可能还带着那一行 → 下次同步归档;持仓页标「今天到期」,用户不会误以为卡住了。
4. **第一次同步那一跳被当成投资亏损 / 收益**:用户看到「本月资产收益 −8%」会吓一跳。→ §13 ② 定处理方式;无论怎么定,同步结果里都写明「期权首次计入,带来 ±X 的变化」。

## 11 · 回滚与关闭

- **不可逆动作**:无(只读同步,不向盈透写任何东西)。

## 14 · v1.29.1 · issue #34(续):全新 Docker 安装后,没关账的那一期账户类型错位

> 来源:[issue #34](https://github.com/LuoDi-Nate/financial-management/issues/34) @chca2 · 2026-10-02 贴出每期每个账户的「定格类型」

**现象**:仪表盘「总负债」= 「中国银行(现金)」+ 一张信用卡,另一张信用卡没算进去;账户页「贷款」那一格、报表页的总负债都是对的。编辑页里两个账户的类型也是对的。

**查到的**:提交者导出的定格类型里,**10 月(还没关账)**这一期居然有定格行 ——「中国银行(现金)」定格成贷款、一张信用卡定格成房产。定格只在关账时写、重开时删,没关账的期本不该有。这两个类型恰好是**演示数据里 5 号、10 号账户**的类型。

**根因**(在一个临时数据库上照全新安装的步骤逐条复现,提交者导出的那四行逐字一样):全新 Docker 安装时,迁移先灌演示数据,迁移 V54 再给演示数据里已关账的期回填定格行;装好后清演示数据的脚本只清了「期」和「账户」两张表,**没清定格表**。编号从 1 重新开始,残留的定格行就按 (期编号, 账户编号) 挂到了用户自己的账户上。9 月关账时定格被重写成了对的,10 月还挂着演示数据。v1.28.4 修的「账户改过类型、明细和合计分家」是真问题,但不是提交者这里的根因。

**影响面**:用 Docker(以及 systemd / macOS 一键脚本)**全新安装**、并且清过演示数据的家庭。升级安装的老用户不受影响(beta 实测四条判据各命中 0 行)。

| # | 要求 |
|---|---|
| FR-956 | 还没关账的期,不读定格行 —— 一律按账户当前的设置算(定格本来就只属于已关账的期) |
| FR-957 | 升级时清掉「不可能是真定格」的残留行:没关账的期上的、早于那一期或那个账户被创建的、期或账户已经不存在的 |
| FR-958 | 清演示数据的三个脚本(Docker / systemd / macOS)一并清定格表;以后迁移往哪张表写过数据,清演示数据时要么清、要么写明为什么保留(护栏拦) |

**口径**:正常数据零差异(已关账的期照旧读定格;没关账的期正常情况下本来就没有定格行)。
