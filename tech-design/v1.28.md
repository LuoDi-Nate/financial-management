## 一、需求分析

### 1. 背景 & 目标

见 PRD §0。一句话:9 处分析类 AI + 超级 Agent 每一问,都能在页面上逐字看到当时发出去的内容;顺带账户名换代号、日志不写正文、隐私模式糊 AI 正文里的金额。

### 2. 需求理解(验收口径)

- 「逐字」= 与交给大模型客户端的 system / user 两个字符串逐字节相同。
- 「这份结果」= 页面上正在展示的那份(缓存命中时是生成它的那一次调用)。
- 没调用 / 失败 / 没采用 / 老结果,四种状态各有说法,不混用。

## 二、关键选型

### 选型一 · 记录在哪一层写

| 备选 | 取舍 |
|---|---|
| ① 各调用方(9 处 + Agent)自己存 | 写 10 遍;哪天一处忘了存、或存的是拼接前的中间串,就是「显示的不是发出去的」—— 这正是 v1.12「六处各自遍历 LLM」出过的病 |
| **② `LlmRouter` 统一存** | 唯一编排点:发出去的原文、实际用的模型、失败时的上游原话都在这一个 for 循环里。调用方只传一个 `PromptTrace`(用在哪 · 代号对照 · 设置摘要),拿回记录编号 |
| ③ 事后按缓存键重拼 | 数据变过之后重拼的与结果对不上,正是本版要防的 |

**选定 ②**。调用方在路由返回后若还要做自己的校验(调仓的输出校验),用 `PromptRecorder.markRejected(id, reason)` 补记结果。超级 Agent 不走 `LlmRouter`(流式 + 工具循环),由两个运行时在「真正发出去的那一刻」回调一次(`AskTurn.onPromptSent`),同样只记原文。

### 选型二 · 记录怎么和结果绑

| 备选 | 取舍 |
|---|---|
| **① 结果带记录编号** | 内存缓存(体检三处)放进 `CacheEntry`;库表缓存(调仓 / 复盘 / 目标 AI 报告)各加一列 `prompt_record_id`;JSON 返回的(透视 / 目标推荐参数 / 复盘)直接带编号;超级 Agent 记在提问那条消息上 |
| ② 记录表按「用在哪 + 键」反查 | 调仓缓存键里没有数据,反查到的「最近一次」未必是这份建议 |

**选定 ①**。新列可空,空 = 老结果。

### 选型三 · 存储形态

规矩那一段(system)各处固定、每次几千字 → 按 sha256 去重存一份(`llm_system_prompt`);你家的数据(user)每次不同 → 原文存。代号对照存 JSON(只在自己库里,只给本家庭看)。

保留:内存缓存那几处(体检三处 / 透视 / 目标推荐参数)2 天;其余 90 天;结果被覆盖时删掉旧记录;没被引用的规矩文本随清理一起删。每天 04:17 跑一次。

### 选型四 · 面板怎么渲染

| 备选 | 取舍 |
|---|---|
| ① 把纯文本交给前端自己切段、标色 | 「哪几段来自你的设置」要认 `AnalysisPromptBlocks` 的标题,前后端各一份就会漂 |
| **② 服务端切段渲染片段,前端 htmx 拉取** | 段标题只认 `AnalysisPromptBlocks` 里的常量(一处来源);转义 + 金额包 `data-priv` 在服务端一次做完;点了才拉,页面不变重 |

**选定 ②**。`GET /ai/prompt/{id}` 返回面板片段(查询带 `family_id`);`GET /ai/prompt/none?why=legacy|skipped|noai&for=…&at=…` 返回说明面板。前端 `prompt-peek.js` 只管开合、打字效果、命令与复制。

### 选型五 · 账户名换代号怎么换(FR-920)

| 备选 | 取舍 |
|---|---|
| ① 对整段提示词做全文替换 | 用户常把账户叫「现金」「房贷」「公积金」—— 全文替换会把「现金 (CASH)」这类普通词一起换掉,材料就坏了 |
| **② 只在系统写入账户名的位置换** | 账户清单、单账户的「账户名」一行、范围块里列出的账户、调仓的账户列表、透视按账户切的行;用户自己写的偏好 / 补充要求不动(只换成员名) |

**选定 ②**。代号「账户A / 账户B …」按账户 id 升序,稳定。回答展示前把代号换回真名(正则 `账户[A-Z]{1,2}(?![A-Za-z])`,长的先换),与成员名反映射同一处。调仓的输出校验与「账户存在」检查在换回真名之后做。

金样本护栏改成:**新提示词把代号换回真名后,与 v1.26.1 金样本逐字相同**(只允许「已脱敏成员真名」那一行标题因「也脱敏账户名」改字)—— 证明这次只换了名字,别的一个字没动。

### 选型六 · 超级 Agent 记什么(FR-919)

| 模式 | 规矩 | 这一问 |
|---|---|---|
| 本机 | 这次请求的系统提示词 + 分析上下文(本来就拼在一起发) | 问题原文 |
| 托管 | 「更新 Agent / 创建 Agent」成功时存的那份原文 + 时间(百炼侧的系统提示词由它决定) | `composeTurnInput` 的结果(分析上下文 + 问题) |

前几轮对话与工具返回不重复存(面板写明去「思考过程」看工具)。工具返回仍带账户名,面板照实写。

### 选型七 · 日志(FR-921)

`LlmAuditLogger` 只记:模型、用在哪、家庭、耗时、两段长度 + sha256 前 12 位、结果、拒收原因、上游错误、记录编号。删掉诊断里 DEBUG 级别打印整段提示词的那行。护栏:任何 log 语句不许带 `systemPrompt` / `userPrompt` / `raw` 这类变量。

### 选型八 · 隐私模式糊 AI 正文里的金额(FR-913)

一个正则(货币符号开头的金额、「N 万 / N 亿」)两份实现:服务端 `AiText.privHtml(text)`(先转义再包 `<span data-priv>`,模板用 `th:utext`);前端 `privText(el, text)`(只用 `textContent` 与 `createElement` 拼节点)。单测对同一组样本断言两边切出的金额一致。

## 三、系统概要设计

### 1. 整体设计思路

```
调用方 ──PromptTrace──▶ LlmRouter.invoke ──▶ client.chat(system, user)
                               │ 循环结束
                               ▼
                        PromptRecorder.save ──▶ llm_prompt_record / llm_system_prompt
                               │ id
调用方把 id 放进结果(缓存条目 / 缓存行 / JSON / ask_message)
页面卡片头 >_ ──htmx──▶ GET /ai/prompt/{id} ──▶ PromptPeekView(切段 · 标来源 · 包金额) ──▶ 终端片段
```

### 2. 领域模型设计

- `PromptSurface`:用在哪(10 个取值,含中文名与保留档位)。
- `PromptTrace`:一次调用的上下文(surface · 代号对照 · 设置摘要),路由写回 `recordId` / 结果。
- `PromptRecord`:存下来的一次调用(原文 · 模型 · 结果 · 原因 · 时间)。
- `PromptPeekView`:面板视图(说明行 · 规矩 · 你家的数据分段 · 代号对照 · 复制原文)。

### 3. 代码架构设计

| 位置 | 内容 |
|---|---|
| `service/llmtrace/` | `PromptSurface` · `PromptTrace` · `PromptRecorder`(存 / 查 / 清理)· `PromptPeekView` · `AccountCodenames` · `AiText` |
| `LlmRouter` | 新重载 `invoke(familyId, PromptTrace, system, user, handler)`;老重载不变(不记录),9 处改走新重载 |
| `web/ai/PromptPeekController` | `/ai/prompt/{id}` · `/ai/prompt/none` |
| `templates/fragments/_prompt-peek.html` | `btn(src)` 图标 · `panel(v)` 终端 |
| `static/js/prompt-peek.js` | 开合 · 打字 · 命令 · 复制 · `privText` |

### 4. 数据架构设计

`V65__llm_prompt_record.sql`(只加不改):

- `llm_system_prompt(family_id, hash, text, created_at)`,主键 (family_id, hash) —— 本机模式超级 Agent 的系统提示词里拼了家里的分析上下文,不是纯代码常量
- `llm_prompt_record(id, family_id, surface, system_hash, user_text, vendor, outcome, outcome_note, settings_note, legend_json, created_at)`,索引 `(family_id, created_at)`
- `rebalance_advice_cache` / `review_ai_cache` / `goal_ai_report` / `ask_message` 各加可空列 `prompt_record_id`
- 开关:`family_runtime_config.ai_prompt_peek`(缺省 = 开)

## 附录 B · v1.28.1 补丁(PRD §14 · FR-922 ~ FR-928)

### B.1 开账基线不含首期转账(FR-924 / FR-925)

**问题**:`openingBaseline(slice, P)` = Σ 首次出现在 P 的账户的**期末余额**。新账户开户 0、首期从老账户转入 X:期末 = X,整笔进开账基线;老账户那边 ΔNW −X、净流入 0 → 家庭口径「本月资产收益 = ΔNW − 净流入 − 开账基线」凭空少 X。账户级「累计净投入」= 首期期末 + Σ 各期(收入 − 支出 + 转入 − 转出),首期的转入被加了两遍。

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A · 首期期末 − 首期转入**(选) | 事实表每行已有 `transferInBase`,纯函数 `openingOf(row)` 就地算 | 不查新表、不改 SQL;首期没有转入时**逐字不变**(零差异可证);家庭层 / 账户层共用同一个函数 |
| A′ · 首期期末 − 首期转入 **+ 首期转出** | 同上,再把转出加回 | 初稿这么写的,复核 prod 数据时撤掉:新添的工资卡首期转出的钱,常常就是当月工资 —— 而工资已经记在家庭级收入总额里(不挂账户)。加回会把工资既算「人赚」又当开账基线剔除一次,那一期的钱赚被少算。转入没有这个歧义(钱一定来自家里另一个已记账的账户),转出有,账本分不出来 → 维持原口径 |
| B · 从审计日志 / `source_tag` 找「开户时手填的那张快照」 | 找首笔 MANUAL 快照当校准值 | 快照是 upsert,同一期后续的划转 / 收支会覆盖同一行,「开户那一刻填的数」库里并不单独留存;审计日志是文本,拿它算指标脆 |
| C · 只在「转出方是老账户」时扣 | 按对手方是否也是新账户区分 | 两个新账户之间互转时,A 本来就一进一出在家庭层抵消;C 多一层判断、换不来差别 |

**资产类不为负**:A 在「转进来的钱首期就亏了 / 花了」时会算出负数 —— 资产类此时记 0(亏掉的部分留在钱赚 / 未归因,不当成「负的存量」);负债照常为负。**只在首期有转入时才走这条**:没有转入的行原样返回,连 beta 上「资产期末为负」的怪数据也不借这次顺手改口径(`OpeningBaselineTransferTest` 第六条钉住)。

**收入 / 支出不动**:首期的收入按同理也该从开账基线里拆出来,但维护者点名的只有转账;一次只改一个量,改动面可控、口径变更声明能写清。

**影响面**:只影响新账户首期有转入的那些期;凡是经 `openingBaseline` 的都跟着变 —— `kpis()` 的本月资产收益与人赚 / 钱赚里的开账基线行、`familyXirr` / `familyTwr`、`periodFlows` → `principalVsReturnDecomposition`、`netWorthTrendExOpening`、YTD;账户层 `buildAccountPerformance.netPrincipal`(→ 累计损益)。账户级 XIRR 起点本来就是「首期期末」、首期流水不计,不受影响。**已封板快照不回写**(按封板时的值展示)。

**零差异基线**:`scripts/metric-baseline.sh` 对照已发布 v1.28.0 —— 只有 beta 上一个首期有还款转入的贷款账户「累计净投入」按新口径变了(变化量恰为那笔转入),其余全部零差异。

### B.2 入口写明「查看 prompt」、与同一行按钮等高(FR-922 / FR-923)

`.peek-btn` 改 `inline-flex` + `align-self:stretch`:图标 + 「查看 prompt」;所在的操作组一律 `items-stretch`,入口的高度由同组最高的按钮决定 —— 不写死像素,各卡片的刷新按钮长什么样都跟得上。仪表盘复盘 / 透视洞察原来的「重新解读」「收起 ×」是纯文字,等高无从谈起,改成与体检卡同款的细边框小按钮。调仓建议把「查看 prompt」和「↻ 刷新」包成一组,窄屏整组换行、时间戳单独一行,避免按钮被挤成两行字。

### B.3 账户页「⋯」菜单(FR-926 · issue #25)

| 方案 | 取舍 |
|---|---|
| **打开时按按钮位置改 `position:fixed`,下方放不下就往上开**(选) | 不动表格的 `overflow-hidden`(圆角与窄屏横滑都靠它);几行 JS。滚动 / 改窗口大小时**跟着按钮重新定位**(capture 监听,表格内横滑也跟),按钮滚出视口才收起。初版是「一滚就收」—— 整套 e2e 撞上:点 ⋯ 前页面恰好在把那一行滚进视口,滚动事件晚一帧到,菜单刚开就被关掉 |
| 去掉外层 `overflow-hidden` | 表格圆角会被行背景盖掉,窄屏横滑失效 |
| 最后 N 行改成向上展开 | N 取多少都不对(行高随内容变),账户数一变就又裁掉 |

### B.4 账户页类型合计换成本位币(FR-927 · issue #25)

`AccountService.summarize` 逐账户换算后再按类型相加:汇率取各账户当前余额所在期里最新的那一期的 `fx_rate`(与净资产同一套:本位币 = 原币 ÷ rate),没有就取最近一条;都拿不到时按原币相加并记告警(与净资产那边的兜底一致,不让整张卡片消失)。标签用家庭本位币符号。

### B.5 落地页 GitHub 角标(FR-928 · issue #25)

## 附录 D · v1.28.3 补丁(PRD §16 · FR-931 ~ FR-933 / FR-939 · issue #27 / #28 / #29,拆自 #25)

### D.1 Logo:编不出 WebP 的浏览器

| 方案 | 取舍 |
|---|---|
| **前端认 blob 的真实类型,不是 WebP 就用 PNG(超 190KB 退 JPEG);后端按魔数认 WebP / PNG / JPEG**(选) | 两头都不信「声明的类型」,只信字节;扩展名跟着真实格式走,`/uploads` 按扩展名给对 Content-Type |
| 后端把 PNG / JPEG 转成 WebP | 要引入图像编码库(Java 标准库不会写 WebP),为一个 256px 的 logo 不值 |
| 前端引入 WebP 的 wasm 编码器 | 多一百多 KB 的脚本,只为 logo 一处 |

### D.2 Logo:换图后显示旧图

`/uploads/**` 是 7 天公共缓存,而文件名原来永远是 `logo.webp` —— 地址不变,浏览器(和中间的反代)照样给旧图。改成 `logo-<SHA-256 前 10 位>.<ext>`:内容变则地址变,缓存不用动。写入后删掉同目录下其他 `logo.*` / `logo-*.*`(只认这两种名字,别的文件不碰);「移除」同理。未选:给地址加 `?v=` 时间戳(要在模板里取文件修改时间或给 family 表加列,为一个 logo 改表不值);缩短 /uploads 缓存(所有上传内容一起失去缓存)。

### D.3 关账节奏选中态

选中态原来只在服务端渲染(`rhythm-on`),点卡片只改了隐藏的 radio,看不出变化。改为 CSS `.rhythm-opt:has(input:checked)` 跟着 `:checked` 走,另有几行脚本在 change 时同步 `rhythm-on`(不认 `:has()` 的老浏览器靠它),并在选中项 ≠ 已保存项时显示「已选「…」· 还没保存」。不自动保存:关账节奏改的是「什么时候锁账」,点错了不该立即生效。

### D.4 Docker 备份容器(FR-939 · #29)

- **健康检查**:备份容器复用 app 镜像,而镜像里写了 `HEALTHCHECK curl localhost:20000/health` —— compose 不覆盖就被继承,备份容器里没跑 app,永远 unhealthy(用已发布镜像真起容器复现:`curl: (7) Failed to connect to localhost port 20000`)。compose 里给 backup 覆盖成「`.last-ok` 是否 26 小时内刷新过」。未选:`healthcheck: disable: true` —— 那就看不出备份真的停了;在 Dockerfile 里去掉 HEALTHCHECK —— app 自己需要它。
- **重试**:原来失败后 `sleep 86400`,日志却写「稍后重试」。改成每 5 分钟重试、最多 12 次,还不行才等下个周期;起步宽限 70 分钟与此对齐。
- **成功的判据**:与 `deploy/backup-now.sh`(v1.6.28)同一条 —— 能解压 + 含 `CREATE TABLE` 才算;日志写 `wc -c` 字节数与表数(`du -h` 在一些文件系统上报的是占用块,比如「512」,看不出是不是空备份)。
- **失败原因**:不再 `2>/dev/null`,打 mysqldump 报错第一行(密码走 `MYSQL_PWD`,不会出现在报错里)。
