### 静默失败预检

## 二、关键选型

### 选型一 · 服务配置怎么保持原子

| 方案 | 用户可感知的优点 | 风险/代价 | 结论 |
|---|---|---|---|
| 地址/Key/认证分开存键,逐键读缓存 | 和旧平台键形状相似 | 事务之外的多次读取可能混用版本,也容易在改地址时误带旧Key | 不选 |
| **既有runtime表一行私密JSON+版本号** | 地址、认证、Key同时生效或同时失败;没有半份服务 | 需专用解析、掩码及并发更新校验 | **选它** |
| 新建服务表并做多服务管理 | 后续可扩展任意数量 | 用户多出管理对象和切换语义,超出首版一个服务位 | 不选 |

选定理由:一行数据物理上绑定地址与凭据;界面仍是一张平台卡。不能只靠“保存用了@Transactional”就声称多个缓存读也是同一版本。

### 选型二 · 动态地址传输

| 方案 | 优点 | 风险/代价 | 结论 |
|---|---|---|---|
| 原HttpURLConnection/RestTemplate只加URL黑名单 | 现有固定平台已使用 | JDK默认解析与连接分离难以固定批准DNS集合;用IP替换URL会破坏SNI/证书主机名 | 不选 |
| **显式使用已有OkHttp4.12.0的DNS接口,仅用于custom** | 传入批准地址且保留原hostname/TLS;JSON和SSE同一访问策略 | 每次custom请求独立连接池,增加一次握手;需管理取消和资源释放 | **选它** |
| Apache HttpClient5自定义DnsResolver | 本轮也通过同样20项实验 | 当前部署包没有它;新增后可能改变Spring Boot对其它RestTemplate的请求工厂自动选择 | 不选 |

选定理由:OkHttp已在现有依赖图及部署jar中,显式声明同版本保证未来不随券商依赖移除而消失;不会新增Apache类路径导致的全局HTTP行为变化。本版只替换custom出口,四家固定平台沿用原传输。

实施依赖核对:显式声明OkHttp会改变Maven最近依赖优先关系,使JetBrains annotations解析为本机未缓存的13.0。同步显式保留当前已部署的17.0.0,不拉新版本、不改变现有运行依赖版本,离线编译通过。

### 选型三 · 内网与DNS边界

| 方案 | 优点 | 风险/代价 | 结论 |
|---|---|---|---|
| 全部禁止非公网目标 | 配置简单 | 用户明确提出的本地/公司服务无法使用 | 不选 |
| 内网勾选后不再检查目标 | 内网连接最宽松 | 云元数据、重定向、DNS变化可送出凭据或访问保留服务 | 不选 |
| **语法校验+明确许可+保留目标拒绝+每次解析固定** | 支持用户指定的内部模型服务,并阻止默认情况下的内网误访和已知保留目标 | 私有服务仍由用户负责信任;不能防止其服务器自己转发数据 | **选它** |

选定理由:内网许可是对明确配置服务的授权,不是任意代理能力。服务合法不等于服务可信,界面只说明发送位置和真实能力,不增加形式化合规确认流程。

### 选型四 · 一次业务调用读哪一份配置

| 方案 | 优点 | 风险/代价 | 结论 |
|---|---|---|---|
| 每个出口临发前逐键重新读 | 看似最快反映修改 | 多图、工具第二回合、并发保存时可能跨服务,还会丢发送时来源 | 不选 |
| 长缓存client内固定配置 | 一次读取 | 换Key/地址后仍继续用旧值,用户难以验证热改是否生效 | 不选 |
| **操作开始读一份执行快照,每次发送检查revision仍有效** | 地址与Key不串版;后台/工具回合可清楚解释变更中止 | 变更会中止尚未发送的旧任务,用户需重试 | **选它** |

已发出的HTTP请求无法撤回,不承诺点击保存能收回在途数据。后续HTTP请求、候选和工具回合发现相关配置变更则停止,不能悄悄转入新服务。下次独立操作读新快照。

### 选型五 · 来源与缓存失效

| 方案 | 优点 | 风险/代价 | 结论 |
|---|---|---|---|
| 只改vendor短串或回看时查当前配置 | 不加元数据 | 长型号截断,改名后历史来源被重写;无法判断是否旧服务缓存 | 不选 |
| 换配置就删所有AI结果/清库 | 容易看到新结果 | 丢历史、触发隐式重算和用量,失败后原报告消失 | 不选 |
| **发送时存安全来源快照,复用时比较指纹** | 旧结果可读且不冒充新来源;不自动重算 | 增加可空元数据列及旧数据分支 | **选它** |

选定理由:来源是结果的属性,不是当前设置的属性。指纹不包含Key或Key的hash,换Key通过随机revision表示。已有财务事实、历史报告正文、确认后的导入均不改。

### 选型六 · 配置与模型的交互如何一致

| 方案 | 优点 | 风险/代价 | 结论 |
|---|---|---|---|
| 新开“自有服务”页面并直接填一个型号 | 初次配置短 | 主备/视觉另有一套入口,和四平台不一致 | 不选 |
| **同页共用卡片外壳及原三级模型表单,自有卡用独立服务保存** | 原来用户的操作路径不变;新服务仍先配连接、再选模型 | 表单要承认免认证及配置完整性,不能只判断有Key | **选它** |
| 所有平台合成一个超大表单 | 一次提交 | 又出现未选型号就存不了Key的历史死锁,失败也扩大 | 不选 |

### 选型七 · 探针与故障隔离

| 方案 | 优点 | 风险/代价 | 结论 |
|---|---|---|---|
| 保存时自动测,成功即标“全部可用” | 立刻有反馈 | 草稿/保存隐式产生用量,文字成功不能证明图片/工具 | 不选 |
| **用户显式测试已保存型号,健康按配置及能力区分** | 知道测了哪个服务/型号;改配置后没有虚假绿灯 | 需记录revision、形态、型号及时间 | **选它** |
| 为所有可能能力自动发一轮测试 | 覆盖多 | 要提交真实图片/工具,增加用量且仍无法证明任意型号 | 不选 |

## 三、系统概要设计

### 1. 整体设计思路

目录仍定义平台、系列和型号规则;连接配置解析从目录中分离。custom的地址和Key只存在于服务端私密配置及请求内目标对象中。统一解析服务负责“配没配好、这一轮去哪”,统一custom传输负责“允许连哪、如何实际发送”;业务prompt与财务计算保持原链。

```text
AI接入页 --服务POST--> CustomLlmConfigService --单行JSON--> family_runtime_config
         --模型POST--> 既有主备/视觉配置(校验同一configured规则)

文字分析 / 后台月报 / 截图扫描 / 本地Agent / 显式探针
  -> LlmExecutionSettings.load(familyId): 一次读全部已提交设置
  -> LlmTargetResolver: invocation + 同一私密快照 -> ResolvedLlmTarget
  -> LlmTestGate: 准备记录 / 最后发送保护
  -> custom: CustomEndpointPolicy -> 固定DNS -> CustomLlmTransport(OkHttp)
     内置: 原客户端/HTTP实现
  -> 原响应/业务校验 -> 结果 + 安全LlmSource -> 原页面/提示词面板
```

### 2. 领域模型设计

| 概念 | 定义与边界 |
|---|---|
| 自有服务位 | 平台code恒为custom,显示名可改;不是某厂商/系列,不按型号前缀猜平台 |
| 服务revision / 编辑token | revision在有效地址/认证/Key/内网许可变化时生成新UUID;editToken在任何保存内容变化(含名称)时更新,专供旧页面并发冲突检测。仅改显示名不使模型结果无效,旧结果仍保留发送时名称 |
| 执行快照 | 一次文字调用/一个Agent turn/一批截图扫描的完整设置、私密服务版本及主备/视觉坐标;不存会话、不序列化给浏览器 |
| ResolvedLlmTarget | 一次候选的端点、认证、型号、超时和版本;用普通final类封装,禁止record/Lombok自动toString或JSON序列化泄露Key/URL |
| LlmSource | 可持久化来源:platform、modality、完整model、发送时displayName、customRevision、selectionFingerprint;不含URL、解析IP、Key及其hash |
| configured | 内置平台=Key已配;custom=合法服务快照且BEARER有Key或显式NONE。只判本地完整性,不查网络、不代表连接成功 |

这些是连接元数据,不进入fact层、收益/目标公式、账户余额、流水或取期逻辑。定稿实施时同步AGENTS的L35/L37及新增连接不变量。

### 3. 代码架构设计

拟新增职责(类名可按既有包小幅调整,依赖方向不可反向):

| 类/位置 | 职责 |
|---|---|
| CustomLlmConfigService / service.config | 私密JSON解析、规范化、并发保存、DB/env/default三层;对外只给安全CardView或请求内snapshot |
| CustomEndpointPolicy / checkup.llm | URI语法、IP分类、受限目标、全部DNS答案验证,无业务prompt/Key |
| LlmExecutionSettings / checkup.llm | 从一次getAll的结果派生旧/新设置与目标;复用LlmSettings旧键承接规则,不能再逐键读缓存 |
| LlmTargetResolver / checkup.llm | 内置固定目标与custom目标的统一configured、resolve、selectionFingerprint |
| CustomLlmTransport / checkup.llm | 自有服务唯一HTTP发送位置;有限响应、TLS、禁止跳转、DNS固定、取消、保护计数;既有JSON/SSE解析器消费其响应 |
| CustomLlmClient / checkup.llm | 接LlmRouter客户端目录,复用文字请求构建/协议校验,不复制prompt或路由 |
| LlmSource / llmtrace | 不可变安全来源与序列化,同一对象随输出、trace、结果表传递 |

既有改动面:

- LlmCatalog增加连接kind与custom两种形态的显式系列;fixed平台仍有baseUrl/keyConsoleUrl,custom没有固定地址或申请链接。禁止业务调用直接用custom的Platform.chatEndpoint;由resolver处理。
- LlmSettings增加从给定Map派生的入口,原load对旧调用者兼容;主备重复沿用sameStrategy,custom无默认,比较完整ID区分大小写。custom型号只trim且空串才视为缺失,显式输入的字面型号auto保留并发送,不套用内置平台把auto转成null的旧约定;界面仍不给“自动型号”选项。
- LlmRouter内部候选带执行快照,可用性/文字发送/trace使用同一目标;LlmClient增加内部prepared调用入口,旧公开便利方法委托统一实现。AbstractOpenAiCompatibleClient提取可复用请求构建和响应验证钩子,固定平台的Key/参数也从本次快照传入,不能再次逐键读取;custom走新transport,四家HTTP实现不换。
- VisionLlmClient使用同一resolver;HoldingImportService在扫描开始固定视觉及文字配置,每图沿用该版本。不要用创建上传任务时的vision.model当实际发送型号;在真正发送/完成时写来源。识别全失败保留SCAN_ERROR,不能变成空持仓或“全部卖出”。
- LocalToolLoopRuntime从turn开始持有同一执行计划,仅custom分支走transport读取SSE;保留TrackingSink.delivered及既有工具分片重组,真实输出/工具执行后不重放。取消关闭响应和Call。
- AiModelController增加custom/service POST;key POST拒绝custom,不得用空Key间接清/改服务。模型保存及test POST共用configured与saved probe target。
- LlmSettingsView、_llm-settings.html、llm-settings.js复用#42外壳/数据目录,增加custom卡专有字段及校验;不复制三份型号级联。
- LlmHealthTracker、PromptTrace/Recorder/PeekView及各缓存消费者增加安全来源/版本判据;百炼托管的配置、凭据、模板及runtime不迁移。

### 4. 运行架构

仍为单体Spring Boot、单实例systemd/compose。无新进程、定时任务、入站代理或网络扫描。用户配置的localhost指应用实际所在环境;容器内不代表宿主机。

### 6. 数据架构设计

服务配置复用family_runtime_config,键拟为`llm_custom_service_secret`,同一行保存:

```json
{
  "version": 1,
  "revision": "opaque-uuid",
  "editToken": "opaque-edit-uuid",
  "displayName": "自有服务",
  "baseUrl": "https://gateway.example.com/prefix/v1",
  "authMode": "BEARER",
  "apiKey": "<仅服务端私密值>",
  "allowLocalHttp": false
}
```

JSON整体按私密字段处理,不因名字里有secret就认为所有日志路径都已安全。禁止JSON对象toString、raw绑定错误、请求日志或getAll直接进Model。数据库沿用当前Key存储边界:表内明文、数据库/备份权限保护;不虚称加密。页面只返回规范地址、认证、名称、掩码、许可及opaque revision,密码输入始终空。

读取顺序:DB有该行则整份为准;没有行才看`FINANCE_LLM_CUSTOM_SERVICE_JSON`整体环境值,再无则未配置。NONE的空Key不能触发环境Key回退;非法/未知版本配置明确不可用,不悄悄回落到别家。环境仅供可选启动预置,首版无新增必填服务器配置;预置的revision/editToken在启动时一次生成并保持稳定,不能每次读取随机生成或以Key散列派生。whole JSON不能被拆成分别fallback的URL和Key。

保存事务:

1. 从me取得familyId,在family行上`SELECT id ... WHERE id=#{familyId} FOR UPDATE`串行化服务/模型的这两条设置写路径,不依赖内存锁。找不到家庭则失败。
2. 回读当前服务及主备设置,比较服务表单expectedEditToken(含env预置版本);旧页面冲突给“配置已更新,请刷新后重试”,不能盲覆写。模型表单另带customRevision,只核对连接身份,改显示名不阻止保存型号。
3. 解析并规范化全部字段,验证改地址/认证的新Key规则;任何错误均不写。新Key长度上限8192、无CR/LF/控制字符;NONE丢弃旧Key,将来转回BEARER必须重新填。
4. 地址比较使用同一规范URI(去尾斜杠、标准主机/端口表达),路径变化也算换地址;不把HTTP/HTTPS或不同端口视为同一服务。
5. 全部通过后单行upsert,审计只记录custom、操作类型和成功,无Key/URL/原始JSON。事务提交后才清私密快照缓存/更新可用性视图,回滚不能向并发请求发布半份配置。

执行读取一次SELECT取得整个家庭runtime配置,在该Map上完成旧键派生、参数和自有服务解析,不在拼装中调用多个5秒缓存getString。只有服务/模型写路径需要锁,网络请求不持有DB锁。每个custom HTTP发送前新查相关配置版本,变化则中止旧操作;这个检查与socket发送之间仍有极短竞争窗,已开始发送的请求归属于原快照,不混Key。

历史来源拟增加**一份新迁移**(当前编号到V80,实施时重新分配):

| 表 | 变化 | 旧行处理 |
|---|---|---|

不新增表、不改变原短列长度/语义。新custom的旧vendor/vision_model只写稳定短标识custom,完整ID只能从source_json读取;其它平台仍兼容旧展示,有新元数据时优先使用。多图和多候选的安全来源可记录有界数组,按实际发送先后追加,每项同一结构,不能把未发送候选写成已用来源。结果自己的元数据不依赖prompt记录90天后仍存在。

| 截图导入→异步扫描→确认 | VisionLlmClient→custom transport | 独立型号、原图/草稿保留、全失败SCAN_ERROR、人工确认不变 |

实施前用rg枚举所有HTTP模型发送及缓存命中点,和该矩阵核对;未来新增出口也必须遵守同一resolver/policy/gate。

### 2. 对外接口

无新增公开API/MCP/Webhook。仅增加登录态、当前家庭作用域、既有CSRF保护下的管理POST:

| POST | 入参 | 回执 |
|---|---|---|
| /admin/ai-access/llm/custom/service | displayName、baseUrl、authMode、apiKey、allowLocalHttp、expectedEditToken | 校验/冲突失败回原卡,保留经过过滤的非敏感草稿;成功只说明保存,不测连接 |
| /admin/ai-access/llm/models(既有) | 原三组坐标及参数,增加customRevision | 原子保存模型组;有custom时核对当前服务版本,服务没配好直接定位配置卡 |
| /admin/ai-access/llm/test(既有) | platform=custom | 只用已保存执行快照;源版本/型号/形态/时间匹配的本次结果 |

认证权限与原管理页一致,不发明新角色。非法URL里夹的用户名密码/查询不反射进错误文案或flash草稿。校验消息绑定字段key,服务端与JS规则对应;没有JS仍能安全保存合法值。

### 3. 我们调用的上游接口

只支持`POST <规范Base URL>/chat/completions`。不请求/models、不猜/v1,不自动改/Responses,不因型号名换协议。正文使用Jackson,不拼接JSON字符串。

本轮桩的脱敏实测示例(域名、Key、型号均为合成值,端口以临时分配值替代):

```http
POST /prefix/v1/chat/completions HTTP/1.1
Host: gateway.invalid:<临时端口>
Authorization: Bearer fixture-token
Content-Type: application/json

{"model":"Org/Model:version","messages":[{"role":"user","content":"synthetic ping"}]}
```

桩实际返回并经JSON解析的响应:

```json
{"choices":[{"message":{"content":"ok"},"finish_reason":"stop"}]}
```

另测NONE时Header不存在;SSE桩返回`data: {"choices":[{"delta":{"content":"ok"}}]}`及`data: [DONE]`。它们是传输实验报文,不是某家真实模型回包。

业务协议沿用:

- 文字system/user messages、temperature、max_tokens;画像/数学已由既有工程层确定。HTTP200必须无顶层error、有非空choices/message/content,然后再经该业务既有JSON/白名单/数学禁算校验。
- 图片使用原有data URL,并补齐PNG/JPEG/WebP文件头校验(实施复核发现存量代码只有浏览器MIME声明校验);不发送可由上游继续抓取的图片外链,不承诺模型能识别合成实验中的占位图片。
- 工具流保留stream、tools、tool_choice及原role/tool_call_id。只有完成有效SSE流且满足原产出合同才成功;EOF缺结束、网页、error事件、空流、畸形tool JSON均不能报成功。

**URL与网络规则(已实现,以本地桩和纯策略测试验证)**:

1. 使用URI与OkHttp HttpUrl结构解析并交叉检查规范结果,拒绝两者解释不一致的输入。限制Base URL长度2048、绝对HTTP(S)、明确host、合法1–65535端口;拒绝userinfo/query/fragment、控制字符、反斜杠、zone-id、不标准数字IP、编码斜杠/反斜杠及点路径段。IDN经STD3规范化,不把任意字符串交给宽松IP解析器。
2. 保留路径与端口,只去尾斜杠;拒绝完整chat/completions或responses后缀。追加固定子路径前不使用会丢prefix的URI.resolve("/...")。对原始/编码形式作一致检查,最终端点在管理页明确展示,不放到来源或通用日志。
3. 保存时**不解析DNS、不连接**。发送前在同一策略中解析A/AAAA,集合为空/失败明确拒绝;所有答案都须允许,混入一个禁用地址则整次拒绝。IPv4-mapped IPv6先统一成IPv4分类,不能绕过规则。
4. 默认仅HTTPS公网单播;显式allowLocalHttp才增加HTTP、RFC1918、IPv4 loopback、IPv6 ::1及ULA。link-local、unspecified、广播/组播、保留/文档/benchmark/非正常公网特殊用途段始终拒绝;基于IANA注册表将允许的内网类与其余special-use区间显式区分,不只依赖isSiteLocalAddress。
5. 始终拒绝IPv4 link-local(覆盖常见169.254元数据)、CGNAT100.64/10(覆盖已知100.100元数据)、IPv6 link-local及特殊目标。集中拒绝表至少含`168.63.129.16/32`、`fd00:ec2::254/128`及`metadata.google.internal`、`metadata.goog`、`instance-data.ec2.internal`(含子域),主机名先去尾点/归一大小写,地址用纯字节CIDR测试,不访问元数据验证。其余特殊用途段依据IANA表固定进实现和样本;私网许可不覆盖拒绝表。该边界不宣称识别任意自建服务后面的转发目标。
6. 每个HTTP请求使用专用OkHttp client/pool,自定义Dns只返回已验证的地址集合且拒绝其它hostname,强制Proxy.NO_PROXY、HTTP/1.1、followRedirects=false、followSslRedirects=false、retryOnConnectionFailure=false、无cookies/认证协商/系统代理。原hostname保留用于Host/SNI/证书校验;不改成IP URL、不使用trust-all。这样不复用其它revision/hostname的连接,也没有HTTP2合并连接绕过DNS校验。
7. LlmTestGate.beforeSend先于DNS/连接,发送边界再检查一次。每次真正尝试按既有observedSend语义计数,被保护阻止不计发送/失败/熔断。模型传输不做隐藏重试,候选切换仅由现有router决定。
8. custom连接5秒、读写使用现有保存的timeout(5–120秒);整个单次HTTP请求同样设callTimeout防慢速滴流。DNS在有界执行器中限时5秒、队列满拒绝,不能无限堆积不可中断系统解析线程。响应关闭即evict专用pool;不为每个请求创建长期线程池。同步Call、共享有界dispatcher,取消和异常路径同样释放。
9. 非流响应上限2MiB、错误正文只读16KiB、SSE单事件128KiB/累计4MiB,超限固定报协议响应过大。使用流式有界读取,不能先readAllBytes再判断。关闭透明压缩并按实际读取字节限制,不让压缩响应绕过上限。图片请求沿用原上传体积限制。

失败类型集中定义:CONFIG、URL_POLICY、DNS、CONNECT、TLS、AUTH、PERMISSION、MODEL、RATE_LIMIT、TIMEOUT、PROTOCOL、RESPONSE_TOO_LARGE、CONFIG_CHANGED、BLOCKED。HTTP404可能是前缀/路径或型号,custom提示同时核对Base URL与型号,不武断标成Key错;401/403/429等按状态和有限错误码归类。错误码白名单之外的message不原样显示/记录。

custom原始IOException、上游body和URL在transport内转成固定异常,**不附带原始cause**进入会toString的上层。日志仅平台custom、revision短标识、状态/分类、长度、耗时;禁止HTTP wire logging、Key、URL、图片与prompt。这里采用本项目现行隐私护栏,覆盖TDD模板泛称“日志保留上游原话”的要求。

实施核对发现开发配置默认对com.family.finance开启DEBUG,MyBatis会继承该级别打印参数。FamilyRuntimeConfigMapper及PromptRecordMapper显式固定INFO(包括dev profile),防私密JSON与prompt进入SQL日志;路由健康/业务失败回调同样只传安全分类,不附原异常cause。

## 五、稳定性与质量保障

### 1. 兼容性设计

未配置/未选custom:四家固定平台默认/轮询、私密键、主备及视觉保持原合同,不改变默认值/基线prompt。目录custom可见禁选,配置卡数量从目录推导,测试不写死分母。旧三元组、老qwen/deepseek键承接不变,custom永不被旧键派生出来。

当前版本遇到custom配置不完整:必须显式提示并不可用,不能退成百炼主选。回滚旧jar前必须将主备和视觉显式改回旧jar认识的内置平台,不能假设它认识custom。JSON及新增可空来源列可留库,无需删除历史数据。

custom可用性:

- 独立于内置平台,状态按family+serviceRevision隔离。账户级401/403等使该服务版本进入原短冷却;网络/单型号/协议等失败按revision+modality+model冷却,不因主选A型号失败跳过同服务不同B型号。
- 相同custom完整型号不可同时作文字主备;不同型号可作主备。视觉失败不走文字备选;连接文字测试不改变视觉/工具健康判据。
- 成功状态含revision、实际model、形态、时间。修改相关配置后新视图为未测试;旧在途请求完成只更新旧版本。BLOCKED单独显示“测试环境 · 未调用”,不染绿或熔断。
- CONFIG_CHANGED和BLOCKED直接结束旧计划,不进入失败/熔断计数也不再切下一候选;普通上游失败仍按原主备规则处理。健康汇总只取当前选定的有效revision,不能把历史服务故障永久累加到“全部不可用”。

缓存与历史矩阵:

| 消费者 | 新服务配置后如何读旧结果 |
|---|---|
| LlmDiagnoseService内存缓存 | 请求cacheKey加入相关selectionFingerprint;旧版本不能命中,只在原显式/既有业务触发下产生新调用 |
| RebalanceAdvisorService缓存 | source_json指纹匹配才可作为当前建议复用;旧建议保留可读/标旧来源,不改计划或划转 |
| ReviewInsightService封板复盘 | 原正文保留、来源标历史;显式“重新解读”才替换,失败保留原文,不能因保存服务自动重算 |
| GoalReportService月报/预警 | 原财务contextFingerprint不改;并列比较来源指纹,展示历史提示。保留旧报告/未确认预警,生成触发及失败反馈照旧 |
| 账户/持仓AI标签、行业分类及基金穿透缓存 | 已落地分类/穿透为既有已采用结果,不因连接变更重打标或清空;以后新请求通过同一执行计划记录来源 |
| holding_import/ask_message | 已确认/已展示的结果不改;多图/工具同一操作的未发后续回合发现配置变更即停,不跨服务续传 |

selectionFingerprint为规范主备/视觉坐标、必要运行参数及相关customRevision的SHA-256,不含Key、URL、显示名或当前时间。仅当当前选择或结果来源涉及custom时启用新比较,从未用custom的原平台缓存行为不变。没有source_json的老结果在custom模式下不能被说成该服务生成;没有来源时写“旧版记录,未保存完整来源”,不推测。

### 2. 性能评估

新增量仅AI准备时一次整组配置读取、每个custom HTTP发送前一次版本核对和DNS;财务页面/纯规则计算不新增查询,管理页configured不访问网络。等待期间不持DB锁。custom每次单独握手是为固定地址集合付出的有限延迟,模型调用本身仍受已保存超时约束。DNS执行器固定2线程、等待队列4项,溢出直接安全失败;生产请求并发压测及取消后线程/FD无增长纳入验收。

JSON来源按结果/请求写入,没有全表扫描或历史回填;显示历史时沿既有结果读取,不能为每一行再查当前设置。验证实际查询数量、取消、连续调用后的线程/连接数,不能只凭“代码少”认定性能没影响。

### 3. 安全性设计

认证和地址只进私密服务对象,不进prompt、工具输出、通用配置JSON、source_json、公共截图、flash、错误堆栈或审计。服务卡是现有权限内唯一可见地址的位置;型号目录JSON只传code/系列/型号规则和安全label。密钥只在服务端HTTP Authorization中按BEARER发送,NONE完全不带头。

原分析材料的成员/账户代号与AI正文隐私处理仍经AnalysisPromptBlocks、AccountCodenames、@aiText.priv/privText。Agent工具结果不承诺无真实名称,图片不承诺自动遮挡。测试探针仅固定文字,不复用业务材料。新增URL策略不允许Agent填网址或任意访问网络。

服务配置JSON继承备份敏感性,不能把运行环境值写入新文档/测试fixture。所有样本仅example.com、.invalid、随机端口与虚构Key。上传类型继续按实际魔数/既有大小限制,不因为自定义视觉平台放宽。source_json所有写SQL带family过滤,ask归属继续JOIN会话;页面读其它家庭记录继续拒绝。

## 八、成本测算

自有服务没有统一价表,本项目不编造每月金额。业务操作次数、提示词/图片大小、主备失败、工具回合数决定上游计费。记N为每月业务调用次数,R为平均实际HTTP回合(含允许的主备),Pin/Pout为服务每百万token价格,Tin/Tout为每回合tokens:

`月度费用 = N × R × (Tin × Pin + Tout × Pout) / 1,000,000 + 图片/服务固定费用`。

显式探针最多一次短文字请求,不含家庭数据;保存服务/型号、开页面和旧报告回看为0次模型请求。本地模型Pin/Pout可能不计费,仍有维护者自身机器成本,不是平台免费承诺。R从1变2时费用可能近似翻倍,所以不开隐藏HTTP重试、不全能力探测。因用户未给服务价表,单价/每月N均未知;管理提示只说可能产生少量用量,不显示虚构费用。
