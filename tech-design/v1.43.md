# v1.43 · 退休可支用资金净额 · 技术设计

> 状态：技术设计已确认，进入实现与 beta 验证。对应 [PRD](../prd/v1.43.md) FR-1491 至 FR-1494。
> 基线：已发布的 `v1.42.1`；不重做 AI 洞察、不更换模型、不改账面数据。

## 零、前置检查

本次没有第三方新依赖。已核对三处现行代码：`RetirementDataService.load` 已按家庭当前账户汇总金融资产及全部负债；`RetirementPlanService.View` 当前将 R2 的毛额和含债需求交给目标消费者；`RetirementPlan` 已用 `@JsonIgnoreProperties(ignoreUnknown = true)` 读取保存的方案。

| 静默失败 | 守护 |
|---|---|
| 净额分子已经扣债，分母又含负债 | 同账本切换毛额与净额，断言资金缺口、可生息本金及预测结果不变 |
| 把未知的外币负债当成零 | 核对每个纳入账户的本位币余额；未知则标出原因并暂停净额进度及两种预测 |
| 概览改了，仪表盘、报表、导出仍解释原公式 | 对所有消费端断言同一口径；禁止模板或客户端再从账本计算 |
| 老程序把新口径误读为自选账户 | 用上一版模型读实际生成的 JSON，核对同一组金融账户及原毛额 |

## 一、需求分析

| FR | 工程判据 |
|---|---|
| FR-1491 | 新建 R2 默认为净额；只有显式保存才更新已有 R2。旧全家 R2、自选 R2、R1 及未采用退休生活账的目标保持现状。既有 R1 的升级草稿不改变既定的资金选择逻辑 |
| FR-1492 | 两个全家选项共用金融账户筛选。负债独立遍历全部有效负债账户，不受资金勾选、账户归属成员、不参与配置分析或固定还款配置影响；缺余额或汇率逐项点明 |
| FR-1493 | 同一账期、本位币按分精度确定毛额 A、债务 D、生活本金门槛 T 和准备金 B。净额进度用 A−D 与 T+B，允许负净额；毛额保留 A 与 T+B+D。两者短缺均为 max(T+B+D−A,0)，积累起点均为 A−D−B |
| FR-1494 | 草稿、保存回读、目标详情、列表、仪表盘、报表目标条、导出和既有解读都消费服务端结果；预测日期及积累路径在完整数据下不因切换口径而改变 |

## 二、关键选型

| 决策 | 备选 | 采用理由 |
|---|---|---|
| 保存口径 | JSON 新选项替换 `scopeMode`；新增列；在保留 `scopeMode` 的 JSON 中附加可选字段 | 附加 `netOfLiabilities`，只在全家净额且为真时序列化。直接扩展旧枚举值会使旧版验证失败、甚至误走自选；新增列对用户没有收益。本方案不迁移、不回填，旧版仍读出全家毛额 |
| 计算口径 | 各页各扣一次；重定义家庭净资产；退休结果给出唯一的进度口径 | 由退休计算器产出同一份资金结果，消费者读取。家庭净资产、现金流及账户收益不变，避免列表和详情各算一套 |
| 输入不全 | 未知按零；完全隐藏已有余额；显示已知小计、暂停依赖完整余额的计算 | 采用第三种。已知资产、负债仍可查看并注明未齐，避免把少扣的债显示成已达标；不阻止保存方案 |

## 三、系统概要设计

1. `RetirementDataService` 仍以家庭的同一当前余额切片为准；继承既有有效账户、合格金融账户及账期延续规则。两种全家口径共享检查；负债按 `AccountType.isLiability()` 识别，消费已有本位币换汇结果，按欠款余额取正值，不重复换汇或反转符号。已登记且可信的零视为完整；有余额但缺必要换汇、换汇不一致、缺余额且无可沿用记录均为未知，与配置校验分开。
2. 在 `RetirementCalculator.Result` 回传同源资金结果：展示口径、进度分子与分母、完成度、缺口及是否完整。保留 A、D、B、T 和生息本金供构成、公式及预测引用。前端只控制显示；超过 100% 或低于 0% 的数值照实表达，进度条限定在 0–100%。零门槛不做除法，完整数据下可判断达标；无有限门槛不能显示成零。
3. 净额缺资产或负债来源时展示已知小计，不将 A−D 暂估值当作正式进度输入。共享进度、缺口、达标状态、预计达成时间和投资积累预测均降级，正常的说明与保存入口保留。毛额、自选及 R1 仍采用发布版缺失处理。
4. `RetirementPlanService.View.progressAssets/progressTarget` 从上述结果读取，`GoalProgressService`、`GoalForecastService`、`GoalProgressSummary` 与 `RetirementController` 沿用这一链。继续使用既有 `goal-estimate` 和 AI 片段；不引入第二套展示结构。历史报表保留既有取期规则，不把今日预计日期带入封板。

## 四、接口协议设计

- 不新增端点或表。退休计划新建、修改、预览用现有表单提交；「家庭资金」选择毛额、净额或自选，服务端拒绝未知选项。预览不保存；正式保存将选择映射到既有 `scopeMode` 与附加字段。换成毛额或自选时清除净额字段，保留已勾账户。新建默认与旧方案读取分别处理，不以字段缺省推断净额。
- 所选范围、已知负债、完整性、负净额与临界状态均由服务端渲染；切换币种只换展示金额，完成度不变。说明及导出使用对应公式，金额仍走隐私保护。
- 仅净额方案向既有解读补充正确的分子、分母与数据状态；不改生成入口、校验器及触发条件。保存后口径进入既有上下文指纹，既有解读保留并标历史；毛额或自选不因新字段默认值导致无意义的指纹变化。

## 五、稳定性与质量保障

- 复用一次账户读取和换汇，不按账户增加查询，不引入外部请求或异步处理。新/旧用户均可不改账目切换公式；不得重新归类、改余额或更改费用处理。
- 合成用例：A=500 万、D=100 万、T+B=800 万。毛额 500÷900、净额 400÷800；都缺 400 万。验证小数分舍入、负净额、真实零余额、有债/无债、缺汇率、延续余额、归档账户及跨成员/跨币种债务。
- 回归新增选择不能影响教育、应急、其他目标、仪表盘账户总量及现金流。验证旧方案前后关键值和已有 AI 文案一致；净额资料不足不提供误导性结果。

## 六、护栏设计

| 风险 | 预定验证 |
|---|---|
| 负债遗漏、重复扣除或舍入后缺口改变 | 退休数据服务、计算器、目标预计达成单测；完整数据下毛/净预计月份与同一积累路径相等 |
| 存量默认被改，或老版本无法读计划 | 新旧 JSON 样本来回读写；旧版读取新计划时仍显示全家毛额；新版本不改动旧方案 |
| 保存和跨页根本用的不是同一口径 | 新建、预览、保存、重开、再切回毛额；核对详情、列表、仪表盘、报表目标条、导出及服务端数值 |
| 数据提示、负数、隐私或手机操作退化 | 现有目标浏览器 flow 加合成数据，桌面和 390/320 像素实际点击并核对截图；保留历史解读、模型发送 0 |

同步 `docs/qa-cases.md` 和项目静态守护；全量单测、受保护的浏览器回归、Maven 与 Chromium 串行。本阶段未运行真实模型。

## 七、上线与回滚方案

无数据库迁移。先在 beta 验收三种资金范围、回读和未知数据处理；生产仍走单独发版。现有方案保存审计继续记录操作，资金取数缺失面向用户显示，不记录私密余额或 AI 正文。

用户可切回毛额，不反写账面。回滚到 v1.42.1 时旧版忽略可选字段、显示毛额；只读旧版再升级应恢复净额选择。旧版若重新保存该计划，会丢掉它不认识的附加字段，重新升级后需手选净额，其他方案与账目仍保留。用上一版真实或编译出的模型验证该边界，不只依赖注解推断。
