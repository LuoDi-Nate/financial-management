## 一、需求分析

### 1. 背景 & 目标

见 PRD §0。技术上的主线一句话:**页面打开以后宽度还会变**。以前只有手机转屏这一种情况,而且有专门处理;iPhone Duo 让「同一页面在 382 和 951 之间来回变」成了日常操作。

### 2. 需求理解(验收口径)

| FR | 工程判据(可判定) |
|---|---|
| FR-1370 | 在 382×580 / 466×650 / 469×589 / 669×890 / 951×589 / 951×669 六个尺寸(触屏)从顶栏点进五个主页面:`scrollWidth − innerWidth ≤ 1`;按钮 `scrollWidth ≤ clientWidth + 2`;678×400 走现有手机横屏处理,与 390×844 转横屏表现一致 |
| FR-1371 | 951×589 打开 → 改成 382×580 → 改回 951×589,每一步等 1 秒后:①整页不横滑;②每个 Chart.js 画布宽度 ≤ 父容器宽度,每个 ECharts 内部画布宽度 ≤ 容器宽度;③依赖宽窄形态的图换成了新形态(例:仪表盘账户分布图的标题,宽屏带「资产 → 右 / 负债 → 左」,窄屏不带);④变化前离视口顶部 ≤ 120px 的那一节,变化后仍在顶部 ±40px 内;⑤输入框里没提交的值不变;⑥变宽以后筛选条可见 |
| FR-1372 | 951 宽:顶栏汉堡菜单可见,整排导航不出现;顶栏高度与 382 宽时同一档(不折行) |

| FR-1374 | 同一登录开两个 469×589 的页签:A 填报保存,B 刷新后看得到;两边都能正常提交(不出现 CSRF 失败) |
| FR-1375 | 前端只有 `mobile-guide.js` 读 `navigator.userAgent` |

## 二、关键选型

### 选型一 · 宽窄形态翻转后,图怎么换成新形态

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 越过断点就整页刷新 | 一定对 | 丢滚动位置、丢没提交的表单,正好违反 FR-1371 | 不选 |
| B | 越过断点就重新请求含图的 HTMX 片段 | 图按新宽度在服务端重出 | 多一次网络往返;整块闪一下、高度变化又把滚动位置带跑;资产透视的旭日图不是片段渲染的,还得另做 | 不选 |
| **C** | 越过断点时派发一个 `vpchange` 事件,三处依赖宽窄形态的图各自订阅、用手上已有的数据重画(和现有的 `fontscalechange` 同一套做法) | 仪表盘、归因不走网络;资产透视旭日图沿用隐私开关的重画入口,会重新查一次(只读);都不闪;只重画真正依赖形态的三处;字号档位切换顺带也能让仪表盘的图跟上 | 三处图要把「建图」包成可重复调用的函数 | **选它** |

**选定理由**:用户感知得到的只有「折叠那一下会不会闪、会不会跳、填了一半的会不会丢」,C 在三项上都最好。B 的闪烁和滚动跳动正是这一版要消灭的东西。

### 选型二 · 网格被画布撑宽

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 全局 `.grid > * { min-width: 0 }` | 以后新写的网格也自动不会被撑 | 动到全站所有网格,包括本来就按内容宽度排的;改动面不可控 | 不选 |
| **B** | 10 处只写了宽屏列数的网格补上 `grid-cols-1`,加护栏禁止再出现 | 每处窄屏列定义清楚;只动有问题的地方 | 要逐处改 | **选它** |
| C | 只给图表容器加 `min-w-0` | 改动最小 | 治不了别的会撑的内容(长表格、长代码);同一个坑换个形式还会再来 | 不选 |

### 选型三 · 正在看的那一块怎么留在原处

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 靠浏览器的滚动锚定 | 不写代码 | 实测 Chromium 在视口宽度变化时不保位置(§零);Safari 27 的说明里也只讲插入内容 | 不选 |
| **B** | 滚动时记下视口顶部最近的、带 `id` 的区块和它离顶部的距离;宽度变了之后滚回去。节奏照 `landscape.js` 的 `restoreAnchor`(两帧后 + 160ms + 400ms 各做一次,因为 Tailwind 重新编译和图表重排都是异步的) | 和手机横屏处理同一种做法,已在线上跑过 | 带 `id` 的区块不够密时只能还原到最近一节 | **选它** |
| C | 不处理 | — | PRD FR-1371 明确要求 | 不选 |

各分析页的长文目录本来就给每一节挂了 `id`,所以「最近一节」的粒度在仪表盘、报表、体检页上足够。

### 选型四 · 筛选条在变宽之后

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 宽屏也显示「展开」按钮 | 简单 | 电脑上凭空多出一条折叠条,改变所有电脑用户看惯的样子 | 不选 |
| **B** | 越过 768 变宽时把收起的筛选条展开;变窄时不自动收起 | 电脑和普通手机首次打开都不变;变窄时不收,内容不会从手指底下消失 | 外屏上会多看到一段筛选条,手动收起即可 | **选它** |
| C | 窄屏也不再自动收起 | 不会出现这个问题 | 回到 v1.6 之前手机上筛选控件占一整屏的样子 | 不选 |

### 选型五 · 这些逻辑放哪

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 继续加进 `landscape.js` | 重排和锚点代码就在那里 | 那个文件管的是「手机横屏冻结旋转」,职责会混成两件事;它的逻辑大部分只在触屏横屏时启用 | 不选 |
| **B** | 新文件 `static/js/viewport.js` 管「页面打开后尺寸变化」,`landscape.js` 的图表重排改为调用它 | 一个文件一件事;重排只剩一份实现 | 多一个脚本请求(有缓存,可忽略) | **选它** |
| C | 写进 `layout.html` 的内联脚本 | 和 `vpNarrow` 挨着 | `layout.html` 已经很长,内联脚本也没法单独缓存 | 不选 |

## 三、系统概要设计

### 1. 整体设计思路

```
window resize ──(停止变化 150ms 后)──┬─ 宽或高变了 ─────→ vpRelayoutCharts()
                                     │                    Chart.js:按父容器给尺寸 resize(w,h)
                                     │                    ECharts:resize()
                                     │                    (两帧后 + 180ms + 420ms 各一次)
                                     ├─ vpNarrow(640) 或 vpNarrow(768) 结果翻转
                                     │    → 派发 'vpchange'(detail: 新旧两档的结果)
                                     │         ├ 仪表盘 _region:销毁 5 张图 → 用已有数据重建
                                     │         ├ 归因 _attribution:__attrBoot()(和字号档位同一个入口)
                                     │         ├ 资产透视 lens.js:renderSunburst()
                                     │         └ viewport.js 自己:变宽时展开收起的筛选条
                                     └─ 宽度变了,且手机横屏处理没在切换 → 滚回记下的那一节

scroll ──(节流 100ms)──→ 记下视口顶部最近的带 id 区块 + 离顶部的距离
```

### 2. 领域模型设计

不适用 · 不涉及业务概念。前端新增一个全局事件 `vpchange`,和已有的 `fontscalechange` 并列成「要求图重画」的事件,定稿后写进 `AGENTS.md` 的联动链:**新写的图如果读了 `vpNarrow`,必须订阅 `vpchange`**。

### 3. 代码架构设计

| 文件 | 改动 |
|---|---|
| `static/js/viewport.js`(新) | `window.vpRelayoutCharts()`(从 `landscape.js` 搬来)· 防抖的 resize 监听 · 宽窄翻转检测与派发 `vpchange` · 锚点记录与还原 · 变宽时展开筛选条 |
| `static/js/landscape.js` | `relayoutCharts()` 改为调 `window.vpRelayoutCharts()`;切换前后设一个时间戳,`viewport.js` 在这段时间里不碰滚动 |
| `fragments/layout.html` | 在 `landscape.js` 之前引入 `viewport.js`(都是 `defer`,顺序保住) |
| `dashboard/_region.html` | 5 张图的建图代码包进 `boot()`;单次绑定 `vpchange` 和 `fontscalechange`(照 `_attribution` 的 `window.__xxxBoot` 写法:HTMX 换片只换指针,监听不累加);重建前 `destroy()` 旧图 |
| `dashboard/_attribution.html` | 已有的 `fontscalechange` 监听旁边加一行 `vpchange` |
| `static/js/lens.js` | `boot()` 里订阅 `vpchange` → 旭日图已建过就 `renderSunburst()` |
| 10 处网格模板 | 补 `grid-cols-1` |
| `scripts/e2e/lib/browser.cjs` | 加一个「指定尺寸的触屏页面 + 原地改尺寸」的帮手(现有的 `ui.phone` 只有 390×844) |
| `scripts/e2e/flows/55-iphone-duo.cjs`(新) | 见 §六 |

**明确不动的**:

- `flow-table.js` 按 640 决定每页 5 行还是 10 行:只影响分页行数,不会走样。
- 填报页窄屏收起的账户行:宽屏时「展开」按钮仍在,能点开。
- 资产打标页的「手机自动转横屏」:只在首次加载时判断。

这三处变宽变窄后保持原样,不处理。

不会产生第二条求和路径:只动展示层,不碰任何取数。

## 五、稳定性与质量保障

### 1. 兼容性设计

- **电脑和普通手机打开页面时**:所有新逻辑都只在「打开以后尺寸变了」时触发,首次渲染不变。补 `grid-cols-1` 在窄屏上与原来的单列等价,宽屏不受影响(宽屏有 `md:` / `lg:` 列数覆盖)。
- **普通 iPhone 转屏**:高度 < 480 仍算窄,宽窄不翻转,不重画;锚点在手机横屏处理切换期间让路。e2e 竖 → 横 → 竖走一遍,与当前版本对比。
- **电脑拖窗口大小**:会跟着重排 / 重画,这是顺带的改进。
- 回滚到旧 jar 时一切回到现状,没有数据残留。

### 2. 性能评估

尺寸停止变化 150ms 后才处理,拖窗口时不会连续重画。重画只在越过 640 / 768 时发生,一次折叠最多一次。仪表盘 5 张图重建在本机实测约几十毫秒量级(实施时用 e2e 量一次,写进本节)。

### 3. 安全性设计

不适用。重画走的是同一段建图代码,金额标签照旧在建图时读隐私模式状态,所以隐私开着时重画出来的也是打码的。e2e 全程在隐私模式下跑。

## 六、护栏设计

| 护栏 ID | 守的设计意图 | 判据怎么写 |
|---|---|---|
| `v136-GRID-BASE-COLS` | 窄屏下网格的列都能缩,不会被内容撑宽 | 模板里凡是 `class` 同时含 `grid` 和 `sm:/md:/lg:/xl:grid-cols-N` 的,必须也有不带前缀的 `grid-cols-*` |
| `v136-VP-CHARTS-SUBSCRIBE` | 依赖宽窄形态的图,宽窄一变就跟着重画 | 一个文件里既读了 `vpNarrow(` 又建了图(`new Chart(` / `echarts.init(`),就必须出现 `vpchange` |
| `v136-NO-UA-LAYOUT` | 布局只看宽高,不认设备 | 前端脚本和模板里读 `navigator.userAgent` 的只能是装 App 引导这一个文件 |
| `v136-E2E` | 折叠场景有真浏览器覆盖 | e2e 有 `55-iphone-duo` 且带清理函数(护栏 v1230 要求) |

**e2e `55-iphone-duo`**(第一步不直接打开功能页,从首页点进去;每步同时断言页面和库):

1. **五种姿态**:每个尺寸从首页点汉堡菜单进仪表盘 / 填报 / 账户 / 报表,断言不横滑、按钮不截字。951 宽时断言是汉堡菜单。
   → 库:仪表盘「本期还有 N 个账户未填」的 N 等于库里本期未提交的账户数(证明这一屏取数正常)。
2. **折叠仪表盘**:951 宽进仪表盘 → 滚到「人赚 vs 钱赚」→ 改成 382 → 改回 951。每一步断言 FR-1371 的六条:
   - 账户分布图的标题在宽、窄两种形态间切换;
   - 每个画布只有一个图实例;
   - 筛选条可见,而且勾选的账户数等于库里该家庭未归档的账户数。

## 附录一 · 实施中的发现(2026-10-20)

设计时没料到、实测才撞上的四件事。每件都改了实现,没改设计方向。

### 1. 布局里多加载了一份 Chart.js,先建的图一直「找不到」

**症状**:第一次跑折叠检查,仪表盘、报表的画布 `Chart.getChart` 全部返回空,显式重排对它们不起作用。

**根因**:带图的页面在 body 顶部同步引一份 `chart.umd.min.js` 再建图;`layout.html` 为超级 Agent 抽屉又无条件 `defer` 引了一份(v1.19 起)。
defer 的那份在页面建完图之后执行,把 `window.Chart` 换成了第二份 —— 两份各有各的实例表,先建的图登记在第一份里。
所以不止这一版:手机整页横屏的显式重排(`landscape.js`)、隐私开关的 `chart.update`(`layout.html`)对这些图**从 v1.19 起就一直没生效**,
只是 Chart.js 自带的 ResizeObserver 兜住了大部分情况,没人发现。

**修法**:布局里改成「页面没带才补」(`if (window.Chart) return;` + 动态插入、`async=false` 保住先后)。超级 Agent 只在出图那一刻用 `window.Chart`,晚到不影响。

**护栏**:`v136-VIEWPORT` 断言布局里没有无条件引 Chart.js 的 `<script>`。

### 2. ECharts 必须在 resize 当帧就缩

**症状**:从内屏合到外屏,`innerWidth` 停在 898 而不是 382,宽窄没翻转,图也没换形态。

**根因**:手机浏览器在内容比视口宽时会把布局视口放宽去装它。ECharts 没有 ResizeObserver,画布停在 882px,在防抖(150ms)到期之前,布局视口已经被它撑到 898 ——
之后再量,容器被撑宽、`vpNarrow` 也判成宽屏。Chart.js 的 ResizeObserver 在同一帧内就缩了,所以只有 ECharts 有这个问题。

**修法**:`resize` 事件里宽度一变就同步 `ec.resize()` 一次,防抖后再按完整节奏重排。

### 3. 折叠屏折叠会触发「转向」事件,被手机横屏处理误认

**症状**:锚点记对了,但折叠后没有还原。

**根因**:内屏横(951×589)合到外屏竖(382×580)时,屏幕方向从横变竖,`landscape.js` 的 `onTurn` 被触发并打了时间戳,`viewport.js` 以为是手机转屏、让了路。

**修法**:`onTurn` 只在冻结旋转参与(进或出)时才打时间戳。另外,宽窄翻转时(比如内屏横着合到外屏横着,会进冻结旋转),由 `viewport.js` 按章节还原,时序在 `landscape.js` 按像素还原之后,后写的生效。
普通 iPhone 竖 → 横 → 竖宽窄不翻转,和 v1.35 逐像素一致(新旧脚本对照实测:滚动位置、画布宽度、筛选条状态全同)。

### 4. 锚点要记「读到区块的几分之几」

**症状**:用「开头在顶边上方 90px 内、最靠下的区块」做锚点时,常常选中一个很高、开头远在屏幕上方的区块;折叠后它变窄变高,正在读的那段照样被挤走(378px)。

**修法**:优先选「跨过顶边或刚在顶边下方 120px 内开头」的区块,取开头最靠下的(最内层)。开头在顶边下方 → 保持距离;跨过顶边 → 记读到了几分之几,按新高度折算。
仪表盘、报表六种折叠组合实测,合上和再打开之后那一节离顶部的位置变化都在 1px 以内(冻结旋转期间画面被转了 90°,不计)。

### 已知限制

- **资产打标页在分屏半边(469 宽)会自动进入整页横屏**:它的规则是「窄屏 + 触屏首次打开 → 转横屏一次」(v1.6.20),分屏的一半同样满足,
  但分屏时转手机没用。右上角「退出横屏」一点就回来,本会话不再自动转。识别「分屏」需要比较窗口和屏幕尺寸,模拟器里测不出来,等真机到货再定要不要改。
