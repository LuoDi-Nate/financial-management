## 一、需求分析

将退休计划从净资产的固定提款率估计中分离,让家庭能逐项复算;同版消除 AI 入口路由和故障状态不一致。FR-1430–1441 的判据是资金桥恒等式、来源/缺失可见、老目标默认不变、币种不变和全入口同结果。FR-1442–1445 的判据是备选可用、短冷却、明确失败反馈、设置页无远端等待及超时热改。

## 二、关键选型

### 1. 计划保存

| 方案 | 用户收益 | 风险 | 结论 |
|---|---|---|---|
| 改写 family_goal.params_json | 不加表 | 老 jar 解析再保存会丢掉新参数,退出无法恢复 | 不选 |
| 独立 retirement_plan,关联原 goal | 老目标原字段完全保留,可显式退回;老 jar 不修改新计划 | 新建目标回滚需先归档,避免老算法误读 | 选定 |
| 全新目标类型 | 清晰区分 | 老 jar 不认识新枚举,全站调用影响大 | 不选 |

计划表保存带版本的 JSON、active、是否新建、更新时间,家庭过滤贯穿 SQL。JSON 中存账户选择而非外键关联表,服务端校验账户归属与失效状态;不将空选择解释成全部。原生新目标旧 params 为 `{}`,不伪造年龄;回滚脚本必须先归档本版原生新目标,避免老算法误读。旧目标不改金额/年龄/日期,退出只关闭新计划。目标名称和新计划日期单独保存,不静默覆盖旧信息。

### 2. 计算入口

| 方案 | 用户收益 | 风险 | 结论 |
|---|---|---|---|
| 详情单算 | 单页可解释 | 外部目标条仍用旧数字 | 不选 |
| GoalProgress 增加可空 RetirementResult | 所有消费者取得同一结果;原三类兼容 | 需逐个处理空结果/无门槛状态 | 选定 |
| 改整个事实/KPI 层 | 无额外收益 | 退休假设污染账上真实指标 | 不选 |

纯函数 RetirementCalculator 计算门槛和 600 个月路径,金额 BigDecimal、利率 DECIMAL128,分数次幂只用于日期换算与路径;日期从显式 today/YearMonth 输入,可重复测试。保留年化年末生活费基准。资金快照和收支从事实服务组装,不写流水/估值。

### 3. AI 路由

| 方案 | 用户收益 | 风险 | 结论 |
|---|---|---|---|
| 两入口分别补备选 | 当前可用 | 三套冷却、顺序继续漂移 | 不选 |
| 分类复用 LlmRouter,工具流复用候选与平台健康机制 | 设置在各入口一致;保留 SSE 和工具体验 | 流式重试须限制在输出前 | 选定 |
| 工具 Agent 改非流式普通 chat | 路由简单 | 丢失流式反馈和工具能力 | 不选 |

LlmRouter 暴露安全的可用性状态和候选执行记账,不向 UI 返回原始异常。一般文本客户端使用已有平台熔断,本地 SSE 的成败同样回报到该平台机制。候选在每次尝试前复查可用性;已传出文字/工具事件的请求不自动换平台。所有请求逐次读取超时值,不并发修改共享 RestTemplate。

### 4. 模板状态

| 方案 | 用户收益 | 风险 | 结论 |
|---|---|---|---|
| 打开页面同步查询加缓存 | 缓存命中时快 | 首次/过期仍等远端超时 | 不选 |
| 页面只读带配置指纹缓存,单独请求显式刷新 | 页面稳定可用,状态真实,可重试 | 需显示未检查/时间 | 选定 |
| 永不检查 | 页面最快 | 模板缺工具再次隐蔽失效 | 不选 |

### 5. 配置页继承现有登记表(11-05 维护者返工)

| 方案 | 用户可感知的结果 | 结论 |
|---|---|---|
| 继续维护退休专属输入框与标签 | 同一产品的设置页仍有两套外观,字号与对齐继续漂移 | 不选 |
| 全站更换表单框架 | 改动其他成熟表单,扩大录入习惯与回归风险 | 不选 |
| 复用 field-input / field-input-num / field-label / bracket-card,只新增当前页面的排版 | 与账户登记和家庭设置一致,新建/修改/采用一份模板,全局控件升级同步生效 | 选定 |

真实浏览器先比对 `/accounts/{id}/edit`、`/admin/family`、`/admin/analysis`、固定收支新建表单。配置页沿用共享信笺边角、下划线输入与现代按钮,表单宽度不超过800px,分节内部不再套卡片。退休 CSS 只处理章节栏、栅格、单位、来源与确认布局;中文标签用局部12px可读档,金额仍用共享18px等宽数字。所有新增字号经 `--fs-scale`,交互强调用铜色,不把绿色当可点击信号。

不改变字段名和绑定白名单,不引入第二套金额运算。账上来源放在生活安排中,教育参考在有已选目标时自动展开;展开与页签切换不销毁表单。e2e 58 读取已有账户表单的实际金额字体与字号,与新配置页比较,并测手机触摸高度、章节定位、中心点遮挡、特大字号和尺寸变化。

配置页的系统工具组改为表单后的普通文档流,保留原有方向、Agent和隐私控件;切回生活账或原理时恢复原有悬浮位置。这样右对齐金额不再被手机浮钮盖住,也不为浮钮挤窄整个填写区。浏览器逐个输入框滚动检查完整区域与工具组不重叠,并实际切换隐私确认入口仍有效。

## 三、系统概要设计

### 1. 整体设计

`退休表单 → RetirementPlanService(校验/保存) → RetirementDataService(事实/窗口) → RetirementCalculator → GoalProgress → 全站目标消费者`。

### 2. 领域模型

RetirementPlan:币种/购买力基准日、预算模式/排除规则、X/J、预留、账户选择/可变现金额、回报/通胀、C 与增长方式、三情景、目标年月、用户确认。RetirementResult:来源列表、数据日期、资金桥、缺失原因、门槛/反算/覆盖、情景路径/目标月缺口、计划指纹。历史建议与计划参数分离;余额变动不能更新固定 X。

### 3. 代码架构

退休领域在 `domain/goal`、纯计算在 `calc`、取数与计划在 `service/goal`、独立 controller 负责表单/预览/采用/退出/导出。GoalProgressService 的新结果适配保持既有构造器兼容。AI 故障原因由路由转换为有限状态,不通过 ThreadLocal 共享跨请求错误。

### 4. 运行架构

仍为同一 Spring Boot 单体,无新 cron/外部服务。模板显式查询为普通请求,主页面不阻塞。Maven/Chromium 串行。

### 5. 物理架构

不适用,部署形态不变。

### 6. 数据架构

新增 `retirement_plan(family_id,goal_id,plan_json,active,created_for_plan,updated_at)`;只增表,不转换老行。写入用 `INSERT SELECT WHERE family_goal.family_id` 和更新家庭过滤。导出、清演示数据、隔离审计登记新表。无账户 id 列,引用校验由取数服务明确报告失效,不悄悄切回全家庭。迁移事务外失败后重跑使用现有 sha256 迁移纪律。

## 四、接口协议设计

### 1. 影响评估

目标创建/编辑/详情、采用/退出/导出,目标列表/仪表盘/报表条,GoalReportService/GoalLlmService/LlmDiagnoseService 目标上下文;商户分类、本地工具循环,体检/调仓/目标故障展示,AI 接入模板状态和超时字段说明。

### 2. 对外接口

不新增公共 API。登录后家庭隔离,全部修改 POST + CSRF;预览不写库、不调模型。来源只出 BV 链接,`rel=noreferrer`。

### 3. 上游接口

沿既有 OpenAI 兼容协议与百炼管理 GET,不变更报文。验证使用 HTTP 桩的 JSON completion、SSE tool calls/结束/错误/超时,不真实调用模型。

## 五、稳定性与质量保障

### 1. 兼容性

无计划行或 inactive 目标走 tag v1.37.1 的老路径;新算法采用与退出保留旧数据。新参数不进旧 params,老 jar 不覆盖它们。回到 v1.39 之前先归档新方案原生目标,保留计划表,重新升级可恢复。教育/应急/CUSTOM 不换算法。

### 2. 性能

事实层一次批量窗口取数,不逐账户查数据库;单次路径至多 3×600 次递推。计划批量读取避免目标列表 N+1 放大。模板缓存按配置指纹隔离、检查合并,页面零远端查询。

### 3. 安全

无生产读取。计划不保存生日/疾病;密钥仍只在原配置层。AI 失败 UI 只给安全类别与管理页链接,原异常不经网页输出;日志不记请求正文。商户参数类型仍只有商户名称,模型不能获金额。测试不跑关账异步流程。

## 七、上线与回滚方案

### 1. 可观测

保持 /health;计划保存/采用/退出记元数据审计。AI 平台健康记成功/失败类别,不保存正文到日志。模板显示检查时间及状态,无检查不假称最新。

### 2. 预案

单目标退出新算法即恢复旧参数;旧计划不删除。回滚 jar 前执行 v1.39 回滚脚本归档原生新目标,避免老代码误读。迁移仅加表,不删数据。

### 3. beta 方案

先单测/静态守护/本地 AI 桩,再构建及应用新增迁移、部署 beta。浏览器从目标入口走创建/编辑/预算来源/公式/采用退出/币种/手机,AI 请求仅 stub;不关账、不触发后台真实模型。v1.38 尚无实现,不能宣称全站服务端已拦截。

## 八、成本测算

无新增收费服务;退休纯计算不调用 AI。修复只恢复用户主动触发的既有入口,候选短冷却限制重复失败调用。保留最大商户批次数/工具轮数。
