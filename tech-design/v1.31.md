| 可能的静默失败 | 怎么让它响 |

## 一、需求分析

### 1. 背景 & 目标

见 PRD §0。技术上的要点只有一个:**两个问题都出在「PC 布局原样塌到手机上」**(侧栏整列搬到内容前面、5 列表格硬挤 390px),
所以修法是给这两类东西各补一个**手机形态**,而不是逐页调样式。

### 2. 需求理解(验收口径)

| FR | 工程判据(可判定) |
|---|---|
| FR-1010 | 390×844 触屏下,所有设置页 `main h1` 底边 < 844px;`.adm-bar` 高 ≤ 56px;PC 侧栏 `.adm-nav` 不可见 |
| FR-1011 | 手机抽屉与 PC 侧栏按四组渲染,组名与总览页一致 |
| FR-1012 | 侧栏 href 集合 ⊇ 总览页卡片 href 集合;`admin/*.html`(除总览、局部片段、模板定制子页)都 include `_sidebar` |
| FR-1020 ~ 1022(周期表) | 手机上表头不显示;区间 / 关闭时间 / 状态标签高度为单行;理由框与按钮的右边界 ≤ 卡片右边界且 ≤ 视口宽;卡片里能完成重开与关账(库里状态随之变化) |
| FR-1030 | `.pill` 计算样式 `white-space: nowrap` |

## 二、关键选型

### 选型一 · 手机上的管理导航长什么样

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A · 横向滑动 chip 条 | 21 项排成一行可横滑的标签 | 一行高 | 一屏只看得见 3~4 项,找「审计」要横划好几下;当前页之外的项都藏在屏外,和「找得到」相反 | 不选 |
| B · `<select>` 下拉 | 原生下拉列出 21 项 | 实现最轻 | 原生下拉没有分组标题的好看形态、iOS 滚轮选择器一次只露 5 行;选中即跳转的 select 是反模式(键盘 / 读屏会误跳) | 不选 |
| **C · 一行切换条 + 底部抽屉** | 「管理 › 当前页 · 切换」,点开是和页内目录同款的底部抽屉,四组两列 | 一屏看全 21 项且有分组;和仪表盘目录同一种交互(维护者原话「应该以目录的形式来做」);抽屉样式与横屏行为直接复用 `.toc-sheet` | 多一次点击 | **选它** |
| D · 手机上干脆不显示侧栏,回总览页再选 | 只留面包屑 | 最省地方 | 每换一个设置项都要退回总览,来回跳 | 不选 |

### 选型二 · 侧栏条目的「唯一出处」

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A · PC 列表和手机抽屉各写一份 | 复制 21 个 `<a>` | — | 三份真相(总览、PC、手机),漂移已经发生过一次 | 不选 |
| B · Java 端 `@ControllerAdvice` 注入导航模型 | 每个请求带一份分组清单 | 总览页也能从同一份渲染 | 为纯展示的清单加一层后端代码;每个请求都多一份 model 属性;总览卡片还带说明文字,统一成一份要改总览页的结构(超出本版) | 不选(后续若总览也要收进来再议) |
| **C · `_sidebar.html` 里一份 Thymeleaf 内联清单** | `th:with="groups=${ {...} }"`,PC 侧栏与手机抽屉都 `th:each` 它 | 侧栏两种形态只有一份;总览页那份由护栏 `v131-ADMIN-NAV` 盯着「侧栏 ⊇ 总览」 | 总览与侧栏仍是两处,靠护栏而不是结构保证 | **选它** |

### 选型三 · 表格在手机上怎么排

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A · 外层 `overflow-x:auto` 横滑 | 表格保持 5 列,横着划 | 不动 DOM | 周期表的操作列在最右,横划才看得到;用户反馈的就是「看不清、按钮找不到」;宽表横滑只适合列本身是信息的交叉表 | 不选(交叉透视、本期 vs 上期两张宽表保留横滑) |
| B · 手机另写一份列表模板 | `md:hidden` 的 `<div>` 列表 + `hidden md:table` 的表 | 手机形态完全自由 | 每张表两份 DOM:表单字段、按钮、e2e 选择器都翻倍,改一处漏一处 —— 正是 FR-1022「一个按钮都不能少」最容易破的写法 | 不选 |
| **C · 同一份 `<table>`,纯 CSS 在 <768 改成卡片** | `table.m-cards`:`tr` → 两列 grid,`td` 按角色加类(`m-title` / `m-badge` / `m-act` / `m-full`),字段名取 `data-label` 用 `::before` 画 | 一份 DOM、一份表单,PC 完全不变;新表只要加类即可套用 | 卡片排法受 grid 约束,特别复杂的行要额外加角色类 | **选它** |

### 选型四 · 抽屉怎么盖住浮钮

| 方案 | 怎么做 | 劣 | 结论 |
|---|---|---|---|
| A · 去掉 `<main>` 的 `relative z-10` | 拆层叠上下文 | 牵连全站所有 main 内的浮层与 sticky,v1.6 起的若干修复都依赖它 | 不选 |
| **B · 打开前把抽屉和遮罩挪到 body 下** | 片段里一小段脚本 `document.body.appendChild`,`z-index` 10000/10001;打开时 `body.adm-open` 隐藏浮钮栈 | 只动这一个组件 | **选它** |

### 选型五 · e2e 怎么跑「真手机」

| 方案 | 劣 | 结论 |
|---|---|---|
| A · 现有 PC 页面 `setViewportSize(390, 844)` | 不是触屏:`#float-dock` 不出现,看不到浮钮遮挡;`isMobile` 相关的 viewport meta 行为也不一样 | 不选 |
| **B · `ui.phone(fn)`:同一个浏览器实例里另开 `isMobile + hasTouch` 的 context,登录后跑,跑完关** | 每次多一次登录(约 1 秒) | **选它**(不另起浏览器,守 beta 3.5G 内存) |

## 三、系统概要设计

### 1. 整体设计思路

两个共用件,后续批次都用它们:

```
admin/_sidebar.html  ── groups 清单(唯一出处)
   ├─ <768:.adm-bar「管理 › 当前页 · 切换」 → #adm-sheet(.toc-sheet 外观 · 挪到 body)
   └─ ≥768:分组侧栏 .adm-nav(+ 当前项下的 .adm-toc 空位,留给后续 PC 本页目录)

style.css  table.m-cards  ── <768 时 tr→卡片(m-title / m-badge / 普通字段 / m-act / m-full / m-hide)
           .pill { white-space: nowrap }
```

### 2. 领域模型设计

不适用 · 无领域概念变化。

### 3. 代码架构设计

| 文件 | 变化 |
|---|---|
| `admin/_sidebar.html` | 重写:groups 清单 + 手机切换条 + 分组 PC 侧栏 + 手机抽屉 + 挪抽屉的小脚本 |
| `admin/periods.html` | 周期表加 `m-cards` 与角色类;账期节奏四卡手机 2 × 2(`auto-rows-fr` 保证逐像素同尺寸) |
| `admin/appearance.html` | 换成和其它设置页一样的 grid + 侧栏(FR-1012) |
| `static/css/style.css` | 末尾 v1.31 段:`.adm-*`、`table.m-cards`、`.pill` 不折行;侧栏 sticky 限高可滚(分组后变长,矮屏够不着底部几项) |
| `scripts/e2e/lib/browser.cjs` | `ui.phone(fn)`;登录抽成 `login(page)` |
| `scripts/e2e/flows/47-mobile-admin-nav.cjs` | 新主线 |

### 4. 运行架构 / 5. 物理架构 / 6. 数据架构

不适用 · 单体不变,无迁移、无数据写入。

## 六、护栏设计

| 护栏 ID | 守的设计意图 | 判据怎么写 |
|---|---|---|
| `v131-ADMIN-NAV` | 侧栏只有一份清单;它 ⊇ 总览页全部卡片;所有设置页都挂着它 | 从总览页抽出全部卡片 href,逐个在 `_sidebar.html` 清单里找;遍历 `admin/*.html`(排除总览 / 片段 / 模板定制子页)查 include;`th:each="it : ${g.items}"` ≥ 2 处、手写 `/admin…` 链接 ≤ 2 处(两处「总览」);flow 47 存在 |
