### 现状实测(2026-10-19 · beta)

| 事实 | 实测 |
|---|---|
| 按钮类用量 | `btn-paper` 147 · `btn-ink` 128 · `btn-ghost` 42 · `btn-line` 8;`<button>` 共 268 个,159 个带 `btn-*` |
| 按钮尺寸写法 | 模板里用 `text-xs`(67)/ `text-[11px]`(32)/ `text-[10px]`(23)/ `text-[12px]`(9)/ `text-sm`(38)当「小一号」;29 处另写了 `px-* / py-*` |
| 行内颜色覆盖 | 14 处按钮写 `style="color:var(--rust)…"` 表示危险操作(删除 / 归档 / 强制关账 / 清空回收站) |
| Tailwind | 浏览器运行时 **3.4.1**;它的 `<style>` 在 `style.css` 之后注入 → **同优先级时 Tailwind 工具类胜出** |
| 旧样式补丁 | `style.css` 里有 3 处专门压按钮的覆盖(`.tags-note .btn-ink` 改 padding、手机 `.btn-ghost` 改字号、`.ff-l3` 等分);模板里有 `text-transform:none` 之类的抵消写法 |

### 静默失败预检

| 可能的静默失败 | 怎么让它响 |
|---|---|
| 模板给按钮加了 `block` / `inline-block`,覆盖掉 `inline-flex` → 文字不再竖直居中,但不报错 | `.btn-*.block` 提高优先级改成 `flex`;e2e 量按钮内文字中线 ≈ 按钮中线 |
| 固定 `height` 截掉换行的长按钮文字 | 用 `min-height`,不用 `height` |
| 标签字号被 `text-[9px]` 之类的工具类压回 9px | `.pill[class]` 提高优先级,统一 11px |
| 某个页面靠旧按钮尺寸撑出的对齐(等高网格、按钮与输入框并排)错位 | 逐页双端截图 + e2e 量按钮高度 / 并排元素同高 |

## 二、关键选型

### 选型一 · 新规格怎么落地

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 引 daisyUI / HeroUI 的 CDN CSS,模板改用它们的类名 | 现成组件 | 两者都带 Tailwind v4 的样式重置,和运行时 Tailwind 3 冲突;daisyUI 的 `.btn-ghost` 和我们撞名;要改约 350 处模板 | 不选 |
| **B** | **改 `style.css` 里现有的 `btn-*` / `pill` 定义**,类名不变;危险操作、持仓页收纳等少量模板改动 | 一处改全站生效;模板不动的地方零风险;回滚就是回退 CSS | 要清掉模板里抵消旧样式的补丁 | **选它** |
| C | 新起一套类(`ui-btn`…),逐页迁移 | 新旧可并存 | 迁移期两套样式同时在线,和「全部页面都调」矛盾;两份真相 | 不选 |

### 选型二 · 尺寸档位怎么表达

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 新增 `btn-sm` / `btn-lg` 修饰类,逐个改模板 | 语义清楚 | 要改 160 多处模板;漏一处就是大小不一 | 不选 |
| **B** | **沿用模板里已有的写法**:按钮带 `text-xs` / `text-[10–12px]` 就是小档,其余是默认档;另加 `btn-lg` 只给登录、引导这类大入口 | 模板已经这么用,零改动就对 | 「字号类决定尺寸」有点隐式 | **选它**,在 design-system.md 写清这条约定 |

### 选型三 · 按钮字体

| 方案 | 优 | 劣 | 结论 |
|---|---|---|---|
| 继续用 JetBrains Mono,去掉大写和字距 | 改动最小 | 中文在等宽字体里会回退到系统字体,和英文、数字的字重对不上;七个库没有一个按钮用等宽字体 | 不选 |
| 正文衬线 Source Serif | 和正文一致 | 衬线小字在 13px 按钮上发虚 | 不选 |
| **系统无衬线**(苹方 / 微软雅黑 / Noto Sans SC) | 各平台原生、零加载 | 和衬线正文是两种字体 | **选它**:「正文衬线 + 控件无衬线」是编辑类产品的常规搭配 |

### 选型四 · 持仓页 5 个「添加」按钮怎么收

| 方案 | 结论 |
|---|---|
| 全部保留,只缩小 | 不选:一行 5 个仍违反「≤3」 |
| **主按钮 + 「添加其他 ▾」菜单**(原生 `<details>`,和现有「⋯」菜单同一写法) | **选它**:不需要 JS;键盘可达 |
| 改成分段按钮组 | 不选:5 段在手机上放不下 |

## 三、系统概要设计

1. **`style.css` 组件层**(唯一一处):
   - 按钮四类 + `btn-danger` + `btn-lg`。
   - 状态四件套。
   - `.pill` 标签。
   - 输入框 / 下拉框圆角。
   - `paper-card` 圆角。
   - 新增 token:`--ui-sans`、`--r-sm / --r-md / --r-lg`、`--ring`、`--shadow-xs`。
2. **清补丁**:删掉 `style.css` 里 3 处压旧按钮的覆盖;模板里抵消旧样式的 `text-transform:none` / `tracking-*`。
3. **模板**:
   - 14 处行内 rust → `btn-danger`。
   - 持仓页「添加」收纳 + 持仓卡按钮横排。
   - 零散的手搓小按钮(`font-mono text-[10px] px-2 py-0.5 border …`)改用 `btn-paper text-xs`。
4. **逐页过**:全部页面(约 75 个路由)PC + 手机截图,逐页看。发现问题就地改,改动记在 §附录「逐页记录」。

## 附录 · 逐页记录

**方法**:`/tmp/sweep/sweep.cjs`(不入库的一次性工具)把 71 个页面路由在 PC 1440 和手机 390 触屏各拍一张首屏,
同时在页面里量:按钮的大写 / 字距 / 字体 / 高度 / 文字溢出,非按钮控件的大写字距与「直角带框」,同一行按钮数,横向滚动,控制台报错。
量出来的问题和看截图看出来的问题都在下面;每改一轮重新部署再扫一遍。

| 范围 | 发现 | 怎么改 |
|---|---|---|
| 全站按钮(约 350 处) | 等宽大写宽字距、42px、直角 | `style.css` 按钮段整段重写(§三.1);字号类即尺寸档;`:is()` 压过 Tailwind 同名工具类 |
| 全站标签 `.pill`(约 110 处) | 硬边框、9px、等宽大写 | 软底圆角 11px;`.pill[class]` 压掉 `text-[9px]`;`!important` 压掉行内 `border-color` |
