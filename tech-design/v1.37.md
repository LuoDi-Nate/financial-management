## 一、需求分析

### 1. 背景 & 目标

见 PRD §0。技术主线只有一条:**在「主屏 App + 触屏 + Duo 形状窗口」时,把顶栏和浮钮换成一列右侧操作栏**。其余三件是同一次对齐里顺手要修的:内屏横向避开折痕、外屏横握不冻结旋转、测试不烧 AI。

### 2. 需求理解(验收口径)

| FR | 工程判据 |

## 二、关键选型

### 选型一 · 判据写在哪

| 方案 | 做法 | 结论 |
|---|---|---|
| A | 纯 CSS 媒体查询,直接在 style.css 里写 `@media (display-mode: standalone) and …` | 不选:iOS 主屏 App 有时要靠 `navigator.standalone` 认;CSS 拿不到它。而且 JS 侧(弹框定位、图表重排)也要知道,会写成两份 |
| **B** | 头部内联脚本算一次,给 `<html>` 挂 `vp-rail` / `vp-fold` 类;形状判据是一条 `matchMedia` 查询字符串(`window.VP_RAIL_SHAPE_Q`),主屏 App 判断沿用 `display-mode` + `navigator.standalone`;CSS 只认类名 | **选它**:首次绘制前就挂好类,不闪;判据一处;JS 和 CSS 用同一个结果 |
| C | 服务端按 UA 渲染不同骨架 | 不选:苹果明确反对按设备判断,而且同一台手机折叠前后要换形态,服务端做不到 |

### 选型二 · 侧边栏的「更多」菜单怎么来

| 方案 | 做法 | 结论 |
|---|---|---|
| A | 侧边栏里再写一份完整导航 | 不选:同一份导航两处维护,改一处漏一处 |
| **B** | 把汉堡菜单里的导航抽成片段(`nav :: drawer`),汉堡菜单和侧边栏的「更多」各引一次 | **选它**:一份源码,两处呈现 |
| C | 「更多」点的时候用 JS 去点隐藏的汉堡菜单 | 不选:汉堡菜单在被隐藏的页头里,要拆 CSS 才能让它在侧边栏模式下露出来,很脆 |

### 选型三 · 测试怎么模拟主屏 App

| 方案 | 结论 |
|---|---|
| CDP 模拟 `display-mode` | 不选:实测无效(§零) |
| **注入 `navigator.standalone = true`** | **选它**:iOS 主屏 App 真实走的就是这一支 |
| 网址参数强制 | 只给维护者在电脑 Chrome 里预览用(`?app=1` 存进本次会话,`?app=0` 清掉),e2e 不走它 |

### 选型四 · 测试不烧 AI(维护者 2026-10-21 要求,第一层)

| 方案 | 结论 |
|---|---|
| 每条 flow 自己拦(现状 13/36) | 不选:漏网的就是这么来的 |
| **harness 默认拦全部 AI 接口;要真调的 flow 声明 `realAi: true`,默认跳过,`E2E_REAL_AI=1` 才跑** | **选它** |
| 服务端开关(第二层) | 还没定(维护者待办 #3);关账触发的后台目标月报只有它拦得住,本版测试**避开会关账的 flow** |

## 三、系统概要设计

### 1. 整体设计思路

```
<head> 内联脚本(layout.html,首次绘制前)
  VP_RAIL_SHAPE_Q = 触屏 · 竖 · 宽高比 ≥ 0.58 · 宽 < 560   |   触屏 · 横 · 高 ≥ 460 · 宽 < 1024
  VP_FOLD_Q       = 触屏 · 横 · 高 ≥ 460 · 宽 760–1023
  vpIsApp()       = ?app 预览 || navigator.standalone || (display-mode: standalone)
  html.vp-rail    = vpIsApp() && matchMedia(VP_RAIL_SHAPE_Q)
  html.vp-fold    = matchMedia(VP_FOLD_Q)          ← 浏览器里也生效(折痕不分打开方式)
  vp-rail 时给 viewport meta 补 viewport-fit=cover

viewport.js settle()(尺寸停止变化 150ms 后)→ 重算两个类 → 有变化就重排图表(沿用 v1.36)

nav.html:header 里多一个 <nav class="side-rail">(默认 display:none)
  上段:目录(调 .toc-fab)· 超级 Agent(/ask)· 隐私眼(togglePrivacy)
  下段:仪表盘 · 填报(角标)· 账户 · 报表 · 更多(<details>,面板 = nav :: drawer 片段)

style.css:html.vp-rail { 页头不吸顶、隐藏 .nav-actions 和 #float-dock、body 右边让出侧边栏 }
           html.vp-fold { dialog / 更新弹窗 / 目录抽屉靠右半边;md:grid-cols-3 → 2 列 }
landscape.js / style.css:冻结旋转高度上限 479 → 459
```

## 五、稳定性与质量保障

### 1. 兼容性设计

- **普通设备一律不变**:普通 iPhone 主屏 App 竖着宽高比约 0.46(SE 0.56),横着高 ≤ 440;iPad 竖宽 ≥ 744、横宽 ≥ 1024;电脑不是触屏。以上都不满足判据,`vp-rail` 和 `vp-fold` 都为假,页面与改前相同。
- **冻结旋转阈值从 479 改为 459**:只影响横屏高度在 460–479 之间的触屏设备。现有 iPhone 横屏高度都 ≤ 440,不受影响。
- **已知限制**:iPad 上把主屏 App 拖成很窄的分屏窗口(宽 < 560 且不细长)时也会出侧边栏。概率低,记录在案。

### 2. 性能评估

不适用。只多一次 `matchMedia`,在尺寸变化时重算。

### 3. 安全性设计

不适用。

## 六、护栏设计

| 护栏 ID | 守的意图 | 判据 |
|---|---|---|
| `v137-RAIL-ONE-SOURCE` | 出不出侧边栏只有一处判据 | `VP_RAIL_SHAPE_Q` 只在 layout.html 定义一次;style.css 里没有 `display-mode` 媒体查询,只用 `html.vp-rail`;`viewport.js` 读 `window.VP_RAIL_SHAPE_Q` |
| `v137-RAIL-ONE-MENU` | 导航只有一份源码 | nav.html 里完整导航链接(例如 `/help/how-to-use`)只在 `drawer` 片段里出现一次;汉堡菜单和侧边栏都引用这个片段 |
| `v137-FREEZE-HEIGHT` | 冻结旋转只给普通手机 | `landscape.js` 的 `FREEZE_Q` 和 style.css 冻结块里的 `max-height` 是同一个值,且 < 460 |
| `v137-E2E-AI-STUB` | 自动化默认不调 AI | `browser.cjs` 每个 context 默认拦 AI 接口;31 / 32 / 34 标了 `realAi`;`run.cjs` 不设 `E2E_REAL_AI=1` 就跳过它们 |
| `v137-E2E` | 六种姿态有真浏览器覆盖 | flow 56 在,且带 cleanup |

**e2e `56-duo-side-rail`**(首页进入,从侧边栏点按钮,不直接打开功能页):

1. **外屏竖握(主屏 App)**:
   - 断言:有侧边栏、页头不吸顶、浮钮不见、不横滑、内容不被侧边栏盖住;
   - 点侧边栏「填报」到 /entry,角标数 = 库里本期待填数;
   - 点「更多」,菜单里有「管理」「退出」;点「隐私眼」,`html.privacy` 切换。
2. **外屏横握 / 帐篷(主屏 App)**:有侧边栏,`html` 上没有冻结旋转;
   - → 库:仪表盘「N 个已选」= 未归档账户数。
3. **内屏横(主屏 App)**:
   - 有侧边栏,`vp-fold` 为真;
   - 支出类目页打开「新建类目」弹框,弹框在右半边;仪表盘的 3 列网格变成 2 列;
   - → 库:类目数不变(只开不存)。
4. **内屏竖(主屏 App)**:没有侧边栏,页头照旧。
5. **折叠往返**:外屏竖 → 内屏横 → 内屏竖,侧边栏在 / 在 / 不在,正在看的那一节不动。
6. **同样尺寸但在浏览器里**:没有侧边栏;内屏横时 `vp-fold` 照样为真,弹框在右半边。
7. **普通设备**:
   - 普通 iPhone 主屏 App(390×844 · 375×667 · 440×956)、iPad 主屏 App(820×1180 · 1180×820)、电脑 1440:都没有侧边栏,也没有 `vp-fold`;
   - 普通 iPhone 横屏(844×390)照旧冻结旋转。
