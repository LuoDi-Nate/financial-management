## 一、需求分析

### 1. 背景与目标

PRD §0已批准新增硅基流动。现有LlmCatalog和路由已有扩展边界,新增平台应进入这些边界;当前视图的三卡/ready映射及部分错误文案仍写死平台,直接复制第四张卡会继续制造配置差异。本版同时将共同交互收进同一渲染路径,保持原平台执行语义。

### 2. 需求理解

| FR | 工程判据 |
|---|---|
| 1470–1471 | 新平台独立私密配置;四卡来自同一目录和视图结构,Key保存不依赖模型,空提交不写配置 |
| 1472、1477 | 主/备/视觉完整ID逐字回读;格式合法但不在参考清单中的ID仍能用;不改旧键派生及百炼auto轮询 |
| 1473 | 新Client进入原LlmRouter,所有文字消费者自动沿用原主备及trace;冷却和健康按platform隔离 |
| 1474 | 图片独立三元组和原确认入账路径;关闭视觉不阻塞文字,没有虚构的DeepSeek官方视觉能力 |
| 1475 | 原本地Agent候选、工具循环和流式传输覆盖新平台;部分产出失败不切备选重播;托管百炼配置不变 |
| 1476、1478 | 测试用已保存目标;安全分类、最小用量说明、服务端保护与审计对四家一致 |
| 1479 | 同一套表单字段/选择器/校验/反馈,四平台参数化验证;真实能力差异明示而不强行抹平 |

## 二、关键选型

### 选型一 · 平台客户端与目录

| 方案 | 用户可感知的取舍 | 结论 |
|---|---|---|
| 独立硅基流动设置页和路由 | 需要重复配置,业务入口可能使用不同平台,无法保证主备一致 | 不选 |
| 既有LlmCatalog加平台,新增SiliconFlowLlmClient复用公共兼容实现 | 同一处设置覆盖原入口,沿用故障切换、脱敏、超时和保护,原平台不改归属 | **选定** |
| 任意base URL的通用平台编辑器 | 灵活但要求用户辨认代理安全性和兼容差异,超出批准范围 | 不选 |

平台code为siliconflow;固定中国站地址。目录保留现有三家全部系列和参考项。硅基流动文字提供已核验的DeepSeek参考系列及无默认的“其他对话模型”,视觉提供Kimi参考系列及无默认的“其他图片模型”。Model ID只送JSON字段,不用于URL、SQL或执行代码。不存在“某个系列默认走某家平台”的隐式跳转。

### 选型二 · 手填型号与自动语义

| 方案 | 用户可感知的取舍 | 结论 |
|---|---|---|
| 只给硅基流动放宽,其它家继续另一套格式 | 同一个字段出现不同限制,将来换平台更容易丢配置 | 不选 |
| 四家共用安全格式和原自动语义 | 长命名空间可用,旧ID继续合法;保留百炼专属轮询及无默认项的明确必填 | **选定** |
| 必须在远端型号白名单内,否则回到推荐 | 未及时收录的新型号被错拒或调用错对象 | 不选 |

格式拟为`^[A-Za-z0-9._:-]+(?:/[A-Za-z0-9._:-]+)*$`,总长1–256字符。拒绝URL、空白、引号、控制字符、空路径段及超长串;不为“模型必须有组织前缀”另设规则。normalize只trim;空/auto归一为自动,其余不转大小写。前端长度/格式提示与服务端同义,服务端是最终判据。

自动的共同含义是“没有钉死型号,沿用平台既有默认策略”:百炼文字仍轮询原池;DeepSeek官方/方舟有默认的系列及硅基流动有默认的系列用目录默认;无默认的方舟托管DeepSeek及“其他”系列必须手填。页面明确百炼轮询,不得写成必定使用某一个参考项。

备选重复判定也保留该差异:同平台同系列相同显式ID,或两个自动选择,拒绝;非轮询平台的自动与等价显式默认也判重复。百炼自动与某个显式型号不合并成“完全相同”,避免把轮询策略误当单型号。

### 选型三 · 配置卡与交互

| 方案 | 用户可感知的取舍 | 结论 |
|---|---|---|
| 复制第四张卡,每家分别改计数/禁用/测试 | 同类操作逐渐漂移,第四家容易漏帮助或保存提示 | 不选 |
| 服务端目录驱动共同卡片,平台专属帮助保留为内容片段 | 四家状态和按钮一致,能力差异仍能准确解释;无JS仍可提交Key | **选定** |
| 浏览器远端拉全量模型再构建设置页 | 打开页面依赖外部网络,更多暴露凭据/目录错误的机会 | 不选 |

LlmSettingsView从目录生成凭据卡视图,含code、label、已配状态、脱敏值、申请入口、探测目标及帮助片段标识;不向前端输出keyName、baseUrl或明文Key。申请URL补在服务端平台元数据,专属说明留原帮助片段。卡片、计数、主备禁用项和视觉能力名单都从同一目录派生,不再维护“三家”的平行清单。

模板循环渲染Key表单及测试sibling form,保留CSRF与既有端点。桌面两列手机单列,共同控件类和按钮尺度;选择器继续data-lsel。Key和模型各自保存;模型错误定位首错,安全的型号草稿和其它已填选项回填,密码永不回填。格式异常或疑似凭据的原串不放进flash/日志,服务端只返回字段级安全原因。保存动作不测模型。请求期间防重复提交,失败可重试且有效配置不被部分覆盖。

### 选型四 · 连接目标与错误反馈

| 方案 | 用户可感知的取舍 | 结论 |
|---|---|---|
| 测试草稿Key/型号 | 结果与当前运行配置不同,容易误判“保存成功” | 不选 |
| 共用已保存目标解析,按平台提供安全分类 | 点击前能核对测试对象,四家相同错误有相同反馈,具体修复不串平台 | **选定** |
| 只检查Key格式或/models可达 | 不能证明对话端点/所选型号真的能调用 | 不选 |

从现有probeInvocation提取窄职责的LlmProbeTarget解析,供页面展示与连接POST共用:主选→备选→启用的视觉,均未选中此平台才用第一组有默认值的文字系列;没有就提示先保存型号。测试时将自动目标解析成一个明确型号并固定此次调用,百炼连接检查只做一次小探测,不触发整池轮询。业务自动轮询不受影响。

连接检查与视觉/本地Agent的用户可见错误复用窄的LlmFailure安全分类,不更改原控制重试/额度轮询策略。分类从异常链读取HTTP状态及可识别错误码,只输出枚举和固定安全文案;明确的型号错误优先于泛化invalid,401指向Key,402/余额指向账户,403按权限/额度事实区分,429/繁忙及超时独立。仅方舟分支给豆包/ep-/实名指引,仅百炼的免费配额错误提示等额度重置;硅基流动账户不足不能说“免费额度用尽换模型”。未知400/403保持保守描述,不猜具体原因。

### 选型五 · 对接验收

| 方案 | 用户可感知的取舍 | 结论 |
|---|---|---|
| 自动化直接用真实Key跑业务和关账 | 会传出家庭数据并产生不可控账单,违反维护者明确限制 | 不选 |
| 协议桩检查真实请求/响应效果,受保护beta验证真实点击链 | 能重复验证认证归属、完整ID、工具/流式和失败路径,不消耗真实模型 | **选定** |
| 只检查类/下拉/字符串存在 | 无法发现配置保存了却调错端点、SSE不解析或旧平台回归 | 不选 |

文档核验、协议桩、服务端测试保护、beta入口四层证据分别记录。桩成功不写成真实账户生成成功,保护拦截不写成连接成功。

## 三、系统概要设计

### 1. 整体思路

```text
LlmCatalog + FamilyConfigService
  -> LlmSettings / LlmSettingsView / LlmProbeTarget
  -> 同一个AI设置页的四平台Key卡与主备/视觉表单
  -> LlmRouter
      -> SiliconFlowLlmClient : AbstractOpenAiCompatibleClient -> 文字
      -> VisionLlmClient(原平台解析) -> 图片转写
      -> LocalToolLoopRuntime(原候选与工具循环) -> SSE
各出口 -> LlmTestGate / 计数 / 原trace / 独立平台健康
```

### 2. 领域模型

仍为平台→系列→型号三元组。平台负责端点/认证/健康,系列给参考和模态,显式型号是原始ID。新增的凭据卡视图和探测目标只描述设置及一次检查,不是财务事实或另一套AI设置。百炼托管Agent仍是原独立运行方式,本版不新增工具权限、财务求和或预算规则。

### 3. 类与职责

| 文件/层 | 计划变化 |
|---|---|
| LlmCatalog | 新平台/系列/参考/申请URL,共同格式上限与前端格式元数据;保留全部旧定义 |
| SiliconFlowLlmClient(新增) | 唯一新文字bean,复用公共HTTP/超时/熔断/测试保护,不复制业务prompt |
| FamilyConfigService | K_LLM_SILICONFLOW_KEY及env fallback,沿用maskedSecret和缓存失效 |
| LlmSettings / LlmInvocation | 保留旧键派生、显式ID与auto,只在重复判据确有需要时补窄方法 |
| LlmSettingsView | 共同凭据卡/ready/视觉名单及probe目标,清理三家硬编码 |
| AiModelController | 原/key、/models、/test端点,共同字段错误、probe固定目标与安全分类 |
| LlmProbeTarget(新增) | 无网络、只读已保存设置,页面和测试共享目标解析 |
| LlmFailure(新增) | HTTP/已知码到安全类别与平台指引,不持久保存原body |
| VisionLlmClient | 验证目录自动支持新平台;失败带安全图片能力提示,不加视觉failover |
| LocalToolLoopRuntime | 保留原候选/冷却/可见产出后不重放,接安全提示;请求结构不另开硅基流动分支 |
| admin/_llm-settings.html及必要的表单JS | 同一卡片循环/帮助、动态禁用和前端校验、同构反馈;旧高级及百炼设置仍在原位置 |
| 文档/测试/部署样例 | §六与§九所列,不写任何实例运维值 |

LlmRouter和既有文字消费者不新增平台if链。其提示词、数字来源和业务缓存策略不改。若实现发现必须变更这些边界,先更新设计说明,不能顺手引入第二套调用路径。

### 4. 运行架构

原单体Spring Boot、systemd/compose不变。无新增定时、队列、后台模型预热或远端目录抓取。页面GET、保存配置及部署不发模型请求。

### 5. 物理架构

不适用:不改变部署机器、入口、容器或代理形态。

### 6. 数据架构

| 数据 | 变化 | 旧行 |
|---|---|---|
| family_runtime_config | 新增可选键llm_siliconflow_api_key,存原有KV;主备/视觉使用既有键 | 不迁移、不批量改写、不删除 |
| 原报告/审计/提示词 | 原有来源坐标可出现siliconflow | 历史结果不重算 |
| 财务表 | 无变化 | 原口径与金额不动 |

无DDL迁移。优先DB→env→空默认,新增`finance.llm.siliconflow.api-key`的环境fallback,显式支持本项目前缀`FINANCE_LLM_SILICONFLOW_API_KEY`;不假定Spring对api-key/API_KEY的隐式映射一定生效,用配置绑定测试验证。公开部署样例只登记空占位,不新增另一套官方别名优先级。单次模型配置的写入使用既有事务能力保证原子性;如需补事务则覆盖写入异常回滚与缓存一致性,不只证明“校验先跑完”。三个旧选型键不写,现有Key绝不串写。

## 四、接口协议设计

### 1. 影响评估

- 管理页GET /admin/ai-access#llm及原POST /llm/key、/llm/models、/llm/test。
- 所有经LlmRouter的文字分析:仪表盘/体检/报表调仓、复盘、透视、目标报告/预警/建议、超级Agent分类;用原调用点守护核对全表。
- 持仓截图识别、原人工确认路径、本地Agent工具及SSE。百炼托管不迁移。
- 密钥设置文档、环境fallback、Docker/脚本的公开占位样例。检查旧文案中的“三家/不烧额度/仅百炼方舟有视觉”,不改实例配置或prod。

### 2. 对外接口

不适用:无新增对外入站接口、MCP工具或权限。原管理鉴权/家庭归属/CSRF沿用并测试。

### 3. 上游调用合同

真实观察只有§零的无凭据401。以下是**待实施的本地协议桩合同**,使用合成token及图片,不是上游实测报文。

```json
{
  "model": "Pro/deepseek-ai/DeepSeek-R1",
  "messages": [
    {"role":"system","content":"synthetic-system"},
    {"role":"user","content":"synthetic-user"}
  ],
  "temperature":0.5,
  "max_tokens":2000
}
```

文字桩响应`choices[0].message.content`必须非空;缺失、空数组、空正文、畸形JSON都应失败。错误桩包含401/402/403/404/429/503/超时,捕获安全分类和主备效果。请求发往目录固定的/chat/completions,Authorization来自siliconflow键,不使用其它平台Key。

图片请求保留现有`messages[].content=[{type:text,...},{type:image_url,image_url:{url:data:...}}]`结构,model来自独立视觉配置;桩返回可转写的合成持仓JSON,只在既有人工确认后进入业务写路径。

流式桩返回text/event-stream,分别覆盖content增量、分片tool_calls参数、finish_reason、[DONE]、HTTP失败及200中的error。工具回合必须带回assistant.tool_calls和对应tool_call_id,不能只验证第一段文字。额外reasoning_content不当作正文或工具参数,本版不实现新的思考开关。

## 五、稳定性与质量保障

### 1. 兼容性

- 旧家庭:主备/视觉显式值、auto、百炼轮询、托管运行及环境fallback对照v1.40.1结果;不因多一家Key自动切换。
- 新平台:保存完整三元组后才参与业务;只存Key不写模型。截图关闭时保留可解析草稿,异常视觉配置不阻塞文字且回执说明未保存该组。
- 旧程序不认识siliconflow,不能依赖旧LlmSettings自动猜出正确平台。回滚前显式切回原平台,见§七。
- 后端校验拒绝时不部分写入。前端校验是便利,CSRF/归属/格式/Key存在及事务仍由服务端兜底。

### 2. 性能

无额外后台或页面外部请求;配置读取沿用请求内视图和5秒配置缓存。新平台只在用户原有AI动作时调用,原主备次数与超时不扩大。连接测试钉定一个型号,不做批量探测。

### 3. 安全

- Key沿用原私密KV和掩码,只在输入及发给对应平台的Authorization中出现;不进入前端目录、prompt、截图、日志、审计正文、issue或新跟踪文件。
- 不新增任意URL设置;完整型号只作JSON值。上游错误只提取HTTP和已知码,绝不透传body、响应头或异常链正文到用户界面。
- 文字材料的代号映射、既有prompt禁数学与来源记录不变。图片输入仍可能含原图信息,不声称自动遮盖;测试只用合成图片。
- 本地工具只用原Registry/Dispatcher,模型给出的名字或参数不进入eval/反射任意执行;保持原确认及家庭隔离。
- 模型保护覆盖新Client及原视觉/流式/测试出口,不增熔断/失败、不伪造空成功。beta保护epoch及sent计数不得因fixture还原重置。

## 七、上线与回滚

### 1. 可观测

沿用/health版本、AI接入的健康与冷却、原审计/提示词来源。记录平台/型号、HTTP状态、可识别错误码、耗时和安全原因;真实Key、prompt/body不进日志。未知上游错误保留安全元数据用于诊断,不能以“要上游原话”为由泄露响应正文。

### 2. 预案

配置问题先切回已配旧平台并保存,不删报告或财务数据。旧程序不认识新平台:回滚前若主/备/启用视觉选中siliconflow,必须分别切回旧平台或明确关闭该能力;没有已配置旧平台就先完成配置,不能静默猜。保留新Key及新设置的私密备份用于恢复升级,但不入新tracked文件。无DDL回滚。

不可逆的是已向第三方发送的prompt/图片和发生的计费,因此自动化不做这些动作。保护开关用于测试,不是替用户承诺退款或撤回数据。

### 3. beta交付

维护者已授权本版实现、自验通过后部署beta,后续无需再问“要不要部署”。本稿单独评审通过后,代码/测试/文档逐块commit并只push私有origin。功能独占beta,按技能lease feature --approved再部署,不与bug混栈。

验收路径:管理→AI接入→四平台凭据卡→文字主备→独立截图配置→本地Agent/原文字入口。给维护者明确说明候选commit、版本、测试结果、原始数据恢复、模型保护同epoch/sent=0及尚未真实生成的边界。用户在beta验收后,发布仍需另走精确版本release-prod;本次授权不含prod或公开GitHub推送。

## 八、成本测算

按量计费取决于最终选用的完整型号、平台账户权益和当期单价;本稿不填未核实的单价或声称免费。自动化桩/保护检查实际模型用量和费用为0。真正手动点连接检查也可能按平台计少量用量,须明确告知。

用于核算的**情景假设**,不是用户真实用量:每月20次文字分析,每次6000输入/1000输出token;10次Agent问题、平均3回合,每回合3000输入/800输出token;5张截图。定义所选型号每百万输入/输出价格为p_in/p_out,每张图片按实际平台计价折成c_image。

无重试情景月成本=`0.210*p_in + 0.044*p_out + 5*c_image + 手动连接检查成本`。不同型号主备应逐次按实际型号分别求和,不能拿一个价套全部。Agent回合数翻倍则其0.090*p_in+0.024*p_out部分翻倍;输入上下文/图片大小与失败切备选也会增加用量。无新增定时生成或保存自动探测,本版不增加固定月调用量。

### 实施补充 · 手机视口与原生禁用语义

真实浏览器发现两类静态预览未暴露的联动:AI管理页手机12列横向gap与长代码段会撑大布局视口,导致固定下拉的坐标不再等于实际320视口;共用选择器原先也没有继承option/select的disabled。已在AI页面移除手机横向gap、允许代码段换行,在共用组件同步禁用状态到鼠标/键盘/按钮并限制手机面板宽度。旧平台与新平台同时应用,不隐藏未配置项。e2e62比较真实视口、点禁用项验证不改值,三档136项已通过;原退休表单与模型保护流程另做回归。
