## 2. 节目数学信息摘要

这是阅读笔记,不是逐字稿。约 00:00 定义不工作而维持生活及购买力;约 01:00 设月常规支出 X;约 04:20 用名义回报 4%–4.5%、通胀 2%,近似得实际回报 2%–2.5%;约 05:00 用 12 / 2.5% 得月支出倍数 480。约 05:45–09:00 加入育儿 K×N、医疗 M、资本开支 H;自有住房不再加买房钱,租金进 X,养老日常消费已在 X 中。约 09:00 后示例及反算,最后回到生活选择。收益、费用及开支均为节目假设,不是承诺。

数学关系:

```text
节目简算: F = 480 X + K N + M + H
一般化:   F = 12 X / r + K N + M + H
反算:     X = (F - K N - M - H) r / 12
```

关键是 r 的假设和每项支出边界,不能只把代码里的 300 改成 480。

## 3. 我们需要补上的数学边界

以下是本项目的推导与产品决定,不是小Lin原话。

### 3.1 真实回报与近似回报分开

定义:一年后名义资产变为 A×(1+R),物价变为今天的 (1+π) 倍。因此相同购买力下的增长率是:

```text
r = (1 + R) / (1 + π) - 1
```

R 是扣除费用、税负影响后的年回报假设。以 R=4.5%、π=2% 为例,r≈2.45098%,月支出倍数为 489.6。直接相减时 r≈2.5%,倍数为 480。差别来自精确换算,不能暗中把同一组输入显示成相同结果。

系统默认使用精确式;来源页展示节目简算。用户可以选择直接填写实际回报,用 2.5% 复现 480,此时不再扣一次通胀。[圣路易斯联储解释名义与实际利率](https://www.stlouisfed.org/publications/page-one-economics/2023/01/03/adjusting-for-inflation)使用相减近似,精确式是按上述定义的代数推导。

### 3.2 4% 提款与实际本金保全不是同一个判据

[Morningstar 原始退休研究说明](https://www.morningstar.com/retirement/morningstars-retirement-income-research-finding-your-safe-withdrawal-rate)讨论给定资产组合、退休年限、随通胀调整的支出及资金不耗尽的概率。有限年限不耗尽,不等于本金购买力永久不减。

本版只交付可解释的长期购买力基准,不伪造历史回测或成功概率。即使实际回报均值为正,先亏后涨、投资波动、税费与家庭支出冲击仍可使实际路径偏离确定性曲线。展示“按这组假设估算够用”,不展示“可以安全退休”。允许本金逐步用完的寿命模型单独留作后续,不混用一条分母。

### 3.3 四个易被忽略的重复计算

1. 已有孩子只预留剩余未花的养育支出。不能按孩子数量重新收一遍从出生到成年总成本。
2. 已有住房不再预留全额购房款;房产本身也不能自动成为可支用金融本金。换房填写净新增现金需求。
3. 有保险不等于医疗储备为零。只读保单信息作参考,赔付金额与条件不能自动当作可用现金。
4. 教育目标当前用全家资产衡量进度,其“已积累”不是专款。不能从总金融资产再减去同一个“已积累”,再加一遍完整教育目标。

## 4. 已有实现的具体差距

| 现状证据 | 对用户的后果 | v1.39 需求落点 |
|---|---|---|
| `GoalProgressCalculator.computeRetirementTarget`:生活费×12×退休前通胀因子/取用率,默认 4% | 没说明取用率与长期实际收益的区别 | 门槛分项、实际收益推导、原理来源 |
| `GoalProgressService.computePv`:退休读 `kpis.netWorth` | 自住房、不可支用资产也会抬高进度 | 单独的退休资金范围,与分析范围独立 |
| `GoalProgressService.computeMonthlyContributionMedian`:先取 PMC 的近 6 期,收入只用 PMC | 只有账户收入的新月份可能被遗漏 | 退休新方案使用完整家庭事实收支,展示账期和缺失 |
| `GoalProjector`:2%/5%/8% 为固定常量,原本金按年复利而供款按 r/12 复利 | 用户不能表达自己的假设,两种复利时间口径混杂 | 可编辑积累期情景、同一月有效利率、同币值比较 |
| `GoalService.recomputeAutoExpenseGoals`:忽略 ≤0 支出、关账回写自动支出 | 零值/退款/未填难辨;生活预算可能无提示变动 | 建议与确认计划分开,零和缺失不同 |
| 创建/编辑以“当前年龄+退休年龄”从访问当日反推日期 | 多年后编辑可能把目标日再次向后挪 | 固定目标退休年月 |
| `goals/new-retirement.html`:标百分号却要求输入 0.025 | 普通用户难理解输入单位 | 输入 2.0、4.5 这样的百分数 |
| `goals/detail.html`:当前资产与通胀后本金并列计算进度 | 用户容易把今天钱与未来钱直接比较 | 主结果全部用今天购买力,未来名义金额另标 |

其他调用方已读:仪表盘/报表目标条、`LlmDiagnoseService`、`GoalReportService`、`GoalLlmService`。全仓检索未找到现存填报页的退休投入提示实现,虽然旧文档提过,不能把文档描述当作已有能力;本版不新增该提示。新退休方案必须同源,教育/应急/自定义走兼容分支。

## 5. 能联动与不能替用户猜的边界

| 项目 | 系统能提供 | 必须由人决定 |
|---|---|---|
| 当期资金 | 最新余额轴的各账户本位币金额、来源日期、贷款余额 | 哪些账户用于退休、非现金资产是否可变现 |
| 生活预算 | 最近已定稿月的家庭支出、性质/分类、一次性项 | 退休后消费水平、租房还是自住、哪些类目延续 |
| 每月投入 | 最近已定稿期家庭净流入与覆盖情况 | 未来真正留给退休的份额、还贷结清后的调整 |
| 通胀 | 历史 CPI 作为有年月的参考 | 长期计划通胀,不能把最新同比当几十年预测 |
| 回报 | 已实现收益仅作历史对照 | 长期税费后回报、积累期三情景、直接实际回报 |
| 教育 | 既有教育目标名称、金额、币值年和日期 | 剩余未花额度,一次确认接入,不认虚构已筹专款 |
| 医疗 | 保单入口和信息 | 家庭现金储备,不推算个人疾病或赔付 |
| 其他退休收入 | 历史租金/养老金记录可供核对 | 退休起就到账且长期保持购买力的可用金额;以后才领取的养老金本版不提前抵扣 |

## 6. 对本版的结论

用一张“退休生活账”回答四个问题:过怎样的生活、需要多少能生息的本金、现在真正能拿出多少、按计划还差多少。把来源视频放在“怎么算的”附近,展开能对照节目简算与本项目扩展。先形成 PRD + 静态交互预览,独立等需求评审;不在这轮编写 TDD、改业务算法或部署 beta。

## 7. 11-05六项反馈后的补充核查

上一稿已于11-04至11-05实施到beta;本节是维护者进一步反馈后的新需求依据,不把上一稿实现结论外推到本稿。

1. **J与C的身份**:已阅读的节目文字公式中没有J,退休开始的持续收入是本产品加的抵扣项;C也只是回答退休前何时攒够,不是原节目永久本金公式的一部分。标准流程移除J,未来路径改为结果页可选功能。B站本轮访问仍为412,作者播客页能核对题名与节目,不能称已取得官方审定文稿或完整校听。
2. **动态生活费**:`RetirementPlanService.evaluate`已有自动预算读取,但界面输入框加复选框难以表达“自己填/每次按事实算”。`RetirementDataService.load`使用计划通胀重估历史消费,与报表名义月均可能不同。修订二要求同窗均值/剔除额/分母透明,未来通胀不能悄悄改写过去的月均。
3. **动态收益的陷阱**:`FactSlice.returnPeriodIds`最多12张月末快照,`familyTwr`生成N-1个收益段;`TwrCalculator.annualizedOrCumulative`不足12段返回累计值。不能直接把页面里带“年化”名字的值拿来当长期R。新的历史推演要至少12完整月度间隔,范围一致并剔除转账、开账与补录本金;少数据明确待补齐。
4. **CPI并没有注释声称的自动任务**:全仓只有`MacroFetchJob`注释,没有任务类。`IntegrationsController.saveMacro`明确只有管理页手工校正。`MacroBenchmarkService`虽然已有几何均值,但直接读全部行,尚无完整年份/核验状态过滤。V27含2025年0.3%的近似seed,而[国家统计局2025年公报](https://www.stats.gov.cn/sj/zxfb/202602/t20260228_1962662.html)表2给出全国全年0.0%;必须纠正来源后再动态引用,不能改旧迁移或盖掉人工修订。

**实施核验补记**:2016—2025已逐年核对国家统计局发布页,CPI依次为2.0、1.6、2.1、2.9、2.5、0.9、2.0、0.2、0.2、0.0(%),几何年均1.44%。逐年原始URL与核验日期随V79保存在macro_benchmark;迁移仅更正仍匹配的seed,人工校正值不覆盖。退休只采用连续十个完整已核验年份,管理页展示来源和日期;没有新增名义上的自动抓取任务。
5. **城市预留不是官方退休标准**:[国家统计局居民消费统计](https://www.stats.gov.cn/sj/zxfb/202601/t20260119_1962321.html)包含年度人均医疗、教育文化娱乐等支出,不提供家庭终身准备金。育娲2024报告的[原报告镜像PDF](https://caoss.org.cn/upload/news/20240318/d498866bf3554763940159394e219e10.pdf)搜索摘要可读,本轮完整PDF超时,也未核得最新版原件,不据此将其历史总育儿成本硬填为剩余成本。城市档采用明确的产品规划规则,医疗/额外教育/应急逐项标假设和版本,供维护者评审;不冒充统计或节目数值。
6. **家庭结构不能猜**:`Member`只有角色等字段,没有生日。教育目标可保存`childBirthYear`,但目标未建立不等于没有孩子。快速方案必须显式选择无/仍需养育及阶段,不新增精确生日采集。日常育儿在生活费、额外培养在预留,同项发生重叠时要可看见并剔除。

此轮产物是PRD修订二和合成交互稿;当前beta仍为上一稿。业务代码、迁移、生产数据与AI调用均未触及。
