百炼托管 Agent 的设置 · 一共 6 步(4 步要你去百炼控制台)
  1. 我们
    先发一把只读口令

    在下面「接入点」那一节点「新增接入点」。口令只显示这一次,顺手复制走 —— 第 4 步要把它粘进百炼。

  2. 你
    去百炼拿「业务空间 ID」

    它是你在百炼里那个空间的编号,形如 llm-7c72… 或 ws-9x63… —— 两种前缀都有,以控制台上显示的为准,不要按格式去猜。 我们用它拼接口地址(https://业务空间ID.cn-beijing.maas.aliyuncs.com/…), 所以少了它连不上。

    先想清楚用哪个空间 —— 这一步选错,要到最后一步才会暴露。
    默认业务空间:它的 Key 可以调用所有模型,不用额外授权,最省事。
    子业务空间:默认一个标准模型都调不了,必须由主账号 / 超级管理员 在控制台里为它逐个开通模型调用权限。
    为什么容易踩:北京地域的普通对话接口用的是不带空间的 dashscope.aliyuncs.com,绕过了空间限制 —— 所以同一把 Key 「聊天能用」完全不代表「这里能用」。托管 Agent 的地址里嵌着业务空间,受它的授权约束。

    怎么拿
    1. 打开 百炼控制台, 左上角先把地域切到「华北2(北京)」 —— 我们用的是北京地域的接口, 在别的地域拿到的 ID 对不上。
    2. 点页面右上角那个图标,弹出的对话框里就能看到并复制业务空间 ID。
    3. 要看主账号下所有空间的 ID:同样点右上角图标 → 进「业务空间管理」→ 在 Workspace ID 那一列复制。

    拿不到?多半是权限。这一页要求主账号,或者已授予 AliyunBailianFullAccess / AliyunBailianControlFullAccess 的 RAM 子账号;没有权限会直接提示权限不足。
    这个 ID 只能在控制台拿,阿里云没有提供 API 或命令行查询。 官方说明 →

  3. 你
    确认这个业务空间「能调模型」

    用默认业务空间的话这一步可以跳过 —— 它本来就能调所有模型。 用子业务空间就必须做:否则最后一步会报 模型不存在: model=qwen-plus,而那句话是误导的 —— 模型是存在的,只是这个空间没被允许用它。

    怎么开通 · 以及怎么先验一下
    1. 百炼控制台 → 进这个业务空间 → 权限管理 / 模型调用权限 → 为它开通至少一个模型。建议选 qwen-max 系列: 官方说工具调用能力更强,而这个 Agent 全靠调工具取数。
    2. 这一步需要主账号或超级管理员。注意 RAM 权限 (AliyunBailianFullAccess)和百炼内部的业务空间权限 是两套独立体系 —— 有 RAM 权限不等于能在空间里授权模型。
    3. 把你开通的那个模型名,填进下面「模型」那一格 —— 我们默认按 qwen-plus 请求,你开通的要是别的,两边对不上照样报「模型不存在」。
    4. 开通后回到这里走完剩下的步骤;如果最后仍报 「模型不存在」,多半是授权没落到这个空间上,或者「模型」那一格填的不是你开通的那个。

    别用「聊天能不能通」来判断这一步。北京地域的对话接口地址里不带业务空间, 走的是全局通道;而托管 Agent 的地址里嵌着空间。同一把 Key 在前者 200、 在后者「模型不存在」是完全可能的 —— 这正是本项目实测到的情况。

  4. 你
    去百炼把这个账房注册成一个 MCP 服务

    百炼的智能体只能引用已经注册过的 MCP 服务,而注册这件事阿里云没开放接口 —— 只能手工点一遍。这也是这条路线比「本机直连」麻烦的唯一原因。

    怎么做 · 第一步就有个岔路,别走错

    点「创建 MCP 服务」之后,百炼会先让你在几种接入方式里挑一个 (插件 / 使用脚本部署 / 从 AI 网关导入 / 从阿里云 OpenAPI 导入)。 选「使用脚本部署」 —— 只有这一条路能填我们的地址。

    使用脚本部署 ← 选它 唯一支持「连接一个已经跑在别处的远程 MCP 服务」的入口。 这个账房就在你自己的服务器上,不需要百炼替你部署任何东西。
    插件 是把一个普通接口包装成工具用的,所以它会要求你逐个填工具名和描述, 不填就存不了。我们这边本身就是 MCP 协议,工具由协议自动发现 —— 走这条路等于把已经有的东西再手抄一遍,而且抄错了模型就调不对。
    从 AI 网关导入 给「已有 RESTful API,想升级成 MCP」用的,要先在 AI 网关里托管一层。多一跳,没必要。
    从阿里云 OpenAPI 导入 用来让模型操作 OSS / ECS 这些云资源,和你的账本无关。
    1. 先确认右上角的业务空间,和第 2 步填的是同一个 —— MCP 服务是按空间注册的,在 A 空间注册、拿到的 ID 填给 B 空间的 Agent 会引用不到。
    2. 百炼控制台左侧进「MCP 管理」→「创建 MCP 服务」→ 选「使用脚本部署」。
    3. 安装方式选 http。npx / uvx 那两个是把服务托管到函数计算, 只有 http 是「连接到一个已有的、运行在别处的远程 MCP 服务器」。
      选了 http 之后,「部署方式」「部署地域」两个字段会用不上 —— 它们只对 npx / uvx 生效。
    4. 服务名称随便起(官方原话:名称和描述「不影响大模型的判断和调用」)。 不需要填任何工具 —— 这条路不问你要工具清单。
    5. 「MCP 服务配置」里粘这段(第 1 步生成口令时页面给过你): 
      {}
    6. 提交部署,等状态变成部署成功;回到「MCP 管理 → 自定义服务」, 在这个服务上找到它的 服务 ID,填进下面那一格。
    7. 如果表单只给 type / url / headers 这几格,把外面 mcpServers 和服务名那两层去掉再填。

    ① type 必须和地址末尾对上。百炼把这两件事绑死了: streamableHttp 配 /mcp、sse 配 /sse。 对不上会报 404 / 405,看着像地址写错,其实是类型选错。 我们给的这段是 streamableHttp + /mcp,照抄就对。

    ② 口令写在 headers 里,而且要带 Bearer 前缀。 也就是 "Authorization": "Bearer 你的口令" —— Bearer 后面有一个空格,整串是一个值。 我们这边两种写法都收(不带前缀也认),但带上是 HTTP 的标准写法, 照抄上面那段就不会错。绝对不要把口令拼在 URL 上 —— MCP 规范禁止,我们这边也会直接拒掉。
    百炼的配置模板里没有专门列 headers 这一项, 但它的错误排查文档写明:401 的处理办法是「在 MCP 服务中正确添加鉴权信息, 例如 Headers 中的 Authorization 信息」。

    ③ 部署之后想改配置,要先「停止部署」。 百炼只允许直接改服务名称和描述,安装方式、配置 JSON 都得停了才能改再重新部署。 所以我们换口令时新旧两把会并存 —— 新的第一次被用到,旧的才自动失效,中间不断服务。

    ④ 连不上时,先用 curl 直连自测一次(这是官方排错文档建议的第一步, 能立刻分清是「百炼没配对」还是「你的服务本身不通」): 

    curl ...
    能返回工具清单,就说明地址和口令都是对的,问题在百炼那侧的配置。

    出处:自定义 MCP 服务 · MCP 部署使用与排障 FAQ (11200049 = 401 鉴权、11200054/58/59 = 传输类型与路径不匹配)
